# API 작업 규칙

이 디렉터리에서는 루트 `AGENTS.md`와 이 규칙을 함께 적용한다.

## 경계와 계약

- Web/Admin의 application source를 import하지 않는다.
- 외부 입력은 controller 경계에서 검증하고 내부 서비스가 암묵적으로 신뢰하게 두지 않는다.
- DTO, schema, event, persistence model을 같은 것으로 취급하지 않는다.
- 공개 계약을 바꾸면 기존 클라이언트 호환성과 migration 순서를 함께 설계한다.

## 보안 및 데이터

- 인증과 인가는 분리해서 검토하고, 관리자·소유자·일반 사용자 권한을 명시한다.
- 사용자 입력을 로그에 그대로 남기지 않으며 토큰·쿠키·개인정보를 마스킹한다.
- DB 변경은 migration, 재실행 안전성, rollback 또는 복구 경로를 포함한다.
- 요청 처리 중 임의 DDL이나 자동 스키마 수정에 의존하지 않는다.
- 외부 호출에는 timeout, 오류 매핑, 재시도 가능성, 중복 실행 영향을 검토한다.

## 테스트 및 검증

- 성공 경로뿐 아니라 인증 실패, 권한 부족, 잘못된 입력, 저장소 오류를 테스트한다.
- DB·Redis·실시간 기능은 가능한 경우 실제 통합 경계 테스트를 추가한다.
- 공통 최소 검증은 `pnpm harness:verify`와 API 관련 테스트다.
- migration 변경은 빈 DB와 기존 상태 모두에서 적용 순서를 확인한다.
