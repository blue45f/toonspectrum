# ToonStudio 올인원 구현 상태 원장

- 기준일: 2026-09-17
- 제품 정의: **기획부터 연재까지 외부 제작 도구 없이 완결하는 올인원 웹툰 제작 스튜디오**
- 사용자 문장: **기획부터 연재까지, 웹툰 제작의 모든 것을 한곳에서.**

이 문서는 기능 수가 아니라 **실제로 작품을 완주할 수 있는지**를 기준으로 구현 상태를 기록한다. 버튼, 라우트, 데모 데이터 또는 실험용 엔진이 존재하는 것만으로 완료 처리하지 않는다.

## 상태 정의

| 상태 | 의미 |
|---|---|
| 검증 완료 | 실제 화면·저장·복구·권한·내보내기까지 자동 또는 수동 검증 근거가 있다. |
| 구현됨·검증 필요 | 주요 코드 경로는 있지만 전체 작품 흐름과 실기기 검증이 남아 있다. |
| 부분 구현 | 일부 기능 또는 제한된 형식·환경만 지원한다. |
| 설계만 존재 | 계약·문서·UI 초안은 있으나 실사용 경로가 완결되지 않았다. |
| 미구현 | 사용자에게 제공할 수 있는 코드 경로가 없다. |

## 완료 판정 원칙

각 기능은 다음 항목을 통과해야 `검증 완료`로 바꿀 수 있다.

1. 사용자가 별도 설명 없이 시작점을 찾는다.
2. 입력과 결과가 실제로 연결된다.
3. 실행 취소·다시 실행 또는 안전한 되돌리기가 가능하다.
4. 자동 저장 후 문서를 닫고 다시 열 수 있다.
5. 다른 기기 또는 지원되는 오프라인 흐름에서 상태가 일관된다.
6. 역할·권한과 공동 작업 충돌을 처리한다.
7. 가져오기·내보내기에서 손실 항목을 숨기지 않는다.
8. 오류 뒤 입력과 작업물이 보존된다.
9. 데스크톱·태블릿·모바일 지원 범위가 명시된다.
10. 타입 검사, 단위 검사, 브라우저 회귀와 프로덕션 빌드를 통과한다.

## 2026-09-17 UX·저장 신뢰 증분

이번 증분에서 완료한 범위는 다음과 같다.

- 기존 라우트 UX 계약을 실행 가능한 `SiteRouteExperience`로 확장했다.
- 페이지별 빈 상태 종류, 다음 행동, 사용자 용어 범위, 프로젝트 문맥 필요 여부와 저장 신뢰 필요 여부를 파생한다.
- 전체 라우터에 경험 경계를 적용해 페이지 목적을 보조 기술에 알리고 공통 정책을 문서 루트에 노출한다.
- 모바일에서 정밀 편집이 필요한 화면은 지원 범위와 대체 사용 경로를 명시한다.
- 오프라인 상태에서 저장·복구가 필요한 화면은 작업 보존 확인 방법을 안내한다.
- 기기 저장, 클라우드 동기화, 충돌, 검수, 승인과 게시를 서로 다른 사용자 언어로 정의했다.
- 최근 작업 카드에 ‘최근 위치 기억됨’ 상태를 표시했다.
- 새 프로젝트 화면에서 ToonStudio 저장을 기본으로, 외부 드라이브를 선택적 가져오기·백업으로 정리했다.
- 프로젝트 이름이 없어 시작할 수 없을 때 이유와 해결 방법을 버튼과 입력에 연결했다.
- 지연 로딩 화면이 현재 페이지 목적과 복구 정책을 설명하도록 변경했다.
- 정적 헤더와 Cloudflare Worker CSP를 단일 응답 정책에서 함께 생성·검증하도록 변경했다.

## 2026-09-17 과업 중심·직관성 UX 증분

이번 증분에서 완료한 범위는 다음과 같다.

- 첫 화면을 기능 카탈로그가 아니라 `아이디어`, `대본·콘티`, `기존 파일`, `팀 프로젝트`, `샘플 체험`의 현재 재료 기반 시작점으로 재구성했다.
- 기획 → 콘티 → 2D·3D 제작 → 협업 → 검토 → 연재의 전체 흐름을 좁은 화면에서도 읽을 수 있는 공통 단계 레일로 제공한다.
- 새 프로젝트 화면에서 현재 선택한 작업 종류·템플릿·자동 저장 결과를 시작 전에 요약한다.
- 비활성 시작 버튼은 프로젝트 이름이 필요한 이유와 해결 행동을 함께 제공한다.
- 생성 실패 시 입력한 프로젝트 이름과 시작 형식을 보존하고 같은 자리에서 다시 시도할 수 있다.
- 가져오기 화면은 원본 보존, 호환성 분석, 사용자 확인 순서를 먼저 설명한다.
- 지원하지 않는 객체를 사용자 동의 없이 평탄화하지 않는 원칙을 실제 화면과 계약 테스트에 고정했다.
- 소재 화면은 찾기 → 권리 확인 → 프로젝트 추가 → 사용 위치 기록의 목적 중심 흐름을 안내한다.
- 공통 카드·헤더·행동 영역에 `min-width: 0`, 줄바꿈, 모바일 전체 폭 동작을 적용해 긴 한국어·영문 문구와 좁은 화면 잘림을 방지한다.
- `StudioTaskFlow`, `DisabledReason`, `RecoverableActionNotice`, `StudioTaskSummary`, `StudioIntentLauncher`를 공통 컴포넌트로 제공한다.
- 소스 계약 테스트로 시작 경로, 저장 신뢰, 비활성 이유, 오류 복구, 원본 보존, 반응형 문구 정책을 회귀 방지한다.

## 2026-09-17 ProjectGraph v3·실제 revision 연결 증분

이번 증분에서 완료한 범위는 다음과 같다.

- 작품을 단일 문서가 아니라 story·storyboard·2D canvas·3D scene·asset·audio·localization·review·deliverable·release artifact graph로 저장한다.
- artifact head, approved revision, immutable parent graph와 append-only operation journal을 서버 권위로 제공한다.
- 2D layer graph, sparse raster tile, vector stroke, 3D scene/live layer의 정규화된 v3 IR과 검증 계약을 추가했다.
- 원본 blob, revision blob, 외부 파일 binding, 호환성 보고서와 provenance 연결을 PostgreSQL migration으로 영속화했다.
- Google Drive·Dropbox·OneDrive·로컬 파일을 import-only, export-only, bidirectional, backup-mirror 모드로 revision에 연결한다.
- 브라우저 로컬 cache와 서버 ProjectGraph를 함께 사용하고, stale response가 최신 project state를 덮지 않도록 방어한다.
- Studio 프로젝트 화면에서 정본 상태, 버전 stack, 복원, 호환성·손실 보고와 승인 상태를 확인한다.
- Production 작업의 입력 revision을 실제 Studio artifact ID·SHA-256 digest·lineage와 대조한다.
- 공정과 episode scope에 맞는 승인 revision을 우선 추천하고, 명시적 사용자 행동으로 작업 입력에 고정한다.
- 이미 제출된 revision의 digest가 다르면 자동 교체하지 않고 새 제출을 요구해 기존 검수 증거를 보존한다.
- 기능 미리보기 데이터에서는 서버 정본을 변경하지 않으며 실제 프로젝트에서만 연결 명령을 제공한다.

남은 검증은 대용량 업로드 재개, 실제 외부 계정, 다중 사용자 충돌, Safari OPFS·GPU 조합과 기준 프로젝트 A–D의 전체 E2E다.

## 올인원 공개 문구 사용 게이트

다음 기준 프로젝트가 모두 통과하기 전에는 `Clip Studio·Photoshop·SketchUp·Drive를 완전히 대체했다`거나 `모든 전문 기능이 완성됐다`고 표시하지 않는다.

### 기준 프로젝트 A — 1인 세로 웹툰

- 아이디어와 캐릭터를 만들고 1화 대본을 작성한다.
- 콘티, 선화, 배경, 채색, 말풍선과 효과를 ToonStudio 안에서 완성한다.
- 브라우저 종료 후 같은 작업 위치로 복구한다.
- 승인본에서 자체 연재와 외부 플랫폼 패키지를 만든다.

### 기준 프로젝트 B — 팀 제작

- 스토리·콘티·선화·배경·채색·식자 역할을 배정한다.
- 선행 작업과 입력 버전이 맞아야 다음 단계로 이동한다.
- 위치 기반 수정 요청을 해결 버전에 연결한다.
- 미해결 필수 수정이 있으면 승인을 차단한다.
- 권리·크레딧·사용 소재가 게시본에 고정된다.

### 기준 프로젝트 C — 파일 이전과 왕복

- 복합 PSD·PSB를 가져오고 항목별 보존·변환·래스터화 결과를 확인한다.
- ToonStudio에서 수정한 뒤 다시 내보내 구조와 픽셀 결과를 비교한다.
- CLIP·CMC는 지원 범위와 손실을 실행 전에 명시한다.
- 원본은 모든 변환과 관계없이 변경 없이 보존한다.

### 기준 프로젝트 D — 3D 제작

- 캐릭터·포즈·실내 배경과 소품을 ToonStudio에서 만든다.
- 3D 장면을 컷의 라이브 레이어로 연결한다.
- 카메라·재질·선화·톤·마스크 패스를 다시 생성한다.
- 저장·재열기·장면 수정 뒤 2D 컷의 업데이트와 고정 버전을 검증한다.

## 운영 규칙

1. 기능 상태 변경에는 테스트, 캡처, 벤치마크 또는 호환성 보고서 링크가 필요하다.
2. 데모 전용 데이터는 실서비스 구현 근거로 사용하지 않는다.
3. 자동화가 승인·권리·계약·지급 결정을 대신하지 않는다.
4. 지원하지 않는 기능은 비활성화만 하지 않고 이유와 대안을 표시한다.
5. 호환되지 않는 객체를 사용자 동의 없이 평탄화하지 않는다.
6. 외부 서비스 장애가 ToonStudio 내부 제작을 막아서는 안 된다.
7. 기능을 추가할 때 대표 화면과 소유 도메인을 하나로 지정한다.
8. 모든 편집 화면은 저장·복구 상태를 사용자가 이해할 수 있는 문장으로 제공한다.
