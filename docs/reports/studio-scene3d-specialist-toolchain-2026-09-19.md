# Scene3D specialist toolchain — 2026-09-19

Rebased independently onto main `6cafbb293` before final validation. PR #1838 is not required by this change.

## Delivered scope

This change adds functioning local asset-processing tools to the existing BG3D professional workspace.
It does not change the canonical renderer, overwrite source files, upload local assets, or mark experimental
providers as fully admitted Scene3D renderers. The earlier normal/crease output work remains in PR #1838.

Entry: existing 3D workbench → professional tools → **3D 자산 고급 가공 · LOD / 불리언 / 이동 경로**.
The button lazily opens the processing panel and Spark reference viewer. Parent editor locks, cancellation,
and unmount propagate to these tools. Exported GLBs can be re-imported through the existing asset library.

## Product functions

### Asset inspection and derivatives

Inspect an actual self-contained GLB hierarchy and node names. Generate a compressed GLB, three independent
LOD derivatives, Mikk-compatible tangents, or optimized animation keys. Each operation starts from the
original file, produces SHA-256/statistics, and reopens its encoded GLB before reporting success.
Compression emits meshopt version 0 so the existing pinned Three decoder can read the result.

LOD applies to static geometry only; animated, skinned and morphing assets are not silently decimated.
Requested ratios are targets subject to border/error protection, not guarantees. Texture bytes are
preserved, not converted to KTX2. A successful derivative is not automatic asset-quality approval.

### Boolean derivatives

Choose two untextured static single-primitive GLBs in shared world coordinates, then union/difference/
intersection. BVH output is explicitly a preview, not a manifold guarantee. The alternative solid lane
uses the existing Manifold provider and validates the actual result. Original materials/scene authority
are not transferred; this is a geometry-only export, not a destructive editor command.

### IK pose derivatives

Choose unique root/endpoint node names spanning 3–16 nodes and a world-space target. The actual
closed-chain solver applies rotational DoFs with bounded symmetric XYZ limits. It rejects animated or
non-unit-scale chains that could overwrite or invalidate the result. Success requires the solver,
projected glTF pose and re-opened exported GLB to reach the target within the requested tolerance.
The JSON receipt records all three measurements. This is not anatomical full-body IK, contact solving,
VRM compatibility, self-collision prevention or character-authority integration.

The pinned npm package root is broken; imports use its exact `src/core/{Goal,Joint,Link,Solver}.js`
entrypoints, avoiding old Three helpers, URDF loaders and nested worker runtimes.

### Navigation artifacts

Recast produces a voxelized walkable surface and Detour computes a full path between requested endpoints.
Exports include GLB surface, binary navigation data, and path JSON. Grid sizes are bounded and partial or
unreachable routes are rejected. These are local static artifacts, not live crowd/multiplayer movement.

### Spark reference viewer

Accepts local native 32-byte-row `.splat` data, up to two million splats, with finite center/scale/rotation
and opacity checks. The reference viewer supports orbit/zoom and explicit close/cancel. It suspends work
when offscreen/hidden and disposes the renderer when closed. Late GPU failures are visibly reported.
It does not silently replace Three's main scene backend and does not export canonical line/material-ID/
collision passes. PLY/RAD/SPZ are not yet admitted through this UI.

## Resource and input safety

One module Worker per explicit processing job. Source ArrayBuffers are copied before transfer, output
buffers are transferred, identities are correlated, and schemas validate returned files and aggregate
budgets. Cancelling or timing out terminates synchronous WASM kernels as well. Temporary URLs, resources,
Recast queries, Manifold objects and renderer contexts have explicit disposal paths.

Preflight rejects external/data URI resources, unknown/VRM/unsupported Draco extensions, malformed GLB
chunks, invalid virtual meshopt buffers, oversized decoded graphs, cyclic/multi-parent nodes and non-finite
transform/accessor data. Future format support must preserve semantics rather than silently stripping it.

## CSP compatibility: actual failures fixed, policy not weakened

A development browser passed while the real production Worker under the deployed CSP failed. The verifier
now serves the actual built Worker with the exact CSP read from `dist/_headers`. No `unsafe-eval` exception
was added and no checks/hooks were bypassed.

### glTF Transform 4.4.2 patch

`patches/@gltf-transform__functions@4.4.2.patch` moves optional ndarray image kernels from eager imports to
lazy, original API calls. Geometry-only operations no longer initialize Function-generating image kernels.
Actual palette PNG generation is separately tested to prove the optional image APIs were not replaced by
stubs. This does not claim that all optional image APIs have become browser-CSP-compatible.

### Manifold 3.5.1 patch

`patches/manifold-3d@3.5.1.patch` removes dynamically generated JS invokers from the pinned Embind glue and
uses static closures for wire conversion, dispatch, return values and destructor lifetime instead. The
WASM kernel is unchanged. Real union/intersection/difference and warp callbacks run under Node's
`--disallow-code-generation-from-strings` flag, then the actual browser production-CSP worker verifies
solid output. The large-looking vendor diff comes from the original minified glue, not a rewritten kernel.

Both patches are pinned in `pnpm-workspace.yaml` and reproducible in a frozen install. Revisit them on any
upstream upgrade; do not relax the CSP instead. The static-dispatch approach follows Emscripten's
DYNAMIC_EXECUTION=0 implementation pattern:

- https://emscripten.org/docs/tools_reference/settings_reference.html#dynamic-execution
- https://github.com/emscripten-core/emscripten/blob/main/src/lib/libembind.js
- https://github.com/emscripten-core/emscripten/blob/main/src/lib/libemval.js

## Verification

The committed browser verifier exercises nine real module-worker operations, the actual UI file input,
LOD generation/download/3D preview, and the Spark viewer. Its production mode verifies built output,
not an interpreter stub. Software GPU mode checks the actual exposed driver is SwiftShader.
The offscreen render gate is kept: the test scrolls the viewer into view before expecting rendered frames.

Run:

```sh
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm run verify:studio-3d-specialists
pnpm run verify:studio-3d-professional-completion
pnpm run build:bundle
SCENE3D_SPECIALISTS_PRODUCTION_WORKER=1 \
SCENE3D_SPECIALISTS_GPU_LANE=swiftshader \
node scripts/verify-studio-scene3d-specialists.mjs
```

The production-CSP proof applies the production policy to the built Worker; the surrounding inspection
page is a Vite harness, not a claim of full deployment-route/CSP certification. Console errors must be zero.
Upstream BVH deprecation and screenshot readback performance warnings remain visible, not suppressed.
CI runs the native contracts and a full production build + software-GPU specialist browser job.

Local JSON/PNG/logs remain under `.qa/scene3d-output-quality/specialists/`; only synthetic evidence summaries
are eligible for source control. Test suites overlap and must not be summed as independent coverage.

## Remaining long-term program

This delivers usable specialist tools, not every item in the long-term architecture. The full NPR execution
graph, CSM/TAAU/SSGI/SSS, real-time GPU XPBD, Three/BVH/Rapier upgrades, KTX2 encoding/release automation,
3D Tiles, libigl/OpenSubdiv, canonical VRM IK, splat/mesh semantic compositing and large-scene residency
remain separate implementation and validation work. Their existing global capability flags are not
changed to true by the presence of a local derivative/reference tool.

No main merge or production deployment is part of this change.
