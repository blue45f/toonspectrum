# 소재 마켓·내 에셋 운영 연계 검증과 복구 동선

- 상태: **current** — 운영 관찰 결과와 이 브랜치의 구현. 계정 기반 전체 동선 완료 또는 운영 배포 완료를 의미하지 않는다.
- 관찰일: **2026-09-28**, 운영 가입 응답 시각 **23:07 KST**.
- 대상: `https://www.toonstudio.cloud`, 일반 사용자용 실제 브라우저 UI와 실제 API.
- 개발 기준: `b01327c91aa2c037230018130dea7a329073c43f`에서 분리한 `codex/market-liveqa-20260928`.

## 먼저 확인된 운영 차단점

1. 일반 회원가입 화면에서 닉네임·이메일·비밀번호를 입력하고 제출했으나 `POST /api/auth/signup`이 **503**을 반환했다. 응답은 `statusCode: 503`, `message: Request could not be completed`, `requestId: req_512`였다. 정상 생성·메일 인증·일반 사용자 로그인 성공을 확인하지 못했다. DB 직접 삽입, 이메일 인증 생략, 관리자 계정 대체는 하지 않았다.
2. 조건 없는 `GET /api/creator/marketplace/resources?limit=12`는 **200**, `items: []`, `hasMore: false`, `nextCursor: null`이었다. 서버에 공개된 소재를 대상으로 하는 찜·비교·획득·설치 확인을 끝까지 진행할 수 없는 사전조건이다. 정적 샘플을 계정 소장 자료인 것처럼 넣지 않았다.
3. 소장·보관/복원·로그아웃/재로그인·다른 계정 격리·서버 설치 확인은 **미검증**이다. 이전 PR의 가짜 API 응답 기반 브라우저 테스트와 운영 검증을 구분해야 한다. 서버 로그 확인 전 503의 원인을 메일 설정·DB·레이트리미터 중 하나로 단정하지 않는다.

## 운영에서 실제로 통과한 범위

| 동선 | 확인한 증거 |
| --- | --- |
| 한글 검색 → 종류 선택 → 초기화 | 검색어와 종류가 URL에 반영되고 모두 제거됨 |
| 기본 무료 제작 소재 열기 | 실제 공개 페이지에 48개 소재 카드 표시. 48개 전부 다운로드한 것은 아님 |
| 둥근 말풍선 → SVG 저장 | 실제 다운로드 338바이트, SVG 내용 확인 |
| 같은 소재 → PNG 변환 저장 | 실제 다운로드 12,840바이트, PNG 시그니처 확인 |
| 작업 책상 → GLB 저장 | 실제 다운로드 3,552바이트, glTF 버전 2·컨테이너 길이 확인 |
| 소재 이용 조건 저장 | 실제 627바이트 파일에 CC0 조건 포함 |
| 작업 책상 → 3D 미리보기 → 드래그 → 닫기 | 실제 캔버스 렌더 표면과 포인터 조작, 닫은 후 canvas 제거 확인 |
| 무료 2D 소재 → 편집기 → 이미지·소재 도구 → PNG 선택 | 실제 파일 선택창을 사용해 캔버스 레이어 1개 생성 |
| 새로고침 → 로컬 복구 | 가져온 소재 레이어 1개 복원. 클라우드 저장 검증은 아님 |
| 원고 → JSON 백업 | 19,368바이트 프로젝트 파일, 내장 이미지 1개 포함 |
| 비로그인 계정 라이브러리 요청 | HTTP 403으로 차단. 세션은 `authenticated: false` |

세부 실행 로그에는 통과 14개, 사전조건 차단 2개, 초기 자동화 실패 2개가 기록됐다. 초기 실패 중 빈 마켓의 카드 대기는 위 카탈로그 차단으로 확인했고, 숨겨진 ‘이미지’ 버튼을 찾던 자동화는 실제 ‘이미지·소재’ 도구와 파일 선택창으로 다시 수행해 가져오기·레이어 생성·복구까지 통과했다. 최초 실패 기록은 유지했다.

## 이 브랜치에서 보완한 동선

- 내 에셋·소재 상세의 로그인 안내에 일반 로그인/회원가입 버튼을 추가했다. 기존 인증 모달을 열고 현재 URL·검색·작업 문맥을 유지한다.
- 가입과 인증 메일 요청의 5xx·429·손상된 응답을 구분한다. `200`만으로 가입/메일 발송 성공을 표시하지 않고 `ok`, 가입의 `verificationRequired`를 확인한다. 실패하면 입력과 가입 탭을 유지하며, 확인된 응답에서만 인증 안내로 전환한다. 이는 서버 503 원인을 해결했다는 의미가 아니다.
- 공개 카탈로그가 비어 있을 때 계정 없이 사용할 수 있는 기본 무료 소재로 연결한다. 기본 소재를 서버에 소장한 유료/무료 마켓 상품과 혼동하지 않게 안내한다.
- 계정 라이브러리에서 Studio를 열 때 기존 소유자 범위의 원고·페이지 복귀 hook을 재사용한다. 종전 직접 링크가 `/studio`로만 향하던 부분을 수정했다. 외부 URL·유효하지 않은 문서 주소는 기존 검증을 그대로 적용한다.

## 로컬 회귀 검증

실제 운영 결과와 별개로 아래는 코드 수정본의 검증이다.

- 관련 Vitest **76개 파일 / 773개 테스트 통과**. 시장 도메인만 정확히 지정했고 이름이 비슷한 marketing 도메인은 범위에서 제외했다.
- Chromium **8개 시나리오 통과**. 기존 6개에 일반 가입 모달→503→입력 보존, 빈 마켓→실제 기본 소재 페이지 이동을 추가했다. API는 통제된 fixture 응답을 사용하므로 일반 운영 계정 생성의 증거로 사용하지 않는다.
- 첫 브라우저 실행의 첫 화면에서 30초 navigation timeout이 한 번 발생했다. cold Vite 시작/동시 검사 구간의 실패 기록을 보존하고, timeout·assertion·테스트를 완화하지 않은 동일 명령 재실행에서 8개 모두 통과했다.
- 변경 파일 Lint, Secretlint, 아키텍처 경계, 웹/API TypeScript를 포함한 `pnpm harness:verify` 통과.

저장소 루트에서 재현한다.

```sh
pnpm exec vitest run apps/web/src/domains/market/ apps/web/src/domains/auth/ apps/web/src/domains/creator/studio-shell/StudioAssetHubPage.test.tsx --maxWorkers=2
pnpm harness:verify
TOONSPECTRUM_MARKET_E2E_PORT=5387 pnpm exec playwright test --config playwright.market.config.ts market-asset-experience.spec.ts
```

## 계정·운영 데이터 보호 및 재개 조건

가입용 두 계정의 입력값은 git에서 제외된 로컬 `.env.market-liveqa.local`에 소유자 전용 권한으로만 준비했다. 첫 계정만 일반 UI 가입을 시도했으며 두 계정이 생성됐다는 의미가 아니다. 비밀번호·인증 쿠키·인증 토큰은 저장소나 이 보고서에 넣지 않았다. 실제 작업은 새 브라우저의 게스트 원고이며, 공개 게시·결제·운영 DB 직접 수정은 수행하지 않았다.

운영 가입 API의 503 원인을 로그로 확인하고 정상 가입·이메일 인증을 복구한 뒤, 두 일반 계정으로 소장·설치·로그아웃/재로그인·보관/복원·계정 격리를 이어서 검증해야 한다. 테스트 가능한 공개 소재도 실제 서버에 존재해야 한다. 현재 차단점을 숨기기 위해 샘플 카탈로그나 관리자 세션으로 대체하지 않는다. 이 변경은 PR로 제출하며 운영 배포·환경변수 변경·마이그레이션은 수행하지 않는다.
