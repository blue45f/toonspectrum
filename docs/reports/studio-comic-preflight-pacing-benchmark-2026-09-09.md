# Studio 만화 제작 벤치마크 및 프리플라이트 구현 보고서

- 기준일: 2026-09-09
- 대상: `/studio`, `/studio/comic`의 빠른 웹툰 조립 흐름
- 구현 브랜치: `feat/studio-comic-preflight-pacing-20260909`
- 기준 커밋: `main@5ff065f7b91dd6f43f93f46d506db421450f8c18`

## 1. 목표

기존 빠른 웹툰 조립은 컷 레이아웃, 장면 템플릿, 대사 스크립트를 실제 Studio 요소로 조립하고 기존 문서·Undo 경계를 재사용한다. 다만 적용 전에는 다음 위험을 충분히 설명하지 못했다.

1. 대사 수와 현재 컷 수가 맞지 않아 한 컷에 말풍선이 몰리는 문제
2. 긴 대사와 좁은 컷 조합으로 인한 가독성 저하
3. 대사가 있는 상태에서 기본 말풍선 포함 프리셋을 골랐을 때 공간이 경쟁하는 문제
4. 화자 표기가 섞였을 때 말풍선 좌우가 예상과 달라지는 문제
5. 조립 엔진이 `composable=false`를 반환한 뒤에야 실패를 알 수 있는 문제

이번 변경의 목표는 새 문서 모델이나 별도 편집기를 추가하는 것이 아니라, **현재 조립 결과를 적용하기 전에 설명하고 바로 고칠 수 있는 제작 프리플라이트**를 제공하는 것이다.

## 2. 유사 서비스 벤치마크

### Clip Studio Paint

공식 제품 설명은 코마 나누기, 말풍선, 텍스트, 집중선, 톤을 빠르게 만들 수 있는 만화 전용 도구와 네임부터 마감까지 이어지는 제작 흐름, 여러 페이지 관리, 웹·인쇄용 출력 경계를 함께 강조한다.

- 참고: https://www.clipstudio.net/
- 수용한 원칙
  - 원클릭 생성보다 **적용 전 제작 품질 확인**을 같은 흐름 안에 둔다.
  - 컷·말풍선·텍스트를 적용 후에도 각각 편집 가능한 네이티브 요소로 유지한다.
  - 프리플라이트가 문서를 직접 바꾸지 않고 사용자가 명시적으로 적용하도록 한다.

### MediBang Paint

MediBang의 배포 설명은 만화 패널, 스크린톤, 말풍선, 다수 폰트와 클라우드 동기화·협업을 한 작업 흐름으로 묶는다.

- 참고: https://play.google.com/store/apps/details?id=com.medibang.android.paint.tablet
- 수용한 원칙
  - 복잡한 전문 설정 대신 초보자도 이해할 수 있는 짧은 안내와 즉시 실행 가능한 보정을 제공한다.
  - 협업·저장 경계는 기존 Studio가 소유하고, 새 도구는 결정론적 계획만 만든다.

### Krita

Krita는 디지털 페인팅뿐 아니라 comics와 animation을 명시적인 지원 분야로 두고, 실제 제작 흐름과 개방형 상호운용성을 중시한다.

- 참고: https://docs.krita.org/en/
- 수용한 원칙
  - 진단과 추천 로직을 UI에서 분리한 순수 모듈로 구현한다.
  - 실제 조립 엔진 결과를 최종 권위로 사용하고, 프리플라이트 추정치가 이를 덮어쓰지 않는다.

### MangaFlow (2026)

MangaFlow는 이야기 분해, 레퍼런스 정착, 레이아웃 구성, 렌더링, 페이지 합성, 텍스트 배치를 분리하고 레이아웃과 레터링을 편집 가능한 중간 변수로 노출한다.

- 참고: https://arxiv.org/abs/2605.28173
- 수용한 원칙
  - 직접 완성 이미지를 만드는 대신 `layoutId`, 장면 선택, 대사 스크립트를 독립된 중간 변수로 유지한다.
  - 레이아웃 추천은 자동 적용하지 않고 사람이 확인·교체할 수 있게 한다.
  - AI 코믹 생성 기능과 중복하지 않고, 기존 결정론적 Quick Comic 경로의 품질 게이트에 집중한다.

## 3. 기능 갭과 구현 매핑

| 기능 갭 | 구현 | 사용자 가치 |
| --- | --- | --- |
| 현재 레이아웃이 대사량에 맞는지 알기 어려움 | 모든 제공 레이아웃을 대사 수, 컷당 최대 대사, 긴 문장, 컷 폭, 프리셋 말풍선 기준으로 점수화 | 대사를 입력하는 즉시 더 적합한 컷 흐름 확인 |
| 적용 실패 안내가 늦고 추상적임 | 실제 `assembly.composable`을 blocker로 승격 | 적용 버튼이 안전하지 않은 결과를 만들지 않음 |
| 컷당 말풍선 과밀 | 모듈로 배치와 같은 순환 분배를 계산해 컷당 평균·최댓값 표시 | 왜 과밀한지 수치로 이해 |
| 긴 말풍선 | 52자 초과 감지, 자연스러운 문장·공백 경계에서 자동 분할 | 화자 좌우를 보존하며 빠르게 수정 |
| 화자 형식 혼합 | 전각/반각 콜론과 공백을 정규화하고 혼합 표기 진단 | 좌우 배치 예측 가능성 향상 |
| 기본 말풍선 프리셋과 입력 대사 충돌 | 프리셋 `bubbles`와 실제 대사가 함께 있을 때 경고, 빈 컷 기반 레이아웃 추천 | 중복 말풍선과 겹침 위험 감소 |
| 검수 결과가 색에 의존 | 상태·심각도 한글 라벨, 아이콘, 제목, 설명을 함께 제공 | 색각과 보조기술 환경에서도 의미 유지 |
| 모바일에서 조작이 작음 | 핵심 보정 버튼과 이동 버튼 최소 44px | 터치 오작동 감소 |

## 4. 구현 구조

### `studio-quick-comic-preflight.ts`

UI와 분리된 결정론적 모듈이다.

- 대사 메트릭
  - 전체, 대사, 나레이션, 화자 수
  - 화자 미지정 수
  - 평균·최대 글자 수
  - 긴 대사 수
- 레이아웃 메트릭
  - 컷 수
  - 컷당 평균·최대 대사
  - 현재 레이아웃 적합도
- 결과
  - `ready`, `review`, `blocked`
  - 0~100 가독성 점수
  - 심각도별 이슈
  - 추천 레이아웃과 설명
- 보정
  - 대사 형식 정규화
  - 긴 대사 자연 경계 분할

### `studio-quick-comic-plan.ts`

기존 preview가 실제 assembly와 함께 preflight 보고서를 반환한다. 조립 결과가 프리플라이트의 최종 권위이며, 기존 `ComipoAssemblyInput` 공개 계약은 바꾸지 않는다.

### `StudioQuickComicWizard.tsx`

- 레이아웃 단계: 현재 적합도와 추천 표시
- 대사 단계: 실시간 프리플라이트, 추천 레이아웃 적용, 형식 정리, 긴 대사 분할
- 미리보기 단계: 점수, 상태, 메트릭, 전체 이슈, 적용 가능 여부
- 기존 Escape, Alt+방향키, Ctrl/Command+Enter, 포커스 트랩, 배경 inert, 포커스 복귀 유지

## 5. 안전 경계

- 새 문서 형식, 서버 저장소, AI 공급자 호출을 추가하지 않는다.
- 조립 적용은 기존 `applyQuickComicInput`과 문서 변경 티켓, 충돌 검사, Undo 경계를 그대로 통과한다.
- 추천은 자동 적용하지 않는다.
- `assembly.composable=false`는 프리플라이트 추정치보다 우선한다.
- 화자를 추론하거나 대사를 다시 쓰지 않는다. 사용자가 입력한 의미를 보존하면서 공백·구두점 형식과 길이만 정리한다.
- 기존 AI 코믹 디렉터 PR의 생성·후보·참조 이미지 범위와 중복하지 않는다.

## 6. 테스트 범위

- 빈 초안의 안정적인 기본 추천
- 대사 8개/2컷의 과밀 감지와 다컷 추천
- 기본 말풍선 프리셋 충돌 감지
- 전각 콜론 정규화
- 긴 대사 분할 후 동일 화자의 좌우 보존
- 나레이션 형식 보존
- 실제 assembler 실패 시 blocker 처리
- 대사 단계에서 프리플라이트 노출 및 추천 레이아웃 원클릭 적용
- 긴 대사 원클릭 분할
- 기존 4단계, 접근성, 키보드, 적용 입력 회귀 테스트 유지

## 7. 후속 우선순위

이번 변경 이후에는 다음 순서가 효과적이다.

1. 컷별 대사 드래그 재배치와 컷별 읽기 순서 미리보기
2. 여러 페이지에 걸친 대사 밀도·클리프행어 리듬 분석
3. 플랫폼별 안전 영역과 글자 크기 프리셋
4. 식자 검수: 금칙 처리, 말줄임·구두점 규칙, 세로쓰기
5. 인쇄용 재단·도련·톤 모아레 검사

이 항목들은 현재 문서 모델과 내보내기 경계에 영향을 주므로 별도 수직 슬라이스로 진행한다.
