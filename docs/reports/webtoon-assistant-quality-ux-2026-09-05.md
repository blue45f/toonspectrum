# 웹툰 보조 기능 경쟁력·완성도·UI/UX 고도화 보고서

- 기준일: 2026-09-05
- 범위: `StudioCompanionAssistantDisplay`, 웹툰 창작 보조 센터의 컴패니언 표면
- 목표: 기능 나열형 보조 도구를 **현재 데이터의 출처가 보이고, 결과에서 바로 다음 작업으로 이어지는 제작 도구**로 전환

## 1. 경쟁 제품에서 확인한 기준선

### Clip Studio Paint

공식 웹툰·컴패니언 문서에서 확인되는 강점은 다음과 같다.

- 스마트폰을 단축키, 퀵 액세스, 색상 혼합, 도구 관리, 터치 캔버스 조작, 실시간 프로젝트 프리뷰 장치로 사용한다.
- 웹툰 원고를 실제 스마트폰 비율로 실시간 확인한다.
- Story Editor에서 대사, 말풍선, 폰트, 자간, 레이아웃과 효과선을 묶어서 관리한다.
- 웹툰 프리셋, 빈 공간 추가·제거, 페이지 관리, 내보내기 프리셋, WebP 등 제작 후반 흐름이 연결된다.

공식 참고:

- https://www.clipstudio.net/en/functions/multi-device/
- https://www.clipstudio.net/en/comics-manga/
- https://tips.clip-studio.com/en-us/articles/4001
- https://www.clipstudio.net/en/dl/release_note/latest/

### MediBang Paint

공식 제품 설명에서 확인되는 강점은 다음과 같다.

- 만화용 폰트와 소재, 페이지 단위 프로젝트, 클라우드 동기화와 그룹 프로젝트를 함께 제공한다.
- 모바일·태블릿 환경에서 패널 분할과 만화 제작 도구의 접근성이 높다.

공식 참고:

- https://medibangpaint.com/en/
- https://medibangpaint.com/en/use/2022/12/comic-project/

### 벤치마크 결론

경쟁력이 높은 제품은 보조 기능 개수만 많지 않다. 공통적으로 다음 흐름을 완성한다.

1. 현재 원고 또는 현재 선택을 자동으로 받는다.
2. 분석값과 추정값을 구분한다.
3. 결과의 근거와 영향 범위를 설명한다.
4. 같은 화면에서 수정·삽입·복사·프리뷰로 이어진다.
5. 데스크톱과 모바일에서 같은 작업을 44px 이상 터치 타깃으로 수행한다.

## 2. 기존 ToonSpectrum의 강점

기존 구현은 기능 범위 자체는 이미 경쟁력이 높았다.

- 7개 플랫폼 규격과 출처 신뢰도 기반 감사
- 보호 영역을 피하는 안전 슬라이스 계획
- WEBTOON CANVAS 공식 간격 기준과 휴리스틱을 구분한 페이싱 분석
- 8개 범주의 한국어 효과음 사전
- 5개 피부톤과 휴 시프트 음영 계산
- 웹툰 제작 6공정 포모도로 엔진
- 30·60·180초 크로키와 4개 투시 프리셋
- 별도 창·태블릿·다중 모니터용 컴패니언 표면

즉 부족한 것은 엔진 수가 아니라 **데이터 신뢰성, 편집 연계, 제어 깊이, 작은 화면의 작업 완결성**이었다.

## 3. 발견한 핵심 결함

### P0 — 예시 데이터가 현재 원고처럼 보임

- 규격 탭은 실제 포맷을 알 수 없는데도 `jpg`를 고정했다.
- 실제 컷 간격을 받지 못하는데 `[150, 250, 400, 300, 800]`을 넣어 감사했다.
- 페이싱 탭은 고정 패널 5개를 분석했지만 예시라는 표시가 없었다.
- 따라서 경고가 정확해 보여도 현재 원고와 무관할 수 있었다.

### P0 — 결과에서 수정으로 이어지지 않음

- 규격과 페이싱 값을 컴패니언에서 직접 고칠 수 없었다.
- 효과음 카드는 전체 클릭이 복사여서 삽입과 복사의 의도가 분리되지 않았다.
- 컬러는 프리셋 조회만 가능했고 임의 밑색 계산과 장면 무드 비교가 없었다.

### P1 — 보조 도구의 제어 깊이가 엔진보다 얕음

- 포커스 타이머 엔진은 공정·3개 모드·초기화를 지원하지만 UI는 시작/정지만 제공했다.
- 크로키 엔진은 3개 간격과 4개 투시를 지원하지만 UI는 다음 포즈만 제공했다.
- 페이싱 엔진은 실제 독자 화면 높이를 받을 수 있지만 UI 입력이 없었다.

### P1 — 신뢰도와 휴리스틱 표현 부족

- 플랫폼 규격의 공식·외부·미검증 출처는 엔진에 있으나 컴패니언 요약에서는 판단 범위가 약했다.
- 페이싱의 공식 구간과 출처 없는 휴리스틱이 같은 무게로 보였다.

## 4. 이번 구현

### 4.1 데이터 출처 계약

컴포넌트 입력을 다음으로 확장했다.

- `canvasWidth`, `canvasHeight`
- `imageFormat`
- `panelGuttersPx`
- `panels`
- `readerViewportHeightPx`
- `onInsertSfxText`

모든 분석 표면은 데이터 상태를 `현재 원고`, `직접 입력`, `예시 데이터`로 표시한다.

- 실제 값이 없으면 예시 모드로 시작한다.
- 예시 결과는 업로드 차단 판단에 쓰지 않는다고 명시한다.
- 포맷과 컷 간격이 없으면 값을 만들지 않고 `미검사`로 표시한다.
- 사용자가 값을 바꾸는 순간 `직접 입력`으로 전환한다.

### 4.2 플랫폼 규격·슬라이스

- 폭·높이·포맷·컷 간격을 한 화면에서 수정할 수 있다.
- 포맷 미지정과 컷 간격 미지정을 별도 상태로 보여준다.
- 더 이상 가짜 JPG·가짜 컷 간격을 감사 입력에 넣지 않는다.
- 플랫폼별 권장 폭, 전체 판정, 권장 슬라이스 수, 우선 이슈 4건을 단계적으로 보여준다.
- 현재 원고 값 복원 또는 예시값 초기화 경로를 제공한다.

### 4.3 스크롤 페이싱

- 실제 패널 스팬이 있으면 현재 원고를 분석한다.
- 없으면 컷 사이 여백을 직접 입력하는 간이 시뮬레이터를 제공한다.
- 간이 모드는 컷 높이 600px 가정과 완독 시간 추정임을 명시한다.
- 독자 화면 높이를 입력했을 때만 화면당 컷 수를 판정한다.
- 각 비트에 `공식 근거` 또는 `휴리스틱` 배지를 붙인다.
- 경고를 우선순위 블록으로 묶고, 경고가 없으면 완료 상태를 보여준다.

### 4.4 효과음

- 카드 전체 클릭을 제거하고 `캔버스에 삽입`과 `텍스트 복사`를 독립 액션으로 분리했다.
- 삽입 콜백이 없는 환경에서는 복사만 노출한다.
- 복사 성공·실패와 삽입 성공·실패를 색만이 아니라 라이브 텍스트로 알린다.
- 검색, 카테고리, 페이지 확장, 빈 상태 복구 흐름을 유지했다.

### 4.5 컬러 조화

- 5개 피부톤 프리셋을 유지했다.
- 임의의 `#RRGGBB` 밑색을 입력하거나 컬러 피커로 선택할 수 있다.
- 하이라이트·밑색·1차 음영·2차 음영을 즉시 계산하고 각 값을 복사할 수 있다.
- 잘못된 HEX는 계산 성공처럼 보이지 않고 명시적 오류를 낸다.
- 골든아워·학원물·누아르·사이버펑크 장면 무드를 같은 탭에서 비교한다.

### 4.6 포커스 타이머

- 6개 제작 공정 선택
- 표준 25/5, 몰입 50/10, 스프린트 15/3 선택
- 시작·일시정지·세션 초기화
- 진행률, 완료 포모도로, 공정 누적 시간 표시

### 4.7 크로키·투시

- 30·60·180초 간격 선택
- 시작·일시정지·리셋
- 다음 포즈 선택 시 추천 시간 자동 적용
- 동세선, 해부 포인트 표시
- 아이레벨·로우앵글·하이앵글·더치 앵글 선택
- 지평선 위치·기울기·소실점 개수의 간이 프리뷰

### 4.8 모바일·접근성

- 탭 본문의 모든 버튼에 공용 포커스 링과 44px 최소 터치 타깃을 적용했다.
- 좁은 창에서도 탭 스트립은 가로 스크롤을 유지한다.
- 색 띠, 아이콘 버튼, 진행률, 복사·삽입 상태에 접근 가능한 이름을 제공한다.
- 장식용 아이콘은 접근성 트리에서 제외한다.
- 모션 감소 환경에서는 진행 전환 애니메이션을 줄인다.

## 5. 비교 점수

| 기능 범위 | 4.5 | 4.8 | 기존 6개 엔진에 사용자 제어를 연결 |

| 작업 연계성 | 2.7 | 4.4 | 직접 입력, 삽입/복사 분리, 즉시 계산·제어 |

## 6. 검증 계약

`StudioCompanionAssistantDisplay.test.tsx`가 다음을 회귀 방지한다.

- 예시 데이터를 현재 원고처럼 표시하지 않음
- 포맷·컷 간격 미검사 상태
- 현재 원고와 직접 입력 상태 전환
- 뷰포트가 있을 때만 화면당 컷 수 판정
- 현재 패널 스팬 사용
- 효과음 삽입·복사 액션 분리
- 클립보드 실패를 성공으로 표시하지 않음
- 임의 HEX 검증과 음영 결과
- 공정·집중 모드·크로키 간격·투시 제어
- 모든 탭 본문 버튼의 44px 터치 타깃과 포커스 링
- 장식 아이콘의 접근성 트리 제외

## 7. 다음 통합 경계

이번 변경은 컴패니언 자체가 거짓 판정을 하지 않고 독립적으로 작업을 끝낼 수 있게 만든다. 다음 통합 단계에서 아래 데이터를 주입하면 수동 입력 없이 완전히 현재 원고 기반으로 전환된다.

1. `StudioToolsCompanionPage`에서 `navigatorImage.width/height`를 `canvasWidth/height`로 전달
2. 검수 프로젝션에 패널 스팬과 컷 간 여백 추가
3. 현재 독자 프리뷰 프레임 높이를 `readerViewportHeightPx`로 전달
4. 효과음 삽입 콜백을 기본 스튜디오 텍스트 레이어 명령에 연결
5. 컬러 결과를 현재 팔레트 또는 선택 레이어 색상에 적용하는 명령 연결

이 경계를 연결하기 전에도 예시·수동·현재 원고 상태가 분리되므로 잘못된 자동 판정으로 작가를 오도하지 않는다.
