# Shaper 벤치마크 기반 3D 제작 품질 개선

기준: `29aa82c1214fe9dbeba6712fcb9fc523528ef8f2`. 경쟁 서비스와 기존 기능의 상세 판정은 [별도 벤치마크](shaper-competitive-benchmark-2026-09-12.md)에 기록했다. 이 문서는 이번에 실제로 바뀐 동작과 검증 범위를 기록한다.

## 캐릭터 출력

기존 PNG/PSD는 뷰포트 비율에서 높이 520px로 크기를 결정했다. 새 파일 해상도 선택기는 PNG의 긴 변을 1024·2048·4096px로 지정하며 기본은 2048px이다. 실제 뷰포트 비율을 유지한다. 여러 레이어를 동시에 보유하는 PSD는 긴 변 2048px 상한을 화면에 표시한다.

4K PNG는 8MP를 넘는 장면을 최대 1024×1024 타일로 렌더링하여 최종 해상도의 픽셀을 직접 연결한다. MToon의 화면 기준 외곽선은 타일 투영 배율을 보정하므로 마지막 부분 타일까지 같은 선폭을 유지하고, 실패 후에도 원래 재질 값을 복원한다. 카메라의 부분 투영과 4배 MSAA를 유지하며 확대 보간하지 않는다. 단일 PNG 전용 워커만 최대 4096×4096을 허용하고, BG3D의 다중 레이어 PNG·LT·PSD와 명시적 메인 스레드 인코더의 8MP 예산은 유지한다. 워커 실패를 메인 스레드 인코딩으로 자동 재시도하지 않는다. GPU 렌더와 readback 자체는 기존 동기 API이며, 타일 사이에 UI를 양도하는 비동기 캡처를 보장하지는 않는다.

PNG, PSD, 캔버스 삽입, 썸네일, 포즈 공유가 동일한 캡처 작업 권한을 사용한다. 내보내기 중에는 화면 조작뿐 아니라 VRM 애니메이션, 웹캠 포즈 적용, 소품의 보조 손 IK, 그립 보정, 의상 물리의 프레임 갱신을 멈춘다. 중단할 때 기존 포즈를 초기화하지 않는다. 첫 패스 전에 현재 포즈와 의상 물리를 동기화한다.

내보내기 진행·완료 안내와 취소 버튼은 뷰포트 밖 레이아웃의 높이를 변경하지 않는 overlay로 표시한다. 저장 안내가 카메라 비율을 바꿔 연속 PNG와 PSD 크기가 달라지던 실제 브라우저 결함을 수정했다.

여러 패스 사이에서 모델·카메라·렌더러·표면 페인트 리비전이 바뀌면 출력을 취소한다. 취소 버튼, 화면 닫기, 모델 변경 이후 오래된 파일이 다운로드되지 않도록 검사한다. 캡처 소유권 토큰은 이전 작업의 정리가 새 작업의 잠금을 해제하지 못하게 한다. 장면 재질과 도우미를 복원한 뒤 잠금을 해제한다.

음영과 하이라이트는 단순 차분 대신 Multiply/Screen 역합성 계수로 만든다. 불투명 픽셀의 모든 65,536 채널 조합은 RGBA8 반올림 오차 1 이내로 원래 색을 재현한다. 반투명 경계, PSD 그룹 규칙, 추가 선화 레이어까지 포함한 전체 합성의 동등성을 보장하는 수치는 아니다.

선화는 셰이딩을 제거한 밑색의 알파·명도 경계에서 추출한다. 검은 머리·옷의 면 전체를 잉크로 채우던 near-black 합집합과 툰 그림자 경계를 선으로 복제하던 경로를 제거했다. 재질의 텍스처 경계까지 포함하는 래스터 선화이며, 벡터 선 또는 직접 추출한 기하학 선이라고 표시하지 않는다.

PSD의 독립 표면 드로잉 레이어는 현재 런타임이 획만 있는 텍스처를 제공하지 않아 지원되지 않는다. 실제 결과에는 드로잉이 포함되지만, 별도 획 레이어를 제공한다고 설명하지 않는다. 생략된 패스와 이유를 결과 안내에 표시한다.

## 의상의 실제 변형

동일 PNG를 시각 검수해 절차적으로 생성하는 상의의 어깨 연결부가 솟는 현상을 확인했다. 어깨 폭을 몸통 최대 폭으로 늘리던 계산, 수평 튜브의 과도한 높이, 가로축을 골반→가슴 축으로 해석하던 웨이트를 고쳤다. 연결부 안쪽은 가슴을 따르고 바깥쪽은 대응하는 윗팔을 따른다.

소매 가중치는 옷 전체 길이 대신 실제 관절 구간으로 계산한다. 윗팔의 42%만 덮는 반팔의 끝단이 팔꿈치 본에 붙어 움직이던 결함을 수정했다. 회귀 검사는 팔꿈치만 90° 굽힐 때 반팔이 끌려가지 않는 것, 팔 회전 때 어깨 연결부가 각 본을 따르는 것, 골반 폭이 어깨 위치를 이동시키지 않는 것을 검증한다. 실제 `sample.vrm`과 `AvatarSample_B.vrm`을 로드한 회귀 검사도 추가했다. 양쪽 소매의 410개 정점이 0.6·1.25라디안 팔 회전과 원위치에서 실제 윗팔 본을 따르는지 검증하며, 소매 시작점이 쇄골에 붙어 공중에 남던 가중치도 수정했다.

변형 결함을 고친 뒤에도 절차형 의상의 연결부·주름·충돌 품질은 전문 제작 원본에 미치지 못한다. 기본 의상 선택은 모델 원본을 유지하고, 절차형 의상은 추천에서 제외하여 **실험 의상 표시**를 직접 켠 경우에만 탐색할 수 있게 했다. 이전에 저장한 선택은 변경하지 않고 계속 표시한다. 실험 의상을 검수한 이미지와 원본 모델로 만든 출판용 검증 이미지를 구분해 보관한다.

## 카메라와 결과 이미지 구도

기존 화면 맞춤은 하나의 선택만 허용하고 경계 구를 기준으로 거리를 계산했다. 새 계산은 선택한 표시 객체들의 경계 상자 꼭짓점을 카메라 공간에 투영한다. 세로·가로 화면, 원근·평행 투영, 줌, 렌즈 시프트, 기울어진 카메라와 가까운 클리핑 평면을 반영한다.

다중 선택은 한 번의 실행 취소 단위로 맞춘다. 잠긴 객체도 구도에 포함할 수 있고 숨겨진 객체/하위 객체는 제외한다. 선택한 표시 모델이 아직 로딩 중이거나 실패한 경우 일부 모델만 맞춘 결과를 성공으로 처리하지 않는다.

화면 맞춤은 내보내기 비율의 실제 안전 프레임을 고려한다. 화면에서는 보이지만 세로 원고로 자를 때 사라지는 객체를 방지하기 위한 변경이다. 9:16 가이드도 뷰포트 크기로 계산하므로 넓거나 좁은 화면에서 비율이 바뀌지 않는다.

Three.js `setViewOffset`이 원근 카메라 비율을 1로 바꾸던 렌즈 시프트 경로를 수정했다. 큰/작은 모델의 화면 맞춤을 기존 고정 OrbitControls 거리 제한이 다시 잘라 버리지 않도록 거리와 클리핑 범위를 장면 크기에 맞춘다.

카메라 명령 전에 OrbitControls의 남은 회전·이동 관성을 공개 API로 비운다. 화면 맞춤·줌·실행 취소 직후 이전 드래그가 계속 적용되어 구도가 움직이는 결함을 수정했다. 실제 OrbitControls에서 명령 뒤 100프레임 동안 위치가 유지되는 회귀 검증을 추가했다. 연속 확대가 초점 대상을 near 평면 안쪽으로 밀어 넣지 않도록 최소 거리를 near 값에 연결했다. near 0.1·0.01에서 세 번의 0.5배 확대와 이후 20프레임의 대상 클립 좌표를 검증하며, 명령이 near 자체를 바꾸지는 않는다.

## 모바일과 초기 편집 보존

320px에서 대화상자의 자동 그리드 열이 최소 콘텐츠 폭을 따라 늘어나고, 바깥의 `overflow:hidden`이 잘라내고 있었다. 단순 문서 가로 스크롤 검사는 이를 놓쳤다. 열의 최소 폭을 0으로 제한하고, 작은 화면의 상단 액션을 두 줄로 배치하며, 내보내기 팝업은 부모 도크 폭에 맞췄다. 모바일 카메라 프리셋과 부위 검사도 캔버스 위의 독립 영역으로 옮겨 도구가 캐릭터 얼굴을 가리지 않게 했다. 품질 도구는 시트 헤더로 옮겨 PNG/PSD 버튼을 가리지 않게 했다.

브라우저 검사는 390·320px에서 출력 패널을 열고 닫아 필수 컨트롤의 실제 경계, 잘라내는 조상 요소, 44px 터치 크기와 세 지점의 클릭 대상까지 검사한다. 의도적으로 스크롤하는 프리셋 레일과 모든 컨트롤이 항상 노출되어야 하는 상단/출력 도크를 구분한다.

BG3D 엔진 선택 가능 여부와 실제 렌더러·초기 문서 복원 완료는 다른 시점이었다. 초기 복원이 첫 사용자 편집을 덮어쓸 수 있는 경합을 확인하여, 열림/렌더러/복원 준비 상태를 도형 UI와 장면 변경 명령에 공통 적용했다. 실제 복원 hook의 지연·재열기·렌더러 교체 시험에서 복원 전 추가는 받지 않고, 복원 완료 뒤 첫 추가와 히스토리는 보존한다.

## 실제 장면과 연결되는 제작 화면

기존 Pro Suite의 20개 항목을 각각 추적했다. 컷 디렉터와 멀티패스는 이미 실제 장면과 연결되어 있었지만, 나머지 18개 진입점은 패널 내부 상태·예제 데이터·호출되지 않는 callback에 머물렀다. 해당 제작 화면을 `구도 → 컷 디렉터 → 원고 출력`으로 재구성했다. 독립 실험 모듈의 소스와 테스트는 남아 있으며, 기존 캐릭터 편집기의 포즈·의상·페인트 도구는 계속 사용할 수 있다.

새 화각 카드는 실제 장면 카메라에 명령을 보낸다. 선택 표시는 로컬 클릭 상태가 아니라 장면의 현재 화각을 읽으므로 실행 취소·컷 적용과 일치한다. 피사체 크기 유지 옵션은 초점 지점의 투영 크기를 유지하며 카메라 거리를 조정한다. 원근상 초점 깊이가 다른 대상까지 동일한 크기를 유지한다고 약속하지 않는다.

컷 디렉터와 원고 출력은 기존 runtime wrapper를 사용한다. 출력 가능한 패스 필터, 사전 검증, 복구 가능한 ZIP/PSD 경로를 유지한다. 탭은 화살표·Home·End 키로 이동할 수 있으며 한번 연 패널의 옵션을 보존한다. 숨겨진 디렉터는 카메라 재생을 멈춘다.

## 검증 기록

소스/단위 테스트 통과를 실제 GPU 출력 또는 경쟁 서비스와의 시각적 동등성으로 해석하지 않는다. 다음 명령은 작업 checkout에서 실행했다. pnpm 11 공유 의존성 worktree에서는 `pnpm_config_verify_deps_before_run=warn`을 지정해 별도 install을 막았다. 의존성 또는 lockfile 변경은 없다.

SwiftShader로 전체 캐릭터 편집 화면을 실행한 시도는 screenshot 시간 초과로 완료되지 않았다. 작은 엔진 fixture 통과를 전체 캐릭터 소프트웨어 렌더링의 통과로 기록하지 않는다. 실기기 캐릭터 검증과도 다른 실행 조건이다.

## 엔진 검토

Three.js/R3F, 기존 Babylon specialist, PlayCanvas, Unity, Godot, Unreal의 엔진 기능·웹 제약·도입 비용은 [엔진 평가](studio-3d-engine-evaluation-2026-09-12.md)에 구분한다. 현재 캡처/문서 경계를 유지해 동일 장면으로 비교하는 전략이며, 다른 엔진의 기능표만으로 품질이나 속도 향상을 판정하지 않는다.

## 남은 비교 검증

- Shaper 설치 앱과 동일한 캐릭터·포즈·조명·출력 크기로 비교한 자료는 없다.
- 에셋마다 얼굴 형태·스키닝·헤어·의상과 셰이프키 지원이 다르다. 고품질 원본 메시 제작 및 극단 포즈에서의 관통/변형 검수는 별도 자산 작업이 필요하다.
- 일부 프리셋의 썸네일은 실제 모델 렌더가 아닌 도해다. 실제 적용 결과와 동등한 미리보기라고 판정하지 않는다.
- 인증을 요구하는 클라우드 저장·재접속과 실제 카메라 입력은 별도의 실행 증거가 필요하다.
- 웹 브라우저 GPU 경로별 성능과 색·알파 품질은 실제 사용한 backend를 명시하여 판정해야 한다.
