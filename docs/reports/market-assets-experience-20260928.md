## 현재 구현

### 탐색에서 비교로

마켓 홈에서 바로 검색할 수 있다. URL 검색어는 기존 계약으로 검증하고 인코딩하며, 한글 조합 중간값을 제출하지 않는다. 검색 결과에서 카드·목록 보기를 변경해도 검색·종류 조건을 유지한다. 표시 방식은 API 검색 조건에 섞지 않는다.

검색 결과의 중복 카테고리 메뉴를 줄이고 개별 종류 조건을 제거할 수 있게 했다. 실제 비교 후보를 선택하면 후보 수·개별 제외·전체 비우기·비교 화면 이동을 제공한다. 비교 목록은 소장 권한을 부여하지 않는다. 최신 소재의 태그를 인기 데이터처럼 표시하던 제목은 ‘최근 공유 소재의 키워드’로 수정했다.

### 내 에셋에서 제작으로

이름·패키지·한글/영어 종류·버전의 다중 단어 검색, 최근/오래된 추가순·이름순 정렬, 종류·공개 상태·계정 업데이트 이력 필터를 추가했다. 한글 분해 문자와 전각 영문도 정규화한다. 각 소재는 정확한 현재 릴리스의 상세 화면과 기존 기기 설치 확인·Studio 동선으로 연결한다.

보관·복원은 서버 응답 뒤에 반영하며, 실제로 변경된 작업만 실행 취소를 제공한다. 계정이나 소장/보관 보기 문맥이 바뀌면 취소 권한도 폐기한다. 소장/보관 탭은 방향키·Home·End 이동과 선택 상태를 지원한다.

### 화면·접근성

내 에셋의 헤더·검색·상태 요약·소재 카드를 하나의 계층으로 정리했다. 44px 보기 전환과 카드의 찜/비교 버튼, 모바일 필터 배치, reduced-motion·forced-colors 스타일을 추가했다. 신규 공통 검색·필터·비교 UI는 한국어/영어 원문을 기존 i18n 체계에 연결했다. Studio 소재 허브 안에서는 중복 마켓 내비게이션을 렌더링하지 않고, 기존 프로젝트 연결 탭을 유지한다.

## 데이터 경계와 남은 범위

**검색·상태 개수는 현재 불러온 계정 라이브러리 항목에만 적용된다.** 현재 서버 DTO에는 전체 검색·전체 개수·썸네일·태그·사용권 메타데이터가 없으므로 이를 만들어내지 않는다. 결과가 없어도 미조회 페이지가 있으면 ‘더 보기’를 유지하고 검색 범위를 설명한다. 라이브러리 카드의 종류 아이콘은 실제 에셋 미리보기가 아닌 종류 표시다. 실제 미리보기·사용권은 상세 화면에서 확인한다.

계정의 과거 설치 확인은 현재 기기의 설치 증거가 아니다. 공개 상태도 해당 기기에서 바로 사용할 수 있다는 보장이 아니다. 기존 정확한 버전·매니페스트·기기 설치 검증을 계속 사용한다.

**target — 미구현:** 서버 전체 소장 검색, 프로젝트별 컬렉션, 일괄 설치·보관, 새 결제·구매 권한, 새 다운로드 시스템. 이번 변경에서 DB 연결·환경변수·마이그레이션·배포 파이프라인은 수정하지 않는다.

## 검증과 재현

저장소 루트에서 의존성 설치 후 실행한다. 브라우저 검증은 별도 Vite 포트와 가짜 API 응답을 사용하며 실제 계정·소장 데이터나 운영 DB를 변경하지 않는다.

```sh
pnpm exec vitest run apps/web/src/domains/market apps/web/src/domains/creator/studio-shell/StudioAssetHubPage.test.tsx --maxWorkers=2
pnpm harness:verify
TOONSPECTRUM_MARKET_E2E_PORT=5357 pnpm exec playwright test --config playwright.market.config.ts market-asset-experience.spec.ts
```

검증 결과와 남은 제한은 PR 본문에 실제 실행 결과로 기록한다. 브라우저 스크린샷은 해당 실행의 `test-results` 디렉터리에 저장된다. 자동 접근성 검사는 `.market-library-page`의 WCAG 태그 기준 serious/critical 위반을 검사하며, 앱 전체의 수동 접근성 인증을 의미하지 않는다.

## 검토·반영·롤백

작성자는 검증 결과와 화면을 PR로 제출하고 저장소 관리자가 리뷰 후 병합 여부를 결정한다. 성공 기준은 관련 테스트·타입·경계 검사 통과, 검색·보관 취소의 정확한 상태 변경, 모바일 가로 넘침 없음이다. 문제가 발견되면 해당 PR 커밋을 revert한다. 데이터 구조 변경이 없어 별도의 DB 롤백은 필요 없다. 이번 작업은 PR 생성까지이며 운영 배포를 수행하지 않는다.
