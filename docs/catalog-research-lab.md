# 작품 리서치 랩 · 수집 데이터 활용 확장

## 사용자 흐름

`/research/catalog`에서 작품명·작가·장르·태그를 검색하고 플랫폼·형식·연재 상태를 좁힌다. 현재 결과의 장르/플랫폼 분포와 소재 태그를 살펴보고 최대 4편을 비교한다. `/research/catalog/notebook`에서 조사 질문 → 직접 확인한 관찰 → 나의 가설 → 5컷 실험을 작성한다. CSV, 출처를 포함한 Markdown, 재가져오기 가능한 JSON을 제공한다.

## 벤치마킹과 적용 판단 (2026-09-13 확인)

- AniList의 만화 탐색 진입점: https://anilist.co/search/manga — 작품 카탈로그를 목적 있는 탐색으로 연결하는 방식을 참고했다. 외부 AniList 데이터를 가져오거나 API를 호출하지 않는다.
- Milanote의 캐릭터 기획 템플릿: https://milanote.com/templates/creative-writing/character-profile — 참고 자료와 질문을 창작 노트로 연결하는 방식을 참고했다. 서비스 템플릿·이미지·디자인·코드를 복제하지 않는다.
- 기존 ToonStudio의 리서치 데스크, 글로벌 도서/미술 자료 검색, 저장 보드, 스토리 연구실은 유지한다. 동일한 외부 자료 검색 페이지를 중복 생성하지 않고 기존 작품 카탈로그를 재활용한다.

## 데이터 계약과 정직한 표시

- 입력: `apps/api/data/catalog.json.gz` (또는 기존 빌드 환경변수로 지정한 스냅샷).
- 출력: 기존 `catalog:gen`의 `apps/web/public/data/research-index.json`. 별도의 예약 수집, DB, 외부 API, 새 패키지 의존성은 없다.
- 제목·작가·형식·상태·기록 연도·장르·태그·플랫폼 ID만 사전/튜플 형식으로 저장한다. 표지 URL, 소개문, 본문, 조회수, 평점 및 추정 트렌드 점수는 제외한다.
- `collectedAt`은 원본의 `crawledAt`이며 빌드 날짜로 바꾸지 않는다. 일부 KMAS 보강 날짜를 전체 수집 날짜와 별도로 표시한다. 원본에 날짜가 없으면 미상이다.
- `sourceHash`는 압축 입력 파일의 SHA-256 앞 16자다. 색인 버전과 기획 당시 출처를 구분한다.
- ID 중복 및 최소 형식 오류는 제외하고 건수를 표시한다. 제목이 같아도 서로 다른 플랫폼/판본 ID는 합치지 않는다.
- 한 작품의 같은 장르/태그/플랫폼은 한 번만 센다. 현재 필터에 맞는 모든 작품이 분모이며 중복 분류이므로 비율 합계가 100%를 넘을 수 있다.
- 상위 8개 장르/플랫폼, 상위 16개 태그임을 표시한다. 검색 결과는 24편씩 페이지를 나눈다. 기록되지 않은 정보는 0점이나 임의 추정으로 대체하지 않는다.
- 기록 연도는 실제 첫 연재일을 검증한 값이 아니다. 카탈로그 수록량은 시장점유율, 현재 인기, 매출 또는 흥행 가능성을 의미하지 않는다.
- 19세 작품 메타데이터는 기본 제외한다. 별도 체크로 포함할 수 있으며 해당 작품 본문이나 표지를 제공하는 기능이 아니다.

## 비용·수집 범위

기존에 배포하는 정적 데이터와 동일한 빌드/CDN 경로만 사용한다. 신규 유료 API, 결제, 유료 플랜, 데이터베이스 마이그레이션은 추가하지 않는다. 정적 파일 전송/빌드 사용량 자체는 기존 호스팅 한도의 영향을 받으므로 모든 사용량이 무제한 무료라는 뜻은 아니다.

이 변경은 외부 사이트를 새로 크롤링하지 않는다. 향후 수집처를 추가할 때에는 공식 API/허용 피드 우선, 제공처별 이용 조건·robots 정책·요청 빈도·출처/삭제 요청 경로를 별도 검토해야 한다. 공개 페이지라는 이유만으로 본문·이미지의 재배포나 AI 학습 권리를 가정하지 않는다.

## 런타임·브라우저 안전성과 복구

- 같은 출처의 정적 JSON만 요청한다. 응답 타입/크기/스키마를 검증하며 리디렉션·HTML fallback·손상된 항목은 수용하지 않는다.
- 동시 로드는 하나의 요청으로 합치고 검증된 파일만 CacheStorage에 보관한다. 갱신 실패 시 검증된 이전 캐시 또는 이미 로드한 메모리 자료를 유지한다.
- 저장된 색인의 날짜와 연결 실패 상태를 숨기지 않는다. 캐시 용량 초과 시 온라인 조회는 계속되며 오프라인 보관 실패를 알린다. 사이트 최초 오프라인 부팅까지 보장하는 기능이 아니다.
- URL은 검색 조건과 비교 작품 ID만 담는다. 사적인 기획 노트는 공유 링크에 포함하지 않는다.
- 노트는 명시적으로 저장하며 Web Locks와 저장 직전 값 비교로 다른 탭의 변경을 덮지 않는다. Web Locks 미지원 또는 손상된 저장 데이터는 쓰기를 막고 내보내기를 제공한다.
- JSON 가져오기는 크기·버전·문자열 길이를 검사하고 바로 영구 저장하지 않는다. 초안을 교체할 때 확인한다. 저장 도중 텍스트 입력/가져오기를 막아 저장 완료 콜백이 새 입력을 덮지 않게 한다.
- CSV는 모든 필드를 인용하고 수식으로 해석될 수 있는 접두사를 무력화한다. 내부 상세 링크는 경로를 인코딩하고 Markdown의 출처 메타데이터는 이스케이프한다.
- 기획 질문은 장르/태그 기반 규칙이며 AI가 원문을 읽거나 성공 가능성을 추론했다는 주장을 하지 않는다. 노트는 Studio에 자동 삽입되지 않는다.

## 검증

`catalog-research.test.ts`는 데이터 축약·형식 검증·출처 날짜·중복 집계·유니코드 검색·URL 경계·CSV 수식·Markdown·노트 충돌/손상/용량 실패를 검사한다. `catalog-research-data.test.ts`는 동일 출처 로딩·중복 요청 방지·검증된 오프라인 캐시·손상된 캐시·메모리 fallback·저장 실패·응답 타입/크기/상태를 검사한다. `CatalogResearchPage.test.tsx`는 검색·페이지 전환·4편 비교·기획 동선·빈 결과·색인 실패 재시도·저장/내보내기·다른 탭과 손상된 노트 보존을 검사한다.

```sh
pnpm exec vitest run apps/web/src/shared/lib/catalog-research.test.ts apps/web/src/domains/creator-resources/catalog-research-data.test.ts apps/web/src/domains/creator-resources/CatalogResearchPage.test.tsx
pnpm catalog:gen
pnpm typecheck
pnpm build
```
