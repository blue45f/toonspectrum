## 검토 범위에 관한 중요 사항

`/studio` 화면은 Canvas/WebGL 중심으로 렌더링되어 일반 웹 크롤러에서는 실제 편집기 내부를 읽을 수
없었다. 브라우저 원격 조작 환경도 연결되지 않아 로그인·클릭·드로잉을 포함한 완전한 실사용 E2E
테스트는 수행하지 못했다. 대신 최신 공개 소스, 제품 문서, 프로덕션 성능 측정 문서, 브라우저 검증
자료, CI 결과, 최신 PR 리뷰를 교차 분석했다. 아래 내용은 현재 소스에서 확인된 결함, 출시 위험,
과거에 수정된 회귀, 추가 실기기 검증이 필요한 UX 가설로 나뉜다.

## 1. 핵심 결론

ToonStudio는 이미 단순 웹 드로잉 도구 수준을 넘어섰다. 현재 소스와 검증 문서에는 기본
드로잉·도형·채우기뿐 아니라 템플릿, 콜라주, 말풍선, 스티커, 캐릭터, 배경, 브랜드 키트, 스톡 이미지,
AI 보조, 3D 배경·캐릭터, 애니메이션, 스토리 기획, 리뷰, 퍼블리싱까지 상당히 넓은 기능이 잡혀 있다.

따라서 다음 단계에서 가장 먼저 해결해야 할 문제는 기능 수 부족이 아니다.

- 저장·복원·내보내기를 믿을 수 있는가
- 실시간으로 보이는 결과와 확정·저장·내보내기 결과가 같은가
- 수많은 기능을 사용자가 발견하고 이해할 수 있는가
- 대용량 문서와 3D, 모바일 환경에서도 안정적인가
- 현재 복잡한 편집기 구조를 지속적으로 유지보수할 수 있는가

클립스튜디오의 최근 1년 방향도 유사하다. 대규모 기능 추가만 한 것이 아니라 브러시 지연 체감, 큰
브러시 성능, 복구 저널, 소재 탐색, 모바일 팜 리젹션, 메모리·고주사율·내보내기 오류를 집중적으로
다뤘다.

## 2. 현재 ToonStudio 기능 구조 분석

### 2.1 기본 편집·드로잉

| 구분 | 확인된 기능 |
| --- | --- |
| 기본 도구 | 선택, 그리기, 핸드/이동 |
| 그리기 모드 | 펜, 지우개, 도형, 픽셀, 라쏘 채우기 |
| 도형 | 선, 사각형, 타원, 별, 화살표, 삼각형, 다각형 |
| 콘텐츠 | 템플릿, 콜라주, 말풍선, 스티커, 요소, 캐릭터 |
| 배경 | 3D/장면 배경, 배경 채우기, 배경 에셋 |
| 소재 | 에셋, 톤, 장면, 클립, 팔레트, 브랜드 키트, 스톡 이미지 |
| 확장 | AI 보조, 외부 연동 |

이 구성 자체는 매우 강하다. 다만 콘텐츠 카테고리가 많아지면서 사용자가 "기능을 찾는 시간"이 실제
제작 시간보다 늘어날 수 있다.

### 2.2 웹툰·스토리 제작

검증 자료에서 확인되는 흐름: 7단계 작가실·스토리 기획, AI 초안 검토 및 캔버스 반영, 스토리보드와
세로 스크롤 미리보기, 장면 연속성 확인, 다중 레이어 타임라인, 문서 댓글과 리뷰·편집 잠금, 11종
말풍선과 꼬리 편집, 자동 액션의 페이지·배치 적용, 게시 전 사전 점검과 결정적 ZIP 출력.

이 부분이 ToonStudio의 가장 강한 제품 차별점이다. 기획 → 콘티 → 작화 → 식자 → 검수 → 플랫폼별
출력이 하나의 문서 모델로 이어지도록 만드는 편이 훨씬 경쟁력이 있다.

### 2.3 소재와 에셋

확인되는 기반: 저장 에셋 이름 변경·공유·삭제, 카페·학교·판타지·도시 등의 래스터 소품, 즐겨찾기,
브랜드 키트, 스톡 이미지, 팔레트와 톤, AI 및 외부 연동.

에셋 수가 수백·수천 개가 되면 즐겨찾기만으로는 부족하다. 최근 사용, 사용 빈도, 핀 고정, 프로젝트별
최근 소재, 태그 교집합, 라이선스·출처 필터가 필요하다.

### 2.4 채우기·선택·보정

Advanced Fill에는 범위, 허용 오차, 확장, 틈 닫기, 참조 레이어, 누출 방지, 미리보기, 적용·실행
취소가 잡혀 있다. 향후 중요한 것은 옵션을 더 늘리는 것이 아니라 (1) 초보자는 클릭 → 결과만으로
성공하게 만들기, (2) 전문가는 고급 옵션과 참조 규칙을 저장·재사용하게 만들기다.

### 2.5 3D

VRM, GLB, 3D 배경, 캐릭터, 표면 브러시, 2D→3D 계열 기능이 고려되어 있다. 3D 표면 브러시는 포인터
생명주기, 취소·블러·GPU 장치 손실 롤백, 원자적 커밋을 고려하고 있으며 샘플·연산량 상한도 존재한다.

3D는 "기능 존재"보다 아래 완성도가 중요하다: 실시간 표시와 확정 결과 일치, UV 경계에서 끊김 없는
페인팅, 텍스처 레이어·실행 취소, Base Color뿐 아니라 Normal·Roughness·Metallic 관리, 원본 모델
왕복 및 텍스처 일괄 출력, 저사양 기기의 LOD와 메모리 제어.

### 2.6 저장·복원·내보내기

SQLite WASM과 OPFS가 지속성의 중심이며, localStorage·IndexedDB는 호환 경로다. 입력·저장·복구·실행
취소·내보내기의 결정성을 시각 효과보다 우선한다는 제품 원칙도 적절하다.

문제는 실제 전원 차단, OS 프로세스 종료, 장시간 방치, 저장소 용량 부족, Safari·iPadOS 백그라운드
종료 등에 대한 외부 검증 게이트가 아직 충분히 통과되지 않았다는 점이다.

## 3. 최신 소스에서 확인된 현재 결함 (원문 주장)

아래 세 건은 확인 당시 최신 main 소스에 남아 있는 문제로 원문이 주장한 것이다. 실서비스에서 직접
클릭 재현한 것은 아니므로 "소스 수준 확정 결함"으로 표현했다.

### P1-1. `.will` 대용량 문서 CRC 제한 불일치

문서 스트로크 프로필은 최대 32MiB까지 허용하지만, 인코더가 사용하는 직접 CRC 경로의 상한은 1MiB다.
직렬화된 스트로크 데이터가 1MiB 초과 ~ 32MiB 이하이면 프로필 검증은 통과하지만 실제
인코딩·저장·내보내기 과정의 CRC 계산에서 실패할 수 있다.

- 사용자 영향: 스트로크가 많은 대형 문서의 저장 또는 내보내기 실패, 일정 크기 이후 갑자기 실패,
  재시도해도 같은 크기에서 반복 실패.
- 권장 수정: 32MiB 계약을 유지해야 한다면 CRC를 증분·청크 방식으로 변경. 프로필 제한을 1MiB로
  낮추는 것은 기존 계약을 깨므로 비권장.
- 필수 경계 테스트: `1MiB - 1`, `1MiB`, `1MiB + 1`, `32MiB - 1`, `32MiB`, `32MiB + 1`.
- 실패 시 "저장 실패"만 표시하지 말고 문서 크기, 처리 단계, 재시도 가능 여부, 진단 정보 복사 제공.

### P1-2. 구형 렌더러 대체 메타데이터 마이그레이션 오류

현재 스키마는 렌더러 대체 근거에 `fallback`이라는 구형 값을 허용하지 않고 구체적인 정규값을 요구한다.
하지만 구형 에셋을 옮기는 마이그레이션은 다른 필드는 바꾸면서 기존 `requiredEvidence: "fallback"`
값을 그대로 남길 수 있다.

- 사용자 영향: 이전 버전에서 저장한 에셋·프로젝트가 최신 버전에서 열리지 않음, 마이그레이션 직후
  재검증 실패, 특정 오래된 문서에서만 발생해 재현이 어려움.
- 권장 수정: 구형 `fallback`을 단순 삭제하지 말고 과거 의미에 따라 정규값(자동 성능 정책, 자동 복구
  정책, GPU 경로 사용 불가, 기기/API 비호환, 사용자 명시적 대체 선택) 중 하나로 명시적 변환.
- 필수 테스트: 구형 JSON fixture 로드 → 마이그레이션 → 최신 스키마 재검증 → 저장 → 다시 열기 →
  렌더러 선택 결과 동일 확인.

### P1-3. Dry Media 캐시 스냅숏의 레이아웃 검증 부족

보존된 렌더링 스냅숏을 재사용할 때 현재 코드는 주로 `elementSheet` 동일성만 확인하고, 스냅숏 생성
당시 레이아웃 키와 현재 레이아웃 키가 동일한지 충분히 검증하지 않는다.

- 예상 증상: 창 크기 변경 후 이전 프레임 잔상, DPR 변경·브라우저 줌 후 캐시 오배치, 회전·확대·축소
  후 일부 타일이 과거 위치에 표시, 실시간 결과와 확정 결과의 순간적 불일치.
- 권장 재사용 조건: `same element sheet AND same layout key AND same DPR AND same render scale AND
  compatible viewport transform`. 하나라도 다르면 해당 타일 재렌더링.
- 필수 회귀 테스트: 창 크기 변경, 100%→200% 브라우저 줌, DPR 1·2·3, 캔버스 회전, 패널 열기·닫기,
  모니터 간 창 이동, 모바일 방향 전환.

## 4. CI와 테스트 신뢰도 문제

확인 당시 최신 main 체크는 34개 중 31개 성공, 2개 실패(Studio Perf Harness, 일반 test), 1개 건너뜀.
실패 로그 근본 원인은 확보되지 않았다.

반드시 적용할 배포 원칙:

```text
main required checks 모두 성공
+ 문서 저장/재오픈 테스트 성공
+ 실시간/확정 렌더링 비교 성공
+ 핵심 뷰포트 접근성 테스트 성공
= 프로덕션 배포 가능
```

장거리 스트로크 테스트에서는 Stage가 없을 때 성공처럼 종료될 수 있는 경로가 있고, 명시적 수치
임계값보다 스크린샷 기록 중심인 부분이 확인된다. 필요한 assertion:

- Stage가 없으면 테스트 실패
- 입력 포인트 수와 커밋 포인트 수가 허용 오차 내에서 일치
- 포인터 종료 후 미완료 스트로크가 0개
- 실시간 프리뷰와 커밋 이미지 픽셀 차이 임계값 이하
- 처리 시간 p95가 기준 이하
- 50ms 초과 long task 개수 제한
- 콘솔 오류·unhandled rejection 0개
- 메모리 증가가 일정 범위 안에서 회수됨

## 5. 이미 수정된 과거 고위험 회귀

과거에는 다중 레이어 타임라인, 타임랩스, 스토리보드 그리드, 세로 스크롤 미리보기, 연속성 검사, 문서
댓글, 리뷰·편집 잠금 7개 기능이 DOM에는 존재하지만 숨김·inert 상태 조합 때문에 모든 뷰포트에서 포인터
접근이 불가능했다. 2026년 8월 9일 수정되고 뷰포트별 도달성 회귀 테스트가 추가되었다.

구조적 교훈: 패널 표시 상태, DOM 마운트, CSS 표시, `aria-hidden`, `inert`, 포커스 가능 여부, 포인터
이벤트 가능 여부를 서로 다른 컴포넌트가 각각 결정하게 해서는 안 된다. 단일 Panel Host가 도달성 상태를
책임지도록 통합해야 한다.

## 6. 성능·아키텍처 분석

### 가장 큰 구조적 위험: 4만 줄 중심 컴포넌트

기능 하나 수정할 때 다른 패널 상태가 깨짐, 렌더링 경로 변경이 저장·실행 취소에 영향, 기능별 코드
스플리팅 곤란, 테스트 fixture 거대화, 병렬 개발 충돌, DOM 도달성·포커스·inert 회귀 재발,
브러시·3D·타임라인의 프레임 예산 상호 간섭.

권장 분리 경계:

```text
StudioShell
 ├─ DocumentCore
 ├─ CommandBus / OperationJournal
 ├─ InputRouter
 ├─ ViewportController
 ├─ CanvasRendererAdapter
 ├─ SelectionController
 ├─ LayerModel
 ├─ InspectorHost
 ├─ PanelHost
 ├─ AssetService
 ├─ SaveRecoveryService
 ├─ ExportOrchestrator
 ├─ ThreeDWorkspace
 └─ AnimationWorkspace
```

UI가 직접 문서를 수정하지 않고 모든 변경을 직렬화 가능한 Command 또는 Operation으로 보내야 한다.

```ts
type StudioOperation = {
  id: string;
  documentId: string;
  sequence: number;
  type: string;
  payload: unknown;
  inverse?: unknown;
  timestamp: number;
  origin: "local" | "remote" | "recovery";
};
```

이 모델이 만들어지면 실행 취소, 복구 저널, 협업, 자동 저장, 충돌 해결, 감사 로그를 같은 기반 위에서
처리할 수 있다.

### 기타 성능 개선점

1. 필터 다이얼로그와 SQLite 로딩 분리 — 필터 UI 즉시 표시 → 프리뷰 계산 → 사용자가 적용한 경우에만
   operation 기록 → 저장 모듈은 백그라운드 초기화.
2. VRM 자산 체계 개선 — 저·중·고 LOD, 모바일 전용 저용량 모델, Draco/Meshopt, KTX2/Basis, 필요한
   애니메이션만 로딩, 최근 사용 모델 캐시, 첫 프레임 리소스 우선, Worker 디코딩, GPU 메모리 예상량
   사전 표시.
3. 슬라이스 출력 고정 지연 제거 — 플랫폼 슬라이스마다 고정 250ms를 기다리는 방식이면 10개 출력에
   2.25초 이상의 인위적 지연. 고정 타이머 대신 렌더 완료·Blob 생성 완료 이벤트를 기다려야 한다.

## 7. UI/UX·디자인 고도화

### 7.1 기능 중심 메뉴에서 작업 중심 워크스페이스로

| 워크스페이스 | 기본 노출 |

| 스토리·콘티 | 대본, 장면, 스토리보드, 컷 배치, AI 초안 |
| 스케치·선화 | 브러시, 지우개, 벡터, 보정, 참조 이미지 |
| 채색 | 채우기, 색상, 팔레트, 마스크, 보정 |
| 말풍선·식자 | 말풍선, 텍스트, 폰트, 꼬리, 읽기 순서 |
| 3D 배경·포즈 | 캐릭터, 포즈, 카메라, 조명, 배경 |
| 애니메이션 | 타임라인, 셀, 어니언 스킨, 재생 |

워크스페이스를 바꾸더라도 문서 상태는 같아야 하며, 패널 배치와 추천 도구만 바뀌어야 한다.

### 7.2 Simple Mode는 패널 숨기기가 아니라 별도 흐름

```text
작품 크기 선택 → 컷 템플릿 선택 → 스케치 → 선화 → 채색 → 말풍선 → 플랫폼 출력
```

고급 설정은 각 단계의 "더 보기" 안에 배치한다.

### 7.3 명령 팔레트 (⌘K / Ctrl+K)

검색 대상: 기능명, 동의어, 현재 선택에서 실행 가능한 명령, 최근 실행, 패널 열기, 소재 검색, 단축키,
도움말, 현재 실행 불가능한 이유.

### 7.4 설정의 단일 정본

각 설정에는 한 개의 정본 UI를 두고 다른 위치에서는 정본으로 이동하는 딥링크, 현재 값 표시, 자주 쓰는
1~2개 빠른 조작 중 하나만 제공한다.

### 7.5 비활성 상태를 설명하기

```text
톤 커브
현재 사용할 수 없음
래스터 레이어 한 개 이상을 선택하세요.
[적합한 레이어 보기]
```

3D 기능도 WebGL·GPU·모델 포맷·메모리 조건을 구체적으로 알려야 한다.

### 7.6 상시 저장 상태 센터

상단 지속 표시: 로컬 저장됨 / 클라우드 동기화됨 / N개 작업 업로드 대기 / 오프라인 / 복구 지점 시각.
상세 화면: 마지막 성공 저장, 마지막 서버 동기화, 로컬 문서 해시, 서버 버전, 대기 작업 수, 실패 원인,
재시도, 로컬 사본 내보내기, 진단 정보 복사.

### 7.7 오류 UX 표준화

모든 오류: 무엇이 실패했는가 / 작업 데이터는 안전한가 / 자동 재시도 가능한가 / 사용자가 지금 할 수
있는 행동 / 기술 진단 정보. 공통 버튼: 다시 시도, 중단된 지점부터 계속, 안전 모드로 열기, 대체 렌더러
사용, 로컬 사본 저장, 진단 정보 복사, 문제 신고.

### 7.8 모바일·태블릿

추가 항목: OS 네이티브 팜 리젹션, 스타일러스·손가락 역할 분리, 두 손가락 undo와 캔버스 제스처 충돌
방지, 소프트 키보드가 속성 필드를 가리지 않게, Safe Area, 화면 회전 중 활성 스트로크 취소, 앱
백그라운드 전환 직전 복구 저널 flush, 120Hz 필터·애니메이션 안정성, 저메모리 경고와 고해상도 자산
자동 다운샘플링.

### 7.9 접근성 (CI 편입 권장)

키보드만으로 모든 패널 접근, 다이얼로그 포커스 트랩, 닫은 뒤 트리거로 포커스 복귀, 텍스트 입력 중
전역 단축키 미실행, 스크린리더용 레이어·도구 이름, 색상만으로 상태 구분 금지, 고대비 모드, 애니메이션
감소 모드, Canvas 조작의 대체 설명과 현재 선택 상태 제공.

### 7.10 브랜드 일관성

서비스/제품명 ToonStudio, 플랫폼·회사 브랜드 ToonSpectrum으로 통일. 대상: 브라우저 제목·파비콘,

## 10. 추천 기능 고도화 상세

### 10.1 브러시 엔진

우선 추가: 손떨림 보정 스트로크 프리뷰, 큰 브러시 속도·품질 모드, 실시간과 확정 결과 자동 비교, 펜
압력·속도·기울기 곡선 편집, 수채 경계 스타일, 색 혼합 품질 등급, 브러시별 성능 예상 표시, 고부하
브러시 자동 품질 조절.

스트로크별 익명 계측 메타데이터: pointer type, DPR, canvas zoom, brush size, stabilization, input
point count, render point count, input-to-preview latency, preview-to-commit latency, dropped frames,
memory delta.

### 10.2 Smart Shape

```text
자유롭게 선을 그림 → 끝에서 350~500ms 유지 → 직선/곡선/타원/사각형/말풍선 후보 표시
→ 펜을 떼면 확정 → 제어점으로 수정
```

옵션: 최근 스트로크 보정, 원본 스트로크로 되돌리기, 제어점 간소화, 15°·30°·45° 스냅, 대칭, 반복
도형, 말풍선과 컷선 특화 인식.

### 10.3 색 관리

문서 생성 시 ICC 프로필(sRGB, Display P3, Adobe RGB), CMYK soft proof, 프로필 포함 출력, 프로필
없는 이미지 경고, Lab 슬라이더, 화면과 출력 색 차이 경고, 브라우저별 색 관리 검증, 프로젝트 단위
색상 정책 잠금.

### 10.4 비파괴 효과

Glow, Drop Shadow, Relief 등을 레이어 효과 스택으로 설계. 각 효과는 실시간 미리보기, 켜기·끄기, 순서
변경, 프리셋, 마스크, 불투명도, 블렌딩 모드, 확대율별 결과 일관성, 내보내기 결과 일치 지원.

### 10.5 3D 직접 페인팅 (단계적)

1. Base Color 단일 텍스처, 원형 브러시, 실행 취소, 텍스처 출력
2. UV seam 보정, 텍스처 레이어, 지우개·마스크, 다중 소재 슬롯
3. Normal·Roughness·Metallic, 대칭 페인팅, 투영·스텐실, 2D UV 편집기, GLB·VRM 왕복
4. 3D 오브젝트 간 복사, 캐릭터 파츠별 텍스처, 팀 소재 서버, 저해상도 프록시와 최종 고해상도 베이크

### 10.6 소재 탐색

```text
빠른 접근: 최근 사용 / 자주 사용 / 즐겨찾기 / 이 프로젝트에서 사용 / 상단 고정
모든 소재: 유형 / 태그 / 카탈로그 / 라이선스 / 제작자 / 로컬·클라우드
```

소재 카드 최소 항목: 미리보기, 이름, 종류, 해상도 또는 폴리곤 수, 라이선스, 출처, 다운로드 크기, 최근
사용, 현재 문서에서 사용 중인지, AI 생성 여부.

### 10.7 웹툰 특화 기능

플랫폼별 세로 길이·용량 자동 분할, 컷 간 시선 흐름 분석, 말풍선 읽기 순서 검증, 말풍선과 얼굴 겹침
검사, 모바일 화면 실제 크기 미리보기, 앞뒤 컷 캐릭터 복장·소품 연속성 검사, 현지화 문자열 교체, 번역
길이에 따른 말풍선 자동 재배치, 에피소드 템플릿, 작가·어시스턴트 역할별 작업 배정, 검수 완료 컷 잠금,
플랫폼별 썸네일·대표 이미지 자동 생성, 수정 전후 비교 PDF.

### 10.8 AI

추가 메타데이터: provider, model, model version, seed, generation time, cost, source assets, prompt
hash, region applied, user accepted/rejected, manual edits after generation.

원칙: AI 결과는 자동으로 원본을 덮어쓰지 않음, 적용 범위 명확 표시, 한 번에 실행 취소 가능,
생성·수정·사용자 승인 상태 구분, 라이선스와 출처 표시, 오프라인·비공개 처리 여부 명시, 서버 전송 전에

아키텍처가 뒤따라가야 하는 단계이며, 앞으로 2~3개월은 "작업물을 잃지 않고, 보이는 대로 저장되고,
필요한 기능을 쉽게 찾는 편집기"를 만드는 데 집중하는 것이 가장 높은 효과를 낸다.
