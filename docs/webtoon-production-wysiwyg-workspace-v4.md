# ToonSpectrum 웹툰 프로덕션 WYSIWYG 작업공간 v4

## 1. 목적

웹툰 프로젝트 관리에서 문서, 회차, 장면, 컷, 작업, 검수, 발주를 서로 떨어진 목록으로 다루지 않고 **현재 제작 문맥 안에서 직접 보고 수정**할 수 있도록 한다.

이번 구현은 다음 원칙을 따른다.

- 프로젝트 관리 기능은 작품 구조(`회차 → 장면 → 컷`)를 중심으로 배치한다.
- 저장은 승인·게시와 분리한다. 편집한 내용이 자동 승인되거나 자동 게시되지 않는다.
- 잠긴 정본은 덮어쓰지 않는다. 변경 시 새 초안 revision으로 분기한다.
- 역할 관점은 표시 우선순위만 바꾸며 정본 데이터 자체를 역할별로 복제하지 않는다.
- 검수 의견은 가능한 한 회차가 아니라 실제 컷 범위에 고정한다.
- 권리, 계약, 지급, 크레딧 상태는 제작 완료 상태와 별도로 유지한다.

## 2. 벤치마크에서 채택한 상호작용 패턴

특정 제품 UI를 복제하지 않고 다음 공통 패턴을 ToonSpectrum 도메인에 맞게 재구성했다.

| 영역 | 참고 패턴 | ToonSpectrum 적용 |
| --- | --- | --- |
| 페이지·회차 관리 | 페이지 관리자에서 썸네일 탐색, 재배열, 세로 작품 확인 | 회차 레일, 장면 보드, 세로 독자뷰, 구조 아웃라인 |
| 협업 편집 | 페이지 단위 잠금, 읽기 전용 전환, 동기화 이력 | 정본 revision 잠금, 새 초안 분기, 역할·권한별 편집 비활성화 |
| 프로덕션 추적 | 작업·노트·버전·게시본을 같은 문맥에서 연결 | 컷 인스펙터에 태스크·에셋·위험·revision 연결 |
| 시각 검수 | 원본/제출본 비교, 주석, 상세 정보, 단축키 | 세로/나란히/오버레이 비교, 컷 고정 질문, lane별 결정 |
| 스토리보드 | 보드·아웃라인·타임라인 간 전환 | 장면 보드, 구조 보기, 일정 타임라인·워크로드 |

## 3. 정보 구조

### 프로젝트 셸

프로젝트 공통 헤더와 좌측 메뉴를 유지한다.

1. 개요
2. 기획
3. 회차
4. 제작
5. 일정
6. 인수인계
7. 검수
8. 발주
9. 권리·정산
10. 협업 설정

`Ctrl/Cmd + K` 명령 팔레트에서 화면, 회차, 주요 작업을 통합 검색한다.

### 기획 작업공간

- **회차 레일**: 회차 상태, 설계 장면 수, 설계 컷 수, 목표 대비 진행률
- **중앙 캔버스**
  - 장면 보드: 장면별 컷 썸네일을 가로로 구성
  - 세로 독자뷰: 실제 웹툰 소비 방식에 가까운 세로 리듬 확인
  - 구조 보기: 장면·컷 계층과 핵심 메타데이터를 밀도 있게 확인
- **인스펙터**: 선택 컷의 프레이밍, 카메라, 레이어, 공수, 복잡도, 연결 에셋, 작업, 위험

### 일정 작업공간

- 타임라인: 14일 단위 마감, 예상 공수 기반 작업 막대, 의존 관계, 기한 위험
- 워크로드: 역할 배정별 작업 수, 예상 시간, 과부하와 주의 작업
- 작업 상태와 마감일은 `upsert-task` 명령으로 저장한다.

### 검수 작업공간

- 회차와 제출 revision 선택
- 세로 원고, 나란히 비교, 오버레이 비교
- 컷별 열린 질문·변경 요청 표시
- 현재 역할이 검수 정책상 eligible한 lane에만 승인·수정 요청 제공
- 컷 위치 질문은 활성 Story→Art handoff에 `ClarificationThread`로 기록
- 기존 정식 검수 정책 및 quorum 요약을 작업공간 아래에 유지

### 공동 Episode Room

기존 3열 문맥을 유지한다.

- 왼쪽: Story Intent와 보존·자율 경계
- 가운데: 실제 기획 데이터와 연결된 시각 컷 작업공간 및 공동 검수
- 오른쪽: 질문·결정, 영향·비용

정적 미리보기 대신 프로젝트 기획과 같은 컷 컴포저를 사용하므로 Episode Room에서 저장한 변경이 프로젝트 기획 데이터에 반영된다.

## 4. revision 규칙

### 최신본 투영

화면은 다음 식별자로 최신 revision만 투영한다.

- 회차: `episodeId`
- 장면: `sceneId`
- 컷: `cutId`

이전 revision은 원장에 보존되지만 현재 캔버스에 중복 표시하지 않는다.

### 초안·검토 상태

`draft`, `review` 상태는 같은 문서 ID로 revision을 1 증가시킨다.

### 승인·잠금 상태

`approved`, `locked` 상태는 기존 ID를 변경하지 않는다. 편집하면 다음 규칙으로 새 초안을 만든다.

- revision을 1 증가
- revision suffix가 있는 경우 새 suffix로 교체
- 상태를 `draft`로 전환
- 승인자 목록을 비움
- 생성 시각 갱신

따라서 승인 정본은 조용히 변조되지 않는다.

## 5. 권한·안전 규칙

- `access.edit === false`이면 모든 신규 생성·인라인 편집·일정 변경·검수 결정·질문 추가를 비활성화한다.
- 역할 관점을 바꿔도 해당 사용자의 서버 권한은 증가하지 않는다.
- 검수 기한이 지나도 자동 승인하지 않는다.
- `approve`, `request-changes`, `veto`는 검수 정책에 정의된 assignment만 기록할 수 있다.
- 외부 지급 기록은 증빙 검증 전까지 완료로 표시하지 않는다.
- 미리보기는 실제 렌더 에셋이 연결되기 전에는 계획/제출 메타데이터 기반 표현임을 명시한다.

## 6. 접근성

- 모든 보기 전환은 `aria-pressed`를 제공한다.
- 회차·장면·컷 선택은 버튼과 키보드 포커스로 동작한다.
- 인라인 편집 필드는 목적이 드러나는 접근 가능한 이름을 가진다.
- 명령 팔레트는 dialog/listbox 패턴과 위·아래·Enter·Escape 키를 지원한다.
- 상태를 색상만으로 전달하지 않고 텍스트 라벨을 함께 표시한다.
- 모바일에서는 회차 레일을 가로 스크롤로, 주요 패널을 세로 스택으로 전환한다.

## 7. 수용 기준

- [x] 잠긴 회차 제목을 편집하면 정본을 덮어쓰지 않고 새 초안 revision이 생성된다.
- [x] 과거 회차·장면·컷 revision이 현재 화면에 중복 표시되지 않는다.
- [x] 회차, 장면, 컷을 시각 작업공간에서 생성할 수 있다.
- [x] Episode Room과 프로젝트 기획이 같은 컷 데이터를 사용한다.
- [x] 작업 상태·마감일 변경이 실제 프로덕션 명령으로 저장된다.
- [x] 역할별 workload와 기한 위험을 확인할 수 있다.
- [x] 컷 위치에 질문을 추가할 수 있다.
- [x] eligible한 assignment만 검수 결정을 기록할 수 있다.
- [x] 읽기 전용 사용자의 편집 컨트롤은 비활성화된다.
- [x] `Ctrl/Cmd + K`로 화면·회차·작업을 탐색할 수 있다.
- [x] TypeScript strict 검사와 변경 파일 ESLint를 통과한다.

## 8. 후속 확장 경계

이번 구현은 서버 정본 모델과 명령 계약까지 연결한다. 실제 PSD/이미지 픽셀 diff, 드래그 재정렬 저장, 실시간 다중 사용자 presence, 캔버스 좌표 기반 핀 주석은 별도 렌더·동기화 계층이 필요하다. 해당 기능을 추가할 때도 현재 `ScopeRef`, revision, handoff, review policy를 우회하지 않는다.
