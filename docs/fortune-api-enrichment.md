# 운세 외부 데이터 보강 운영 가이드

검토 기준: 2026-09-20. 기존 29개 관측소 경험과 캐릭터 POST API를 보존합니다. 외부 제공자는 기본 비활성입니다. 이 변경은 키 발급·운영 설정·운영 배포를 수행하지 않습니다.

## 구현 범위

| 영역 | 동작 |
| --- | --- |
| 기본 계산 | 브라우저·서버 공통 로컬 엔진. 외부 데이터나 운영자 AI 키 없이 동작 |
| 타로 | 기본 메이저 22장 보존, 선택형 전체 78장, 자체 한국어 창작 질문, 소유한 벡터 모티프 사용 |
| 재현 | 기준 날짜·덱·선택 번호를 고정. 전체 덱은 중복 없는 Fisher–Yates 추출 |
| 만세력 보강 | 선택한 공용 월만 서버에 전송. KASI 응답의 음력 날짜·윤달·요일 대조 결과를 별도 표시 |
| 별자리 | 일간·주간·월간 자체 한국어 콘텐츠. 권리 승인 후 영어 원문만 별도 제공 가능 |
| 저장·공유 | 외부 원문은 로컬 해석 저장/공유에 섞지 않음. 생년월일·시간·꿈·상대 정보는 외부 제공자에 보내지 않음 |

KASI 대조 일치는 역법 항목에 한정됩니다. 운세의 예측력을 인증하거나 달력의 월건을 사주의 월주로 치환하지 않습니다. 불일치는 날짜별로 표시하고 기존 달력을 덮어쓰지 않습니다. 현재 24절기 시각은 기존 로컬 계산을 유지하며, 특일 API·공휴일 데이터는 이번 변경에 포함하지 않습니다.

## API

`GET /api/fortune/capabilities`는 설정상 사용 가능 여부·차단 사유를 제공합니다. 이는 제공자 실시간 가용성 보증이 아닙니다.

`GET /api/fortune/calendar?month=2024-02`는 공용 월의 대조 결과를 반환합니다. `checks[].fields`는 **불일치 항목**입니다. 전 일자·중복·페이지·업무 오류 코드·XML 구조를 검사합니다.

`GET /api/fortune/horoscope?sign=aries&period=daily&date=2026-09-20`는 기본 콘텐츠 또는 승인된 추가 원문을 반환합니다. 기간은 `daily`, `weekly`, `monthly`입니다. 알 수 없는 파라미터·개인정보 필드·잘못된 실제 날짜는 400으로 거절합니다.

모든 GET은 HTTP `no-store`이며 읽기 동작에 활동 보상을 지급하지 않습니다. 상태는 `local`, `external`, `external-cache`, `local-fallback`으로 구분합니다.

## 활성화 조건

환경변수 예시는 `.env.fortune.example`에 있습니다. 자동 적용되지 않으며 운영 설정 변경에는 별도 승인이 필요합니다.

KASI는 공공데이터포털에서 음양력 정보 활용 승인을 받은 **디코딩 키**를 서버에 등록해야 합니다. `FORTUNE_KASI_ENABLED=true`와 기존 Upstash coordination 설정이 모두 필요합니다. 키가 없거나 분산 예산을 확인할 수 없으면 외부 호출을 하지 않습니다.

별자리는 제공자의 상업적 표시·서버 캐시 권한과 실제 호출 한도를 확인하고 내부 승인 기록을 남긴 뒤에만 `FORTUNE_HOROSCOPE_ENABLED`, `FORTUNE_HOROSCOPE_DISPLAY_AND_CACHE_APPROVED`, `FORTUNE_HOROSCOPE_POLICY_REVISION`을 설정합니다. 무료라는 소개만으로 재배포 권한을 승인하지 않습니다. 번역·각색·공유 권한은 이 스위치에 포함되지 않으며 해당 기능을 구현하지 않았습니다.

영어 원문은 공식 문서의 `data.date`, `data.period`, `data.sign`, `data.horoscope`를 검사합니다. 표기 날짜가 요청 날짜와 일치하지 않거나 과거 날짜 요청이면 로컬 콘텐츠로 대체합니다. 공급자의 시간대와 주·월 경계가 불명확하므로 한국 표준시와 동일하다고 보증하지 않습니다. 다른 날짜 형식은 추측하지 않고 거절합니다.

## 비용·장애 경계

프로세스당 공용 캐시는 최대 72개, 동시 수집은 최대 16개이며 동일 키의 요청은 합칩니다. 공유 DB 스냅샷이나 스케줄러가 아닌 **요청 시 수집 + 인스턴스별 메모리 캐시**입니다. 재시작·다른 인스턴스에서는 재수집할 수 있습니다.

호출 예산과 장애 차단은 기존 Upstash coordination을 재사용합니다. 실제 HTTP 시도마다 고유 작업 ID를 사용하며 페이지별로 차감합니다. 기본 한도는 공급자별 UTC 하루 100회입니다. 실제 업체/계정의 한도와 리셋 시간, 같은 키를 쓰는 다른 시스템의 사용량을 별도 확인하고 보수적으로 설정해야 합니다. 공급자 API 비용 상한은 0이며 자동 유료 전환은 없습니다. 인프라 사용료까지 0원임을 의미하지는 않습니다.

연결 시간 제한, 최대 128KiB 응답, XML 선언/깊이/엔티티 제한, 고정 제공자 URL, 리다이렉트 거절, 스키마 검사를 적용합니다. KASI는 월 전체가 확인될 때만 결과를 채택하며 최대 4페이지를 시도합니다. 실패한 요청은 예산을 환불해 재호출하지 않습니다. 외부 문장은 다음 KST 자정을 넘겨 캐시하지 않습니다. 로컬 대체 결과 캐시는 60초입니다.

화면에서는 명시적인 확인 동작만 요청을 발생시킵니다. 취소·기간 전환·화면 종료 뒤 늦게 도착한 응답은 버리며, 기존 읽기의 원국·카드·공유 본문을 바꾸지 않습니다.

## 검증과 제한

단위/통합 검증: `pnpm exec vitest run packages/core/src/fortune apps/api/src/modules/fortune apps/web/src/domains/fortune`.
브라우저 검증: 로컬 Vite를 실행한 뒤 `FORTUNE_BASE_URL=http://127.0.0.1:5279 node e2e/fortune-enrichment-smoke.mjs` 및 기존 `e2e/fortune-observatory-smoke.mjs`를 실행합니다. 결과·스크린샷은 임시 폴더에만 기록합니다.

테스트의 KASI 응답은 합성 프로토콜 fixture이며 실제 발급 키를 사용한 역법 검증을 대신하지 않습니다. 실제 활성화 전 개발 계정으로 HTTP/XML 계약·사용 한도·키 인코딩·운영 네트워크를 확인해야 합니다. 외부 제공자의 성공/오류 응답이나 키가 든 URL을 운영 로그에 남기지 않습니다.

이번 변경에는 특일/공휴일 API, 공유 DB 스냅샷·정기 수집 작업, 외부 문장 번역, 유료 사주 API, 타 서비스 AI 호출, 스케치/팔레트 자동 적용, 채용·인력 매칭 점수 연계가 포함되지 않습니다. 기존 창작 미션과 명시적 스튜디오 이동은 유지합니다.
