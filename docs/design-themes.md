# 사이트·스튜디오 디자인 테마

## 사용 경로

설정 → 디자인 테마 또는 사이트 플로팅 팔레트 버튼에서 선택한다. 스튜디오는 상단 디자인 테마 버튼, 모바일 몰입 모드는 프로젝트 센터 → 디자인 테마에서 연다.

잉크(기본), 페이퍼, 그래파이트, 미드나이트, 세피아, 고대비의 여섯 팔레트와 시스템 설정 따르기를 지원한다. 사이트와 스튜디오 선택을 별도로 저장하며 스튜디오 기본값은 사이트와 동일이다. 기본값 복원은 현재 선택 범위에만 적용한다.

선택은 즉시 반영하고 현재 브라우저에 저장한다. 다른 탭에도 동기화하며 브라우저 저장소가 차단되면 세션 적용 안내를 표시한다. 서버 저장·계정 동기화·유료 API는 추가하지 않는다.

## 경계와 호환성

- UI의 의미 색상 토큰만 변경한다. 원고 데이터, 브러시 색상, 캔버스 렌더러 및 내보내기 경로는 수정하지 않는다.
- 기존 `data-theme=dark|light` 계약과 `toonspectrum-theme`의 `state.theme`/`version:0` envelope를 유지한다. 새 필드는 검증된 `preference`, `studioPreference`뿐이다.
- `data-design-theme`가 팔레트이고 `data-theme`는 밝기 모드다. 경로에 따라 문서 루트에 적용되어 body에 포털로 렌더되는 메뉴도 같은 색상을 상속한다.
- 초기 부트스트랩은 기존 CSP의 self-hosted script를 재사용한다. 시스템 변경·storage 이벤트 구독은 해제 가능하고 storage 이벤트를 다시 저장하지 않는다.
- 테마 모달은 앱 소유의 lazy host에서 열어 모바일 부모 메뉴가 사라져도 유지한다. Escape·포커스 트랩·닫은 후 호출 버튼으로 포커스 복귀는 Radix Dialog로 제공한다.
- 고대비 OS 설정을 존중한다. 글자/보조 글자/강조 글자 및 기본·호버 버튼의 불투명 토큰 조합을 4.5:1 이상으로 테스트한다. 모든 투명도 조합과 제품 화면의 WCAG 적합성을 보증하는 것은 아니다.

## 검증

`theme-presets.test.ts`는 첫 페인트와 런타임의 테마 결정 조합, 레거시 이관, 잘못된 입력, 대비를 검증한다. `theme.test.ts`는 저장 차단·탭 동기화·시스템 변경·범위 분리·구독 정리를 검증한다. `AppearanceSettings.test.tsx`는 선택·초기화·모달 포커스와 부모 메뉴 언마운트를 검증한다.

로컬 서버를 `127.0.0.1:5276`에서 실행한 뒤 `node scripts/verify-design-themes.mjs`를 실행한다. 다른 포트는 `THEME_VERIFY_URL`로 지정한다. 이 스크립트는 로컬 호스트만 허용하고 API와 외부 네트워크를 차단한다. Chromium으로 선택·새로고침·탭 동기화·OS 테마·SPA 화면 전환·모바일 진입·390/320px 레이아웃을 확인하고 `artifacts/design-themes/`에 결과를 남긴다.

브라우저 검증은 UI 범위다. API, 원격 소재와 일부 WASM 런타임을 사용할 수 없는 로컬 조건에서 문서 내보내기 품질이나 전체 제작 기능을 검증했다고 해석하지 않는다. 배포·운영 설정·의존성 추가·DB 변경은 포함하지 않는다.
