# ToonStudio 페이지 오거나이저 벤치마크 및 구현 기록

기준일: 2026-09-09

## 목표

기존 도킹 페이지 목록의 빠른 단일 작업과 드래그 정렬은 그대로 유지하면서, 장편 웹툰·스토리보드에서 수십~수백 페이지를 검색·비교·범위 선택·일괄 정리하는 전용 전체화면 오거나이저를 추가한다.

## 벤치마크에서 채택한 작업 개념

| 제품군 | 참고한 일반 작업 개념 | ToonStudio 구현 |
| --- | --- | --- |
| CLIP STUDIO PAINT EX Page Manager | 썸네일 기반 다중 페이지 관리, Ctrl/Shift 선택, 페이지 이동·복제 | 전체화면 반응형 썸네일 그리드, Cmd/Ctrl 개별 선택, 실제 Shift 연속 범위, 명시적 맨 위/위/아래/맨 아래 이동, 일괄 복제 |
| Toon Boom Storyboard Pro Thumbnails | 시간순 전체 조망, 키보드 탐색, 현재 패널 추적 | 방향키·Home·End·Page Up/Down 탐색, 현재 편집 페이지 최소 거리 자동 스크롤, 샷·검토 상태 상시 표시 |
| Adobe Express multi-page overview | 전체 페이지 보기에서 추가·재정렬·복제·삭제 집중 | 새 페이지와 선택 페이지 일괄 작업을 하나의 고정 툴바에 집중하고 구조화된 삭제 확인 재사용 |
| Figma/Slides 계열 오거나이저 | 검색, 선택 수 피드백, 명시적 대량 작업 | 번호·이름·메모·샷·검토·담당자·대사 통합 검색, 결과 수/선택 수 실시간 피드백, 결과 전체 선택 |

타사 명칭·화면·아이콘·에셋은 복제하지 않고 공개적으로 알려진 작업 개념만 ToonStudio의 문서 모델과 디자인 토큰으로 독자 구현했다.

## 구현 범위

### 검색과 필터

- `2페이지`, `page 2`, `p2`, `2장면`, `2컷` 번호 별칭
- 페이지 이름, 콘티 메모, 샷 타입, 카메라 앵글
- 검토 상태, 잠금, 담당자, 검토 메모
- 요소 타입·이름·텍스트·라벨·대체 텍스트·화자
- 전체 / 내용 있음 / 빈 페이지 / 메모·샷 태그 / 검토 정보 필터
- 페이지당 최대 500개 요소와 24,000자만 색인하는 비용 상한
- `useDeferredValue` 기반 입력 반응과 검색 계산 분리

### 선택과 탐색

- 클릭 단일 선택
- Cmd/Ctrl 클릭 개별 토글
- Shift 클릭 앵커~대상 실제 연속 범위
- Cmd/Ctrl+Shift 기존 선택에 범위 합치기
- Cmd/Ctrl+A 현재 결과 전체 선택
- Arrow/Home/End/Page Up/Page Down 키보드 이동과 Shift 확장
- 현재 편집 페이지 자동 추적, 필터로 숨겨졌을 때 복귀 안내

### 일괄 작업

- 선택 페이지 맨 위 / 한 칸 위 / 한 칸 아래 / 맨 아래 이동
- 문서 역순으로 안전하게 실행하는 일괄 복제
- 기존 구조화된 파괴 작업 승인 시스템을 재사용한 일괄 삭제
- 새 페이지 추가 및 선택 해제

### 성능·접근성

- 화면 밖 카드에 `content-visibility: auto`와 intrinsic-size 힌트
- 그리드 `listbox`/`option`, `aria-multiselectable`, `aria-selected`, `aria-keyshortcuts`
- 모든 주요 조작 40~44px 이상 터치 영역
- Esc 닫기, 스크림 닫기, 검색 자동 포커스, 현재 카드 최소 거리 스크롤
- 기존 페이지 목록·SQLite/OPFS 취향 저장·분리 패널·모바일 시트를 변경하지 않는 장식자 구조

## 아키텍처

`StudioPageListPaneBase.tsx`는 기존 페이지 목록 구현을 그대로 보존한다. `StudioPageListPane.tsx`는 기존 export 계약을 유지하는 장식자이며, 기존 일괄 작업 툴바에 오거나이저 진입 버튼을 포털로 추가한다. 전체화면 도구는 `StudioPageOrganizerDialog.tsx`, 순수 검색·선택·키보드 규칙은 `studio-page-organizer.ts`가 담당한다.

이 구조는 거대한 편집기 호스트나 페이지 저장 모델을 변경하지 않으므로 기존 문서 직렬화, Undo/Redo, 협업 잠금, 마스터 페이지, 모바일 시트와의 회귀 범위를 최소화한다.

## 검증 항목

- 순수 검색/필터/범위 선택/키보드 탐색 단위 테스트
- TypeScript/TSX 구문 진단
- 기존 페이지 목록의 공개 props/handler export 계약 유지
- 기존 페이지 목록 소스 blob을 그대로 Base 모듈로 보존
- Git diff whitespace 검사

전체 저장소 CI는 Pull Request의 보호 규칙 `core`에서 최종 판정한다.
