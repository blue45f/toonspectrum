# ToonSpectrum Studio 외부 구현·소재·모델 재사용 정책

- 시행일: 2026-09-02
- 대상: 소스코드, 브러시, 2D/3D 소재, 모델 가중치, UI 에셋, 상표 자산, 라이선스 문구
- 기본 경로: 증빙이 있으면 허용 범위 안에서 정확히 재사용하고, 증빙이 없거나 범위가 불명확하면 기능·알고리즘·작업 흐름을 분석해 독자 구현한다.

## 1. 권한 해석

사용자가 재사용을 허용했다는 지시는 사용자가 직접 소유하거나 적법하게 재허가할 수 있는 권리에 대해서는 작업 승인을 의미한다. 다른 회사·작가·오픈소스 프로젝트의 권리까지 자동으로 이전되는 것으로 보지는 않는다.

정확한 복사·번들·재배포를 하려면 항목별로 다음 중 하나가 확인되어야 한다.

1. 상업 이용·수정·재배포·번들을 허용하는 공개 라이선스
2. 해당 권리자가 제공한 서면 허가
3. 퍼블릭 도메인 또는 동등한 자유 이용 근거
4. 사용자가 저작권·상표권·배포권을 직접 보유했다는 추적 가능한 근거

비공개 계약서는 저장소에 원문을 올리지 않아도 된다. 원문을 보관한 별도 기록의 SHA-256만 `private-record:sha256:<digest>` 형식으로 등록할 수 있다.

## 2. 두 가지 구현 모드

### 2.1 증빙 기반 정확 재사용

`docs/third-party/studio-reuse-registry.json`에 승인 항목을 먼저 등록한다.

필수 정보:

- 원본 URL과 고정 버전·커밋·릴리스
- 원본 SHA-256
- 라이선스 또는 허가 식별자와 근거 주소
- 상업 이용·수정·재배포·번들 등 허용 범위
- 실제 반영 경로
- 고지 의무와 NOTICE 위치
- 검토일

CI 검증을 통과한 항목만 vendoring 또는 runtime download 경로에 사용할 수 있다.

### 2.2 분석 후 독자 구현

정확 재사용 권한이 확인되지 않으면 다음 정보만 추출한다.

- 해결하는 사용자 문제
- 입력과 출력
- 주요 작업 단계
- 도구 간 전환과 오류 복구 방식
- 성능·접근성·저장·Undo/Redo 기대치
- 공개 문서로 확인 가능한 알고리즘 원리와 표준

그 뒤 ToonSpectrum의 문서 모델, UI 체계, 렌더러, 명령 시스템에 맞춰 새 코드와 새 자산으로 구현한다. 이름·레이아웃·아이콘·문구를 그대로 복제하지 않고 기능 결과와 사용성을 흡수한다.

## 3. 종류별 규칙

### 3.1 소스코드

- immutable release 또는 commit SHA를 고정한다.
- SPDX 라이선스와 의존성 전파 조건을 검토한다.
- 저작권 고지·NOTICE·변경 고지를 유지한다.
- 저장소 전체 라이선스와 충돌하는 강한 copyleft 코드는 별도 프로세스·서비스·WASM 경계 등 합법적인 분리 구조가 명확할 때만 사용한다.
- 비공개·유출·역공학 산출물은 사용하지 않는다.

### 3.2 브러시·2D 소재·3D 소재

- 앱 번들 재배포와 상업 결과물 제작이 모두 허용되는지 확인한다.
- 단순 구매권과 재배포권을 구분한다.
- 작가명, 출처, 버전, 원본 해시, 수정 내역을 provenance에 남긴다.
- 재배포가 금지된 소재는 사용자의 로컬 import 경로만 제공하고 ToonSpectrum 번들에는 넣지 않는다.

### 3.3 모델 가중치

- 가중치 자체의 재배포, 상업 이용, 파생 가중치, 생성 결과물 이용 조건을 각각 확인한다.
- 모델 카드와 라이선스 버전을 고정하고 파일 해시를 기록한다.
- 제한된 가중치는 사용자가 직접 공급하는 BYOM 또는 외부 provider adapter로만 연결한다.
- 학습 데이터의 적법성이나 상업 안전성을 확인할 수 없으면 보증 문구를 표시하지 않는다.

### 3.4 상표·로고

- 제품 비교를 위한 명목적 언급은 출처 표시와 함께 사용할 수 있다.
- 공식 로고, 브랜드 색·잠금형 로고 조합, 제휴 배지는 명시적 brand-use 권한이 있을 때만 번들한다.
- 실제 제휴·공식 인증이 없는 상태에서 혼동을 일으키는 표현을 사용하지 않는다.

### 3.5 라이선스 문구

- 법적 고지에 필요한 원문은 요구되는 범위에서 그대로 보존한다.
- 경쟁사의 이용약관·마케팅 문구를 제품 카피로 전용하지 않는다.
- 생성된 `THIRD_PARTY_NOTICES`와 개별 NOTICE가 빌드 결과에 포함되는지 검사한다.

### 3.6 픽셀 동일 UI

- 디자인 시스템이나 화면 자체에 대한 사용권이 확인되면 승인된 범위에서 에셋·컴포넌트를 재사용할 수 있다.
- 권한 증빙이 없으면 정보 구조, 작업 흐름, 단축키 기대치, 오류 복구 방식만 분석하고 ToonSpectrum 시각 언어로 재설계한다.
- 사용자 혼동을 만드는 상표·로고·제품명·고유 아이콘 조합은 피한다.

## 4. 등록 항목별 필수 권리

| 종류 | vendored 정확 재사용에 필요한 권리 |
| --- | --- |
| 소스코드 | commercial-use, modify, redistribute, bundle |
| 브러시 | commercial-use, modify, redistribute, bundle |
| 3D 에셋 | commercial-use, modify, redistribute, bundle |
| UI 에셋 | commercial-use, modify, redistribute, bundle |
| 모델 가중치 | commercial-use, redistribute, bundle, model-output-use |
| 상표 자산 | commercial-use, redistribute, bundle, brand-use |
| 라이선스 문구 | redistribute, bundle |

runtime download는 ToonSpectrum이 원본 파일을 직접 재배포하지 않는 구조이므로 번들 권한 요구가 달라질 수 있다. 그래도 상업 이용과 해당 기능 실행에 필요한 권리는 반드시 확인한다.

## 5. CI 집행

다음 검증을 병합 조건으로 사용한다.

```text
node --test scripts/validate-studio-third-party-reuse.test.mjs
node scripts/validate-studio-third-party-reuse.mjs
pnpm run audit:licenses
```

검증기는 다음을 차단한다.

- 출처·버전·해시가 없는 항목
- 일반 HTTP 또는 변경 가능한 원본 참조
- 명시되지 않은 사용 권리
- 모델 출력 이용권이 없는 가중치
- brand-use 권한이 없는 상표 자산
- 저장소 밖 경로나 중복 destination 소유
- 고지 위치가 없는 attribution-required 항목

## 6. 경쟁 기능 흡수 절차

```text
공식 기능·릴리스 확인
→ 동일 기능의 사용자 가치와 작업 흐름 분석
→ 공개 라이선스·권리자 허가 확인
→ 증빙 있으면 reuse registry 등록 후 정확 재사용
→ 증빙 없으면 clean-room 성격의 독자 구현
→ Studio UI·문서 모델·저장·Undo/Redo 연결
→ 성능·브라우저·접근성 검증
→ PR·자동 병합·배포
```

## 7. 완료 판정

외부 구현을 가져왔다는 사실만으로 기능 완료로 보지 않는다. 실제 Studio 진입점, 저장·복원, Undo/Redo, 오류 처리, 성능, 접근성, 배포 검증이 모두 연결되어야 한다.
