# Virtual Studio server door and Core session lease

Status: current server contract. This is a door and verified Core session lease, **not a conversation grant**. Private acoustic zones remain closed in the client policy until a separate consent grant and media adapter are implemented and verified. The API does not open microphones, add Huddle members, prove participant position, or authorize audio/video/screen sharing.

## Authority and API

All routes require the existing verified cookie session and use private/no-store responses under `/studio-project-graph/works/:workId/acoustic`. The normal cookie CSRF boundary remains in force. A caller-supplied actor, Cloudflare room ticket, public identity claim, generic seat lease, local world hash or display name cannot establish this authority.

- `GET /zones/:zoneId/door` checks current work view permission and the verified current world publication. It returns the published world pin, authored zone/door, current door epoch (null before initialization), open state and whether the requesting actor is explicitly allowed. Only current owner/admin managers receive the allowlist.
- `POST /door`, with `Idempotency-Key`, accepts `{ world: { worldId, revisionId, contentHash }, zoneId, expectedDoorEpoch, open, allowedUserIds }`. Only current work owners/admins may publish door membership. All allowed actors must be active work members or the active owner. A manager is not implicitly admitted. The zone must have exactly one explicitly authored door; ambiguous shared door identifiers fail closed. A change always creates a fresh epoch and atomically deletes that zone's old session leases. Membership publication is separate from each participant's future media consent.
- `POST /sessions/open`, with `Idempotency-Key`, accepts the same exact world pin plus `{ zoneId, doorEpoch, connectionId, clientInstanceId, expectedSessionEpoch }`. Each actor opens only their own authenticated, actually joined Core participant session. The initial expected epoch is null; replacement requires the observed current epoch. At most 24 active session leases exist per work, separately from generic seats; this is not a 24-member media conversation. The future conversation grant must limit exact membership to 2–4.
- `POST /sessions/read` accepts `{ sessionEpoch }` and validates without extending its lifetime. `POST /sessions/renew` also requires `expectedLeaseRevision`, and succeeds once for that observed lease revision. `POST /sessions/close` removes only the caller's exact epoch, so delayed cleanup cannot delete a replacement connection. Cleanup remains available to the actor after their work membership is revoked.

Session replies are explicitly marked `kind: "acoustic-session-lease-only"` and contain the exact world/zone/door epoch, session epoch, monotonic lease revision, database expiry and server-verified Core binding `{ connectionId, clientInstanceId, joinedAt }`. They contain no conversation ID or media grant. Closed or revoked session/membership authority returns 403; stale epoch/CAS or capacity returns 409; missing/corrupt authority evidence returns 422; unavailable or changed Core binding returns 503.

## Existing persistence and reserved namespace

No new table, migration, provider or event-log authority is introduced. Door changes append an immutable checkpoint, actual published-world parent, dedicated `studio.world.acoustic-door` operation and exact mutation receipt on the existing reserved world artifact. Door reads select the latest operation for the exact current published revision and zone before validating the receipt, actor, device, command, scope, hashes, sequence, parent and revision binding. Missing latest evidence fails closed rather than reopening an older door. Generic graph creation, commit and restore cannot write the server-owned artifact namespace.

Session descriptors use server-only receipts on that same reserved artifact. Ephemeral rows use the explicit reserved resource prefix `studio-acoustic:` in the existing live-lock table. The row binds actual socket ownership, epoch and expiry to its exact receipt, actor, auth session version, world revision and work. Display names contain no authority JSON. Generic socket request parsers and the generic repository reject acquiring, renewing, rolling back or individually releasing this namespace. Generic snapshots and event fanout hide it. Existing socket-disconnect and expiry cleanup still delete these rows and advance the work clock.

The database transaction takes the work `FOR NO KEY UPDATE` lock, then the existing work live-lock advisory lock. Membership changes use the conflicting work lock; the subsequent fresh ACL query observes revocation that won while waiting. `NO KEY UPDATE` still permits the foreign-key key-share held by an existing generic lease writer, avoiding the work-lock/advisory-lock inversion. No gateway/adapter network await occurs while either database lock is held.

## Actual Core binding and races

An internal, bounded, one-shot Socket.IO server-side RPC runs on the node owning the actual socket. It checks the socket-private authenticated principal/version, forces current work authorization, and resolves the actual joined participant and joined-at epoch. Public socket metadata and Cloudflare Durable Object room admission are insufficient. A detached gateway, malformed/ambiguous reply, different connection/client, timeout or unavailable owner fails closed. There is no second mutation attempt on request failure.

Open verifies Core before its DB commit and again after it; renewal checks the same binding before and after the CAS update. A failed post-check removes only the epoch just issued. A final database read catches door/world/ACL changes that happened while the post-check was pending. The external check has a 2-second result deadline and does not keep a work database lock open. An adapter's underlying read may finish later; its result is ignored.

No atomic transaction spans Socket.IO and PostgreSQL. A disconnect occurring after the final Core check can leave a DB row until existing connection cleanup or its remaining **at most 15-second** database lease expiry. Current/read/renew recheck actual Core ownership, and a reconnect must use a new session epoch. This residual window is explicitly not media authorization. Door close performs atomic DB invalidation; immediate browser/Huddle track cleanup remains work for the consent/media adapter slice and is not claimed here. World publication changes similarly make old leases unusable on every read/renew, even before physical expiry cleanup removes their rows.

## Retry and verification

Door retry uses the original key and identical normalized input; replay returns the original result without reopening a later closed door. Session-open replay requires the same live epoch, exact current binding, world, door and session version and never extends expiry. Different input with the same key conflicts. An expired/revoked old open cannot resurrect a lease. Ambiguous renewal is reconciled with the read endpoint; repeating its old observed revision fails rather than applying another extension.

The existing required PostgreSQL world-authority suite covers real ACL/CAS, door close and session deletion, expiry/reconnect fencing, session-version changes, current publication changes, missing door/session receipts, a revoked member waiting on the work lock, the 24-session bound independently from seats, and the live-lock FK/advisory race. It also tests post-commit Core loss and concurrent door close before response. Unit tests exercise the real Core binding adapter's local/remote ownership, timeout/teardown and socket-private principal checks; HTTP error/credential boundaries, reserved public protocol rejection and actual Nest module dependency injection are included in required static targets. Browser private-room/media acceptance is deliberately not claimed by these server tests.
