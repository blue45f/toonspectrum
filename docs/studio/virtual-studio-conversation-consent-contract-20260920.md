# Virtual Studio server conversation consent

Status: current server consent contract over verified Core sessions. The private-room browser/media adapter is still separate work. These routes do not start microphones, navigate peers, route media, prove avatar coordinates or enable private Huddle UI. Cloudflare room tickets and client world hashes remain insufficient authority.

## Exact roster and self acceptance

The existing cookie/session/CSRF boundary protects `/studio-project-graph/works/:workId/acoustic/conversations`. Every proposed participant must have a live server-issued Core acoustic session lease for the same current published world revision/hash, zone and door epoch. The roster contains 2–4 distinct actors and exact session epochs. Actor IDs and auth session versions are resolved exclusively from server descriptors, never from client input. The actual owning Gateway rechecks its private authenticated socket and joined participant before and after admission, outside database locks.

- `POST /propose` with `Idempotency-Key` accepts `{ conversationId, selfSessionEpoch, memberSessionEpochs }`. It counts only the proposer as accepted. The other fixed members must each explicitly accept using their own cookie principal and their own session epoch. Proposal IDs cannot be reused after cancellation or expiry. At most 24 outstanding conversations exist per work, independently of the 24 participant-session bound.
- `POST /change` with `Idempotency-Key` accepts `{ conversationId, selfSessionEpoch, expectedRevisionId, action }`, where action is `accept`, `decline`, `cancel`, `leave` or `block`. Block additionally requires one other fixed `targetSessionEpoch`. An actor cannot accept for another member. A pending proposal becomes active only when every exact member has accepted. Concurrent changes use consent-revision CAS; a conflict requires read/reconciliation and an explicit new attempt. A session can belong to at most one active conversation. Changing membership requires a new conversation ID and fresh acceptance.
- `POST /read` accepts `{ conversationId, selfSessionEpoch }`. It checks the actor, current work access, stored proof, every participant's live session/version/membership/door/world, and actual Core bindings. An invalid or expired scope is returned as revoked and its terminal tombstone is recorded once; this maintenance is never a new acceptance or renewed lease.
- `POST /renew` accepts `{ conversationId, selfSessionEpoch, expectedRevisionId, expectedLeaseRevision }`. This is ephemeral compare-and-swap. It changes only the existing conversation observation row, bounded by the minimum expiry of all current participant leases. It does not extend any participant's own lease or alter anyone's consent. A repeated observed revision is stale; reconcile an uncertain result with `/read`, without an automatic second POST.

Replies are `{ conversation, replayed }`. The conversation snapshot has one identical `conversationId`, immutable consent `revisionId`, fixed roster of `{ sessionEpoch, binding, accepted }`, exact world/zone/door, status, reason and expiry for all members. Private actor IDs, session versions and authority proofs are omitted. `leaseRevision` is the current live observation's monotonic CAS value, or null after revocation. `revisionId` changes only for consent/state changes; repeated renewals never append graph revisions, operations or mutation receipts. `expiresAt` for an active conversation never exceeds any verified current participant lease, including when a participant's own shorter cookie expiry shortens that lease.

## Revocation and retry

Decline, cancel and leave revoke the whole fixed scope. A peer block terminates the conversation and binds the blocker's exact visit/session epoch to the target actor established by the original verified server roster. The client submits only the original target epoch, never an actor ID. A target reconnect or second tab cannot bypass the block while the blocker's visit remains live. Later proposals and pending acceptance are denied in either direction. Only a new blocker session epoch starts a new visit without that block; all conversations still require new explicit consent. The private actor binding is never returned in snapshots or events. This slice does not add a persistent account block/unblock policy.

Expired invitation/observation, lost participant lease, auth-version revocation, changed membership invitation/version, reconnect, door epoch change, current world publication change or Core binding failure makes the scope unusable. Membership is bound to the existing server invitation ID, role/status and full database update timestamp so removal/re-addition cannot restore old consent. Revoked state is terminal, and old accept/replay/renew cannot revive it. The same mutation key with normalized identical input reconciles current state without another consent write; different input conflicts.

All consent operations use the existing work/advisory lock and immutable graph revision/operation/receipt on the reserved world artifact. The latest operation must match its exact actor, parent, hash, scope and receipt; a missing latest receipt fails closed instead of falling back to an older accepted roster. Generic graph and generic seat endpoints cannot manufacture this authority. No new table, migration, paid service, event-log platform or Proposed ADR-0024 production migration is introduced.

## Core invalidation and adapter requirements

`studio:acoustic:invalidate` is a best-effort server-origin hint sent to each fixed connection separately. Its strict payload is only `{ version: 1, workId, conversationId, selfSessionEpoch }`; it contains no roster, actor identity, door allowlist, token or positive grant. Receivers must compare their exact epoch and fetch authoritative state. Normal reads and heartbeat renewals do not create an event/read feedback loop. A read or accept preflight that newly records revocation does notify the fixed recipients. Door close atomically removes matching session/conversation rows and sends their fixed recipients hints after commit. Receipt cleanup binds the exact resource, so another actor reusing an intent key in another zone is unaffected.

Post-commit binding failure revokes the complete conversation, not a subset. The external binding RPC has a 2-second result deadline and no automatic mutation retry. No transaction spans Core sockets and PostgreSQL: disconnect after the final check can leave a cached active result until connection cleanup or its remaining expiry, at most 15 seconds and possibly less. Events can be lost. The future private media adapter must renew each actor's own session, reconcile the conversation, hard-stop local media on local zone/identity/door/session loss or expiry, and treat pending/revoked/unavailable state as denied. It must never interpret the lease, event, room ticket or locally asserted avatar position as an active symmetric media grant. Immediate remote Huddle/track cleanup and real two-browser private-room media behavior are not claimed by this server slice.

## Verification

The registered real PostgreSQL world-authority suite covers 2/3/4-actor acceptance, impersonation/old epoch rejection, competing accepts, immutable terminal states, stable-intent replay/different-input conflict, receipt damage, peer blocks, door/world/membership/session-version changes, removal/re-addition, bounded outstanding scopes, competing active scopes, ephemeral renewal without graph-row growth or peer-lease changes, shortened member expiry, and exact-resource cleanup. Production Gateway tests exercise local and remote owning nodes, private principal/version, real joined authority, forced ACL revocation, room transitions and disconnect. Shared strict schemas, HTTP cookie/no-store boundaries, terminal-hint regression and actual Nest DI run in required static CI. Private browser/media UI stays fail-closed pending its dedicated integration acceptance.
