## 1. 확인한 문제와 구현 범위

운영 감사에서 확인한 주요 원인은 문서 셸과 편집기가 서로의 점유 공간을 모른 채 fixed/absolute UI를 올리는 구조였다. 이번 변경은 문서·브러시·저장·협업 권위를 바꾸지 않고, 실제 편집기의 공간 배정과 패널 정보 우선순위를 수정한다.

## 2. 구조와 데이터 보존

`StudioDocumentChromeSlot`이 문서 메뉴 안에 DOM 슬롯을 제공하고, 셸의 작업공간 컨트롤과 모드 컨트롤이 그 슬롯에 포털로 렌더링된다. 모드·문서 상태의 React 소유자는 유지한다. 슬롯이 늦게 생기거나 사라지는 경우를 테스트하며, 메뉴의 실제 높이 측정값은 종료 시 이전 값으로 복원한다.

`StudioShellFloatingTarget`은 기본 배치일 때만 슬롯의 authored 위치를 따른다. 명시적으로 저장한 커스텀 배치와 배치 편집 동작은 기존 경로를 유지한다. 경고·저장 메시지를 삭제하거나 숨김 설정으로 안전 상태를 무시하지 않는다.

브러시 도킹은 현재 도구 레일의 실제 오른쪽 좌표를 사용한다. 페이지 레일까지 포함하므로 1024px 부근에서 브러시가 도구 레일 자체를 덮던 좌표 오류도 함께 고친다. 포인터 스트로크·IME 조합 중에는 기존 재배치 지연 규칙을 유지한다.

## 3. 브라우저 검증

`node scripts/verify-studio-drawing-layout.mjs`는 로컬 origin에서 별도 일러스트를 생성한다. 인증 세션은 비로그인 fixture로, 나머지 API는 503으로 처리해 실제 계정·작품·유료 서비스에 접근하지 않고 오프라인 안전 메시지도 함께 검증한다.

### 기본 화면 20개

1139×768, 1140×768, 1279×720, 1440×900, 1920×1080, 2560×1440, 1366×768, 1280×720, 1180×820, 1024×768, 1023×768, 820×1180, 768×1024, 430×932, 390×844, 375×667, 360×800, 320×568, 844×390, 667×375를 확인한다. 모두 CSS 픽셀이다.

각 크기에서 문서 작업공간·모드·구성 또는 모바일 선택·펜 버튼의 실제 DOM 존재와 중심 hit-test, 문서 가로 넘침, 캔버스 존재, 상태 바의 캔버스 경계 준수를 검사한다. 빈 선택자 결과를 통과로 처리하지 않는다. 비활성 상태도 별도로 기록한다.

### 실제 조작 6개 묶음

1. 320×568에서 첫 구성 행이 스크롤 없이 보이고 취소가 동작한다.
2. 전체 35개 도구를 두 열로 적용하고 마지막 도구·구성 버튼까지 도달한다.
3. 같은 35개를 이름 목록으로 적용하고 마지막 도구·구성 버튼까지 도달한다.
4. 같은 35개를 한 열로 적용하고 마지막 도구·구성 버튼까지 도달한다.
5. 선택→펜 전환 뒤 Chromium 터치 입력으로 실제 획을 생성한다. 레이어 행이 390×844·844×390·667×375·820×1180의 시트 첫 화면에 보이고 표시 버튼이 입력을 받는다.
6. 주 색 편집의 적용·취소가 390×844·375×667·844×390에서 조작 가능하고, 취소 후 캔버스로 돌아온다.

`trial: true`는 강제 클릭이 아니라 Playwright의 표시·안정성·입력 수신·활성 상태 검사를 수행한다. 도구 구성 적용·취소, 펜 전환, 레이어 열기와 터치 획은 실제 동작시킨다. 레이어 표시 상태와 색상은 검증 편의를 위해 실제 변경하지 않는다.

### 구현 후 실측 예

| 화면 | 브러시 결과 영역 높이 | 캔버스 뷰포트 | 비고 |
|---|---:|---:|---|
| 1140×768 | 193px | 480×563px | 분할선까지 포함한 최소 도킹 경계 |
| 1280×720 | 145px | 620×515px | 하단 상태 바 너비 444px, 우측 보조 컨트롤 공간 예약 |

캔버스 뷰포트는 DOM상의 영역이다. 위에 올라온 도구를 뺀 순수 작화 면적이나 기기 물리 해상도와 같지 않다. 이전 운영 감사와 현재 main 기반 로컬 빌드의 SHA가 다르므로 모든 수치를 동일 빌드 A/B 성능 비교로 읽으면 안 된다.

## 5. 남은 검증·설계 범위

실물 iPhone/iPad Safari, Android Chrome, 주소창 접힘·노치·홈 인디케이터, 실제 소프트 키보드와 IME, 실물 펜의 필압·팜 리젝션은 확인하지 않았다. 기존 웹뷰·브라우저별 이슈까지 해결됐다고 주장하지 않는다.

태블릿 전용 작업 레일과 1024px 전환 구조의 통합, 사용자가 임의로 넓힌 여러 패널의 모든 조합, 저장된 자유 배치의 자동 충돌 회피는 별도 설계 범위다. 이번 패치에서는 기존 입력/도구 권위와 사용자 설정을 보존하고, 확인한 기본 배치의 가림과 목록 접근성을 먼저 고쳤다.

코드 변경·커밋·PR과 main 병합·운영 배포는 별도 상태다. 운영 배포는 별도의 사용자 승인 없이 수행하지 않는다.
