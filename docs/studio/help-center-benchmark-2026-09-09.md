# Studio 도움말 센터 벤치마크 및 구현 기록

- 기준일: 2026-09-09
- 대상: `apps/web/src/domains/creator`
- 목표: 사용자가 작업을 멈추고 외부 문서를 읽는 대신, 현재 편집 맥락에서 문제를 이해하고 다음 행동까지 실행하도록 한다.

## 1. 벤치마크 범위

공식 문서와 제품 내 도움말 구조를 기준으로 다음 제품군을 비교했다.

| 제품군 | 참고한 공식 자료 | 관찰한 강점 | ToonStudio에 적용한 원칙 |
| --- | --- | --- | --- |
| Figma | [Figma Help Center](https://help.figma.com/hc/en-us), [Keyboard shortcuts](https://help.figma.com/hc/en-us/articles/360040328653-Use-keyboard-shortcuts) | 검색과 단축키 탐색, 작업 중 빠른 기능 발견 | 기존 F1 명령 검색을 중복 구현하지 않고 도움말 홈의 최우선 진입점으로 연결 |
| Canva | [Canva Help Center](https://www.canva.com/help/) | 목적 중심 안내와 초보자가 이해하기 쉬운 문장 | 기능명보다 “지금 무엇을 하려는가”와 “어떤 증상인가”를 먼저 제시 |
| Clip Studio Paint | [Official User Guide](https://help.clip-studio.com/en-us/manual_en/) | 도구별 세부 사용법과 제작 흐름 설명 | 현재 도구마다 결과·3단계 사용법·팁·실패 복구를 한 화면에 배치 |
| Krita | [Krita Manual](https://docs.krita.org/en/) | 기능별 참조 문서와 문제 해결 정보의 깊이 | 상세 설명서는 유지하되, 앱 안에서는 빠른 성공 경로와 진단으로 연결 |
| Adobe Photoshop | [Photoshop User Guide](https://helpx.adobe.com/photoshop/user-guide.html) | 학습·참조·문제 해결의 역할 분리 | 도움말 홈에서 학습, 검색, 진단, 복구를 명확히 분기 |
| Procreate | [Procreate Handbook](https://help.procreate.com/procreate/handbook) | 작업 단계에 가까운 시각적·도구 중심 설명 | 현재 선택 도구를 첫 문맥으로 사용하고 짧은 단계형 가이드를 제공 |

벤치마크의 목적은 화면을 복제하는 것이 아니라 다음 공통 성공 조건을 추출하는 것이다.

1. 사용자가 기능의 정확한 이름을 몰라도 출발할 수 있어야 한다.
2. 현재 도구와 현재 증상을 도움말의 기본 문맥으로 사용해야 한다.
3. 검색, 학습, 진단, 복구가 별도 섬이 아니라 서로 왕복 가능해야 한다.
4. 짧은 인앱 도움말과 긴 사용자 설명서는 역할이 달라야 한다.
5. 도움말 자체도 키보드, 스크린리더, 작은 화면에서 사용할 수 있어야 한다.

## 2. 기존 구현 감사

기존 Studio 도움말에는 이미 다음 기반이 있었다.

- F1 명령 검색과 별칭 기반 탐색
- 기능 튜토리얼 허브
- 단축키 도움말
- 시스템·입력·GPU 진단
- 복구 센터
- 용어 사전
- 라이선스 및 버그 보고
- 현재 도구와 관련 명령 연결

핵심 격차는 기능의 부재가 아니라 **사용자가 막힌 순간에 이 기능들을 올바른 순서로 연결해 주는 작성형 안내가 없다는 점**이었다. 기존 현재 도구 화면은 명령 메타데이터와 검색 결과는 제공하지만, 성공 결과, 최소 단계, 자주 하는 실수, 문제 해결 순서를 설명하지 못했다.

## 3. 제품 원칙

### 3.1 한 검색 표면

도움말 안에 별도의 전역 기능 검색을 다시 만들지 않는다. 기능·설정·메뉴·튜토리얼 검색은 기존 F1 명령 검색을 단일 진입점으로 유지한다. 도움말 센터는 검색 결과를 복제하는 대신 올바른 검색 표면으로 이동시킨다.

### 3.2 현재 문맥 우선

`toolCommandId`가 있으면 현재 도구의 가이드를 첫 화면으로 연다. 사용자는 홈, 현재 도구, 문제 해결 사이를 즉시 이동할 수 있다. 상세 진단·복구·용어 사전·라이선스·버그 보고는 기존 화면을 그대로 재사용한다.

### 3.3 30초 성공 경로

도구 가이드는 다음 고정 구조를 갖는다.

1. 사용 목적과 기대 결과
2. 정확히 세 단계의 최소 사용법
3. 품질을 높이는 팁
4. 흔한 증상과 즉시 확인할 해결책
5. 관련 문제 해결 레시피

긴 문서의 축약본이 아니라 사용자가 바로 행동하기 위한 체크리스트다.

### 3.4 증상 중심 문제 해결

문제 해결은 “레이어”, “렌더러” 같은 내부 구조보다 사용자가 관찰한 증상에서 시작한다.

- 선이나 지우개 결과가 보이지 않음
- 채우기가 밖으로 샘
- 일부 영역만 편집됨
- 객체가 사라진 것처럼 보임
- 확대 후 작업 위치를 잃음
- 캔버스·입력 지연
- 저장 및 복구
- 단축키 충돌
- 타 편집기 용어 차이
- 내보내기 결과 차이
- 협업 상태 불일치

각 레시피는 세 단계 점검 순서와 다음 행동을 포함한다. 진단이나 복구가 필요한 경우 기존 전문 화면으로 연결한다.

### 3.5 점진적 공개

처음에는 홈과 현재 작업에 필요한 정보만 보이고, 상세 기술 정보는 진단·버그 보고 화면에서 제공한다. 초보자의 인지 부하를 낮추면서 전문가의 조사 경로는 유지한다.

## 4. 구현 구조

### `studio-help-content.ts`

- 핵심 캔버스 도구를 명령 ID에 매핑하는 도움말 그래프
- 도구별 성공 결과, 3단계 가이드, 팁, 실패 복구
- 증상별 문제 해결 레시피와 검색 인덱스
- 관련 가이드와 레시피가 ID로 연결되는 순수 데이터 계층

### `StudioContextHelpDialog.tsx`

- 도움말 홈
- 현재 도구 30초 가이드
- 증상 검색형 문제 해결
- 기존 F1 검색, 진단, 복구, 용어 사전, 설명서로의 연결
- 데스크톱 사이드 탐색과 모바일 상단 탐색
- 모달 포커스 트랩, Escape 닫기, 배경 inert, 스크롤 잠금

### `StudioHelpCenterHost.tsx`

- `current-tool` 요청만 새 맥락형 도움말 센터로 라우팅
- 진단, 복구, 용어 사전, 라이선스, 버그 보고는 기존 다이얼로그 유지
- 기존 요청 채널과 호출부의 API를 변경하지 않아 회귀 범위를 제한

### `studio-help-content.test.ts`

- 고빈도 도구 가이드 커버리지
- 가이드·명령 ID 중복 방지
- 관련 레시피 참조 무결성
- 모든 레시피의 실행 가능 경로
- 한국어 증상, 제품 용어, 기술 용어 검색

## 5. 접근성 및 사용성 기준

- `role="dialog"`, `aria-modal`, 제목 연결
- 열릴 때 명시적 초기 포커스
- Tab/Shift+Tab 포커스 순환
- Escape 및 배경 클릭 닫기
- 배경 DOM에 `inert`와 `aria-hidden` 적용 후 원상 복구
- 모달 동안 문서 스크롤 잠금
- 모든 아이콘 버튼에 접근 가능한 이름 제공
- 현재 탐색 위치에 `aria-current="page"`
- 모바일에서 수평 탐색, 본문 독립 스크롤
- 색만으로 상태를 구분하지 않고 텍스트와 테두리를 함께 사용

## 6. 범위에서 제외한 사항

- F1 명령 검색과 중복되는 새 전역 검색 엔진
- 도움말 CMS 또는 원격 문서 동기화
- 사용자 행동 추적 및 개인정보 수집
- AI가 사실을 검증하지 않고 임의 해결책을 생성하는 상담 UI
- 기존 진단·복구·버그 보고 기능의 재작성

## 7. 후속 고도화 지점

1. 도움말 그래프를 명령 카탈로그의 정적 검증 대상으로 확대해 신규 도구 누락을 CI에서 탐지한다.
2. 기능 튜토리얼 허브에 `tutorialId` 직접 열기 채널을 추가해 가이드에서 실습으로 전환한다.
3. 오류 코드와 진단 결과를 문제 해결 레시피에 안전하게 매핑한다.
4. 익명·집계형 데이터에 한해 “도움이 됨/안 됨” 피드백을 도입하고 문서 개선 우선순위를 정한다.
5. 영어 UI가 활성화되면 동일한 콘텐츠 스키마에 번역 리소스를 연결한다.
