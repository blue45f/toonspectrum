# Storyboard Readiness Control Room — 후속 벤치마크와 구현 결정

작성일: 2026-09-09  
대상: `/studio` 스토리보드 컨트롤 룸  
선행 구현: Storyboard Control Room(#967), 일괄 검토 작업(#999), 카메라·오디오 애니매틱(#947)

## 문제 정의

기존 컨트롤 룸은 페이지 순서, 검토 상태, 담당자, 샷 메타데이터를 한 화면에서 확인하고 검색·필터·CSV로 인계할 수 있다. 그러나 제작자가 여전히 직접 판단해야 하는 질문이 남아 있었다.

1. 지금 애니매틱·작화·외주 인계로 넘겨도 되는 페이지는 몇 개인가?
2. 수정 요청, 빈 페이지, 샷 정보 누락 중 무엇을 먼저 처리해야 하는가?
3. 같은 샷 유형과 카메라 앵글이 장시간 반복되어 시각 리듬이 단조로워진 구간은 어디인가?
4. CSV를 전달할 때 단순 상태뿐 아니라 진단 이유도 함께 보낼 수 있는가?

이번 후속은 새 문서 스키마나 별도 저장소를 만들지 않고, 기존 페이지·검토·샷 데이터를 읽는 **설명 가능한 제작 준비도 계층**을 추가한다.

## 경쟁 제품 패턴의 번역

| 참고 패턴 | 확인한 제품군 | ToonSpectrum 적용 |
| --- | --- | --- |
| 시퀀스 전체의 제작 상태를 한눈에 보는 보드 | Toon Boom Storyboard Pro, Boords, StudioBinder | 페이지별 준비도 점수와 차단/확인/준비 우선순위 |
| 리뷰 요청과 승인 전 상태를 명확히 분리 | Boords, KROCK.io, StudioBinder | 검토 미요청·검토 대기·수정 요청을 서로 다른 가중치로 진단 |
| 샷리스트에서 누락 필드와 반복 구도를 사전 확인 | Storyboard Pro, StudioBinder, Wonder Unit Storyboarder | 샷 유형·카메라 앵글 누락 및 3페이지 이상 동일 구도 연속 탐지 |
| 외주·클라이언트 인계용 구조화된 내보내기 | Boords, Storyboard Pro, StudioBinder | 준비도, 우선순위, 진단 사유를 formula-safe CSV에 포함 |
| 자동화 결과를 사람이 설명 가능하게 검토 | AnimAgents 연구와 기존 AI 스토리보드 디렉터 | 점수의 감점 사유를 모두 사용자에게 노출하고 자동 수정은 수행하지 않음 |

경쟁 제품의 고유 UI나 명칭을 복제하지 않았다. 현재 Studio의 웹툰 페이지 모델과 검토 계약 안에서 반복적으로 발생하는 제작 병목을 정적·결정적으로 판독하는 방식으로 번역했다.

## 준비도 정책

각 페이지는 100점에서 시작하며, 다음 진단에 따라 감점한다.

| 진단 | 감점 | 우선순위 판단 |
| --- | ---: | --- |
| 빈 페이지 | 35 | 차단 |
| 수정 요청 | 30 | 차단 |
| 샷 유형 또는 카메라 앵글 누락 | 25 | 확인 필요 |
| 검토 대기 | 12 | 확인 필요 |
| 검토 담당자 미지정 | 10 | 확인 필요 |
| 승인 페이지 잠금 해제 | 10 | 확인 필요 |
| 검토 미요청 | 8 | 확인 필요 |
| 동일 샷 유형+카메라 앵글 3페이지 이상 연속 | 8 | 확인 필요 |

점수는 0~100으로 제한한다. `빈 페이지`와 `수정 요청`은 제작 진행을 막는 차단 항목으로 분류하고, 나머지 진단이 하나라도 있으면 확인 필요로 분류한다. 진단이 없을 때만 제작 준비 상태가 된다.

이 점수는 품질을 대신 판정하거나 창작 의도를 평가하지 않는다. 동일 구도 반복도 오류가 아니라 검토 신호이며, 사용자가 의도한 연출이면 그대로 유지할 수 있다.

## 구현 범위

### 순수 도메인 모델

- 기존 `buildStoryboardControlRoom` 결과에 `readinessScore`, `priority`, `issues`, `emptyPage`, `continuityRisk` 추가
- 전체 준비도 평균, 차단 수, 확인 필요 수, 준비 완료 수, 연속 구도 위험 수 집계
- `attention`, `continuity-risk` 운영 필터 추가
- 진단명과 우선순위명을 검색 색인에 포함
- 3개 이상 연속한 동일 샷 유형·카메라 앵글 구간을 결정적으로 탐지
- `elements`가 없는 경량 호출자는 빈 페이지로 오판하지 않고, 실제 Studio 페이지 배열에서만 빈 페이지 판정

### UI

- 시퀀스 카드에 우선순위 배지와 준비도 표시
- 차단/확인 필요/제작 준비 3열 `준비도 큐` 추가
- 제작 준비도, 즉시 확인, 연속 구도 지표를 원클릭 필터로 제공
- 검색 범위를 준비도 진단까지 확장
- 기존 시퀀스 DnD, 검토 큐, 샷 태그 편집, 추가·복제·삭제, 키보드 흐름 유지

### 인계

기존 CSV에 다음 열을 추가한다.

- 제작 준비도
- 우선순위
- 진단

기존 UTF-8 BOM, RFC 스타일 인용 처리, 스프레드시트 수식 주입 방어는 유지한다.

## 검증

- strict TypeScript, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`
- 기존 검토·검색·필터·CSV 회귀
- 준비도 평균과 우선순위 집계
- 3페이지 이상 반복 구도 탐지와 2페이지 비탐지
- 빈 페이지 차단 및 `elements` 미제공 경량 호출자 호환성
- 진단 검색과 CSV 진단 열
- TSX 구문 변환

## 의도적으로 제외

- AI가 자동으로 샷 유형이나 카메라 앵글을 변경하는 기능
- 장면 의미를 추론해 180도 룰, 시선 방향, 공간 축을 자동 판정하는 기능
- 서버 권한·마감일·외주 계약을 포함한 조직별 가중치
- 점수를 문서에 저장하거나 협업 상태로 동기화하는 기능

위 범위는 현재 페이지 데이터만으로 확정할 수 없거나 창작 의도를 침해할 수 있다. 이번 준비도는 저장 없는 파생 상태이므로 기존 문서 호환성, Undo/Redo, autosave, CRDT 권위를 변경하지 않는다.
