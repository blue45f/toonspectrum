# 사이트 이미지 품질 전수 조사 — 2026-09-16

## 결론

사이트 정적 이미지 **2,235개**를 파일 단위로 검사하고, 공개 핵심 경로 **22개를 데스크톱·모바일에서 44회 렌더링**해 실제 노출 상태를 확인했다. 최종 프로덕션 번들에서 가시 이미지 **312회**를 실제 응답 비트맵 크기로 다시 측정했으며, 손상·요청 실패·유의미한 저해상도 확대는 모두 0건이었다. 브랜드 히어로와 마케팅 아트는 원본 해상도, 반응형 파생본, 실제 크롭을 함께 확인한 결과 교체보다 유지가 적절했다.

실제 개선 대상은 2D 장면 기본 라이브러리와 이를 재사용하던 마켓 카드였다. 기본 목록에 남아 있던 구형 래스터 배경 중 **24개**는 낮은 원본 해상도, 생성형 문자·간판 형태, 가구·건축 원근 오류, 고정 인물, 출처 불명확성 중 하나 이상이 확인됐다. 이 항목은 새 작업의 기본 선택 목록에서 제외하고, 저장소에 이미 포함된 **2048×1152 Poly Haven CC0 포토 레퍼런스 28개**를 전체 프레임 검수 후 장르·장소·시간·인물·문자 메타데이터와 함께 노출하도록 변경했다.

기존 파일과 ID는 삭제하지 않는다. 이전 이미지 주소를 사용하는 저장 데이터나 명시적 마이그레이션이 깨지지 않도록 호환 카탈로그에 유지하되, 새 작업 UI와 마켓 홍보 화면에서는 더 이상 직접 노출하지 않는다.

## 조사 범위와 방식

### 1. 정적 파일 전수 검사

`apps/web/public` 아래 PNG, JPEG, WebP, AVIF, GIF, SVG를 대상으로 다음 항목을 수집했다.

- 파일 헤더 디코딩 성공 여부, 실제 MIME, 가로·세로 픽셀, 종횡비, 용량
- SHA-256 동일 파일, 지각적 유사도 후보, 투명 영역 비율
- 역할별 해상도 하한: 히어로·프로모션, 장면 배경, 카드 썸네일, 아이콘·브러시 팁을 서로 다른 기준으로 판정
- 큰 래스터의 에지 밀도와 명도 엔트로피를 이용한 과도한 흐림·단색·압축 후보 추출
- 코드의 리터럴 이미지 경로 참조와 실제 사용 컴포넌트 추적

자동 지표는 교체 결정을 내리는 도구가 아니라 **육안 검수 후보를 줄이는 용도**로만 사용했다. 작은 아이콘, 브러시 팁, 투명 패턴, 640/960 반응형 파생본은 원래 표시 크기와 원본 `srcset`을 확인한 뒤 저품질 판정에서 제외했다.

| 검사 항목 | 결과 |
| --- | ---: |
| 정적 이미지 | 2,235개 |
| 디코딩 오류 | 0개 |
| 정확히 같은 바이트 그룹 | 36개 |
| 코드에서 리터럴 경로로 확인된 이미지 | 194개 |
| 장면 배경 후보 | 54개 |

정확히 같은 파일 36그룹 가운데 25그룹은 기존 장면의 `.jpg`/`.png` 호환 별칭이었다. 나머지는 마스크 아이콘, 2D/3D 포즈 미리보기, 일부 CC0 프리뷰 등 의도된 호환·표시 자산이다. 이번 변경에서 중복 수를 줄이기 위해 호환 주소를 삭제하지 않았다.

### 2. 실제 화면 렌더링 검사

다음 22개 경로를 1440×1000 데스크톱과 390×844 모바일 환경에서 렌더링했다.

`/`, `/discover`, `/ranking`, `/market`, `/market/browse`, `/showcase`, `/showcase/challenges`, `/research`, `/research/assets`, `/research/3d-assets`, `/now`, `/learn/recipes`, `/story-lab`, `/production`, `/community`, `/fortune`, `/play`, `/about`, `/studio`, `/studio/new`, `/studio/templates`, `/studio/assets`

44회 모두 HTTP 200, 페이지 런타임 오류 0건, 이미지 요청 실패 0건을 확인했다. 페이지를 끝까지 순회하며 지연 로딩 이미지를 강제로 관찰한 뒤, `currentSrc` 응답을 `createImageBitmap()`으로 다시 해석해 **312회 이미지 노출의 실제 파일 픽셀**을 측정했다. 손상 이미지와 CSS 배경 손상은 0건이었고, 원본 픽셀이 실제 표시 픽셀의 85% 미만인 유의미한 확대 노출도 0건이었다.

첫 검사에서는 `srcset` 후보의 밀도 보정값인 `naturalWidth`를 원본 픽셀로 오인할 수 있음을 발견해 감사 방식을 수정했다. 이 과정에서 창작 나침반 카드가 모바일에서 약 332px로 펼쳐지는데도 `sizes="180px"`로 선언되어 640px 후보를 선택하는 실제 문제를 찾았다. 선언을 모바일 실제 폭과 데스크톱 150px 폭에 맞게 고쳐 3× 모바일에서 1536px 원본을 선택하도록 했고, 회귀 테스트를 추가했다.

0.85~1.15 구간의 고밀도 경계 후보는 92회·원본 8개였다. 대부분 여러 페이지에 반복되는 1536px 브랜드 원화의 커버 크롭과 960×720 3D 환경 썸네일이었다. 실제 표시 크기로 확대 확인했을 때 흐림, 깨진 기하, 문자 오류가 없어 유지했다. 또한 교체 대상 28개는 별도 Chromium 그리드에서 모두 `Image.decode()`를 실행해 **28/28 성공, 자연 크기 2048×1152 일치**를 확인했다.

### 3. 시각적 판정 기준

다음 조건을 함께 판단했다.

- 실제 표시 크기와 DPR 대비 원본 픽셀 부족 또는 확대 흐림
- 임의 문자, 읽을 수 없는 간판, 반복 무늬, 기하·원근·가구 접합 오류
- 빈 배경으로 오해하기 쉬운 고정 인물·홀로그램·포스터 포함 여부
- 페이지의 브랜드 톤과 이미지 스타일 불일치
- `object-fit`, 크롭 위치, 모바일 잘림으로 핵심 피사체가 사라지는지
- 같은 원화를 여러 장면처럼 오해하게 만드는 반복 사용인지, 의도된 컷 분할인지
- 출처·이용 조건을 코드와 원장에서 추적할 수 있는지

## 상세 판정

### 유지한 이미지

- `brand/atelier-world`, `atelier-process`, `atelier-materials` 원본과 640/960 파생본은 파일명만 믿지 않고 실제 비트맵이 각각 1536×1024, 960×640, 640×427인지 확인했다. 카드와 히어로의 크롭도 핵심 피사체를 유지하므로 교체하지 않았다. 창작 나침반의 부정확한 `sizes` 선언만 반응형으로 수정했다.
- 웹툰 갤러리 소개의 동일 원화 3회 사용은 서로 다른 `object-position`으로 한 원화를 컷처럼 분할한 연출이었다. 실제 화면에서 장면 반복보다 연속 컷으로 읽혀 유지했다.
- 아이콘, 브러시 팁, 패턴, 투명 텍스처는 파일 자체가 작더라도 실제 표시 크기 또는 반복 타일 용도에 충분했다.
- 3D 환경 썸네일은 카드 표시 크기 기준으로 픽셀 밀도가 충분하고, 장면 구조가 명확해 유지했다.

### 기본 노출에서 제외한 이미지

구형 2D 래스터 29개 중 추천 검수를 통과한 5개는 유지했다. 나머지 24개는 다음 사유로 기본 선택 목록과 제품 홍보 참조에서 제외했다.

- 20개: 원본이 627×940으로, 일반적인 가로 장면 카드나 캔버스 배경 확대에 부족함
- 4개: 1024×1024이지만 고정 인물, 문자 형태, 복잡한 간판 또는 장면 구조가 기본 빈 배경으로 부적절함
- 일부: 생성형 글자처럼 보이는 간판, 휠체어·가구 접합, 건축 직선·원근, 반복 구조가 확대 시 어색함
- 전체: 기존 생성·제작 기록과 원본 이용 조건 증거가 저장소에 없어 `licenseStatus: unverified`

제외는 파일 삭제가 아니다. `BG_SCENE_COMPATIBILITY_LIBRARY`와 기존 원본 경로를 유지해 과거 참조를 보존하고, `BG_SCENES` 기본 선택 목록에서만 분리했다.

### 대체한 이미지

저장소의 기존 CC0 패키지에서 28개를 골랐다. 모두 2048×1152 WebP이며, 전체 프레임을 확대 확인했다.

- 일상·도시: 넓은 거리, 횡단보도, 발코니 실내, 원목 라운지, 인테리어 숍, 도시 안뜰
- 로맨스: 공원, 가을 공원, 바다 노을, 황혼 옥상, 해안 산책로
- 판타지·모험: 새벽 계곡, 이끼 숲, 숲길
- 무협·사극 참고: 베네치아 골목, 고풍 아케이드 시장
- 드라마: 대형 복도, 연회장, 야간 기차역, 지하철 입구
- SF·현대 공간: 야간 아트리움, 도심 착륙장, 현대 실내 산책로
- 액션·스릴러: 고가도로, 산업 창고, 안개 숲, 야간 안뜰, 선착장

각 항목은 `SOURCE.json`과 대조해 Poly Haven, CC0-1.0, 원본 URL, 확인일을 기록했다. SHA-256, 바이트 수, 실제 WebP 크기, 메타데이터가 달라지면 테스트가 실패한다. 화면에서는 `CC0`, `포토 레퍼런스`, 실제 WebP 형식을 명시해 기존 미확인 래스터와 구분한다.

## 한계와 운영 원칙

이번 전수 조사는 저장소 정적 자산과 현재 공개 화면을 기준으로 한다. 사용자 업로드 이미지, API가 런타임에 반환하는 외부 썸네일, 로그인 후 개인 작업물은 품질을 임의 변경하지 않았다. 개발 서버에서 백엔드 API가 연결되지 않은 화면은 정적 레이아웃과 로컬 이미지까지만 검수했다.

사진 원본은 높은 해상도와 명확한 출처를 제공하지만, 최종 웹툰 스타일과 동일한 완성 일러스트는 아니다. 그래서 UI에 `포토 레퍼런스`로 표시한다. 향후 스타일화 배경을 추가하려면 원본 해상도, 전체 프레임 검수, 출처·이용 조건, 문자·인물·기하 오류 기록을 같은 수준으로 갖춰야 한다.

이 변경은 브랜치와 PR까지만 수행하며 운영 배포는 별도 승인 후 진행한다.
