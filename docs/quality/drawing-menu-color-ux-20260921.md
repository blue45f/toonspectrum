# 드로잉 메뉴·색상 선택 UX 개선 — 2026-09-21

## 확인한 원인

도구 카탈로그는 35종이며, 설정 모델에서 27개 제한은 확인되지 않았다. 저장된 기본 표시 목록은 8종이고 핵심 도구의 강제 표시 및 작업 공간 추천이 별도로 적용된다. 기본 설정의 실제 표시 수는 10종이다. 숨겨진 기능에 도달하는 구성 진입점이 아이콘뿐이고, 표시 개수도 저장 목록만 세고 있었다.

설정 화면의 위·아래 이동은 목록을 저장하지만 기존 좌측 레일은 고정 JSX 순서로 렌더링했다. 또한 참고 이미지는 명시적으로 고정해도 집중 모드의 추가 조건으로 사라질 수 있었다.

상단 색상 컨트롤은 작은 네이티브 색상 칩에 의존했고, 이미 구현된 커스텀 색상 창으로 진입하는 명시적인 버튼이 없었다. HEX 입력에서는 유효한 3자리 미리보기의 상태 업데이트가 입력 중인 6자리 코드를 덮어썼다. 빠른 색 선택기의 pointercancel도 완료 이벤트처럼 처리되어 잘못된 좌표를 확정할 수 있었다.

## 구현

- 고정 footer에 `구성` 문구, 전체 도구 수·실제 표시 수, 검색, `전체 35개 표시` 및 이전 구성 복원을 제공한다. 설정 화면에도 전체 표시와 복원을 제공한다.
- 이름·단축키와 스포이드, 팬, 버킷 등 익숙한 별칭으로 검색한다. 구성 창을 열면 검색 필드에 초점이 이동한다.
- 저장한 순서를 실제 DOM 순서와 키보드 탐색 순서에 반영한다. 35종의 기존 명령과 잠금 조건을 유지한다. 고정한 참고 이미지는 집중 모드에서도 표시한다.
- 레일에 얇은 스크롤바와 위·아래 방향키, Home/End 이동을 제공한다. 구성 버튼은 도구 목록과 독립되어 항상 접근할 수 있다.
- 색상 컨트롤에 명시적인 `다른 색상` 버튼을 추가하고 기존 커스텀 색상 창의 빠른 선택·팔레트·색상환·조화·웹툰·슬라이더를 연결한다. 기존 시스템 색상 선택기와 주/보조 색 교환은 유지한다.
- 캔버스 스포이드 진입을 연결하고 주·보조 색 클릭 영역과 터치용 색조 막대·탭·보조 버튼의 조작 영역을 확대한다.
- HEX 입력 원문을 미리보기 중에도 보존하고 Enter 확정·Escape 취소·중복 확정 방지를 보완한다.
- 포인터 소유권과 캡처 해제·취소를 구분하여 취소 시 원래 색을 미리보기로 복원한다. 색조 키보드 조작은 blur에서 중복 확정하지 않는다.
- 작은 화면과 가상 키보드 영역에 대응하도록 visualViewport의 크기·오프셋·resize/scroll을 반영한다.

## 검증

변경 관련 Vitest 11개 파일, 115개 테스트가 통과했다. 여기에는 저장 순서, 35종 전체 표시/복원, 핵심 도구·잠금·기존 명령 유지, 검색 별칭, HEX 연속 입력, 취소·캡처 손실, 중복 확정 방지, 가상 키보드 영역 및 레일 키보드 이동이 포함된다.

`pnpm run typecheck`의 프론트엔드·API 검사와 `pnpm run validate:architecture`, 변경 파일 ESLint 검사가 통과했다.

실제 컴포넌트를 사용하는 로컬 Chromium 통합 하네스에서 다음 4개 시나리오 묶음을 통과했고 pageerror는 0건이었다.

1. 35종 전체 표시·이전 구성 복원·별칭 검색·실제 개수 안내.
2. 설정 순서 변경이 실제 DOM에 반영되고 하네스 저장 상태가 새로고침 후 유지됨.
3. 지연 로딩 색상 창 진입·HEX 6자리 연속 입력·Escape 원래 색 복원.
4. 390px 터치 에뮬레이션에서 바텀시트 화면 내 배치·색조 조작 영역 44px·캔버스 스포이드 연결.

## 범위와 제한

실제 운영 계정의 전체 프로젝트 흐름, 실기기 펜·가상 키보드, Safari/Firefox는 이번 검증에 포함하지 않았다. 모바일은 Chromium의 터치 에뮬레이션과 visualViewport 단위 테스트를 사용했다. 브라우저 새로고침 검증은 하네스의 로컬 저장소를 사용하며 실제 OPFS 저장소의 별도 통합 검증을 대신하지 않는다. 기존 설정 저장 계약은 유지했다.

운영 배포·데이터베이스·도메인·환경 변수는 변경하지 않았다. 운영 반영 상태는 PR 및 별도 배포 결과로 확인해야 한다.
