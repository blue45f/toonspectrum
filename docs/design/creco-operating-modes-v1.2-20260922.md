# Creco 통합 — 무료·유료 운영 모드 v1.2

상태: **부분 구현 / 운영 미적용**. 사용자 결정 2026-09-22. v1.1의 영구 무료 전제와 미래 과금 경계 제거 결정을 이 문서로 대체한다. 당분간 기본값은 무료이며 향후 관리자 운영 모드로 유료 정책을 적용할 수 있게 한다.

## 1. 세 가지를 분리한다

1. **운영 모드** `free | paid`: 현재 서비스 운영 목적, 활성 기능, 공통 이용 한도, 사용자 안내.
2. **라이선스 승인**: 배포물·자산·모델·사용 형태별 승인 근거와 유효기간. 무료라고 자동 허용하지 않는다.
3. **사용자 과금**: 별도 요금제·가격 견적·명시 동의·결제 수단·서버 결제 확인. 운영 모드만 바뀌어도 가입·청구되지 않는다.

무료에서 기능을 숨기거나 유료에서 보인다는 사실은 라이선스 의무를 이행했다는 증거가 아니다. 이미 번들·정적 URL로 배포한 제한 코드/자산은 런타임 토글로 회수되지 않는다. 유료 전환에는 실제 배포 산출물, dependency lock, 제3자 고지, Rights BOM, 정적 자산 URL과 서비스워커 캐시를 포함하는 배포 전 검증이 추가로 필요하다. 기존 ADR-0008의 빌드/분리/고지 정책을 유지한다.

Creative Commons의 NonCommercial FAQ도 사용의 목적과 맥락에 따라 판단할 필요가 있음을 설명한다. 특정 라이선스 검토는 실제 약관과 배포 형태를 근거로 하고, 무료 운영만으로 적법성이 확보됐다고 표현하지 않는다. 참고: https://creativecommons.org/faq/#does-my-use-violate-the-noncommercial-clause-of-the-licenses

## 2. 관리자 화면

기존 `/admin?tab=ops`에 모드 전환·모드별 한도·변경 미리보기/적용 패널을 연결했다. 독립 `apps/admin`에는 **운영 모드와 라이선스** 상세 검토 화면을 추가했다. 같은 출처의 `/api/admin/production/operation-policy`와 관리자 로그인 세션을 사용한다. 기존 운영 도메인·프록시·로그인 정책을 이번 작업에서 변경하지 않는다. 이 surface 배포는 별도 승인 대상이다.

- 무료·유료 모드 선택: 라디오 토글, 선택만으로 저장하지 않는다.
- 두 모드의 구성은 따로 저장: 소유 워크스페이스, 조직별 프로젝트, 구성원+대기 초대 한도, 기능 상태, 사용자 안내.
- 라이선스 검토: 미검토/승인/차단, 승인된 모드, 배포물 fingerprint, 내부 근거 참조, 만료.
- 변경 영향 미리보기 → 사유 입력 → 확인 적용. 정책 revision으로 오래된 확인창의 적용을 차단한다.
- 적용 이력: 누가, 언제, 왜 바꾸었는지와 변경 전후 digest를 기록한다.

기본 유료 프로필도 2/5/10으로 시작한다. 이는 아직 판매 요금제나 유료 고객의 권리를 정의한 값이 아니다. 관리자 검증 후 모드별 공통 운영 용량을 다르게 설정할 수 있다. 향후 개인·팀별 구독 등급이 도입되면 별도 entitlements와 명시적 구매 동의를 연결한다.

## 3. 전환의 서버 계약

`GET /api/admin/production/operation-policy`

`POST /api/admin/production/operation-policy/preview`

`POST /api/admin/production/operation-policy/apply`

`GET /api/production/operation-policy` — 로그인 사용자용 최소 공개 정책. 내부 근거·감사·다른 모드 전체 설정은 제외한다.

서비스 관리자 `user.role=admin`만 관리 API를 사용할 수 있다. 일반 운영자(operator), 조직 소유자(owner), 일반 사용자는 정책을 바꿀 수 없다. 현재 계정 status를 재검증하며 인증된 서버 사용자 ID를 사용한다. 쿠키 인증에는 기존 CSRF/Origin 경계를 그대로 적용한다.

미리보기는 `expectedRevision + draft + 현재 배포물 fingerprint`의 digest를 반환한다. 적용 시 현재 상태와 라이선스를 다시 확인하고, singleton row 잠금 아래 새 revision·audit·mutation receipt를 원자적으로 저장한다. 같은 요청 ID와 같은 내용은 재실행하지 않고 기존 acceptedRevision을 반환한다. 같은 ID의 다른 내용과 두 관리자의 동시 변경은 충돌로 반환한다.

정책 저장은 사용자 구독, 카드, 청구서, 정기결제, 결제 제공자 API, 워크스페이스 소유권 또는 기존 파일을 변경하지 않는다.

## 4. 무료→유료 / 유료→무료

| 전환 | 적용 | 금지 |
|---|---|---|
| 무료→유료 | 유료 모드용 공통 정책과 안내 적용 | 기존 회원 자동 유료 가입·청구, 검토 미완료 기능의 자동 개방 |
| 유료→무료 | 무료 모드 정책 적용 | 기존 원고 삭제, 초과 회원 강제 추방, 원고 공개범위 변경 |
| 한도 하향 | 새 생성·초대·프로젝트 연결에 낮은 한도 적용 | 이미 보관한 자료나 별도 작품 권한 변경 |
| 기능 일시중지 | 새로운 해당 작업 차단 | 기존 자료 조회·회수·취소를 단순 paywall로 차단 |

이번 구현에는 실제 SaaS checkout이 없다. API `billing.state=disabled`, `checkoutEnabled=false`, `automaticEnrollment=false`는 두 모드에서 고정이다. 향후 과금 도입 시 **모드 paid AND 라이선스 승인 AND 명시적 상품·금액 견적 AND 사용자 동의 AND 결제 제공자 준비 AND 서버 확인**을 모두 충족해야 한다. 상품 판매/후원/작품 계약 정산의 기존 기능을 이 구현의 신규 SaaS 구독으로 재사용하거나 임의로 삭제하지 않는다.

## 5. 라이선스 승인과 배포물

관리자가 `approved`를 선택하려면 승인 모드, `sha256:` + 64자리 digest, 근거 문서 참조가 필요하다. 만료가 지나거나 배포물 fingerprint와 일치하지 않으면 paid 전환을 거절한다. 전환 후 배포물이 바뀌거나 승인이 만료돼도 새 워크스페이스 작업은 실행 시 다시 검사한다. 무료 복귀는 오래된 유료 승인 때문에 막지 않는다.

`TOONSTUDIO_LICENSE_FINGERPRINT`는 배포 검증자가 검토한 산출물 manifest의 digest를 전달하는 **서버 전용 비밀이 아닌 설정값**이다. 관리 화면에서는 실제 배포물 값을 수정할 수 없다. 없거나 형식이 틀리면 유료 전환은 차단된다. 이번 작업에서는 운영 환경에 이 값을 설정하거나 실사용 승인을 만들지 않았다. 테스트의 반복 문자 digest/근거는 명시된 synthetic fixture일 뿐이다.

현재 승인 기록은 운영자의 확인 기록이며, 실제 계약 원본 검증·BOM 자동 대조·법률 판단을 수행하는 엔진이 아니다. 무료 용도와 유료 용도 승인을 따로 표현한다. 사이트가 무료여도 사용자의 상업 작품 출력, 모델 사용, 자산 재배포 권리가 허용되는지는 별도 검토해야 한다.

## 6. 현재 연결된 범위와 미연결 범위

**현재 구현:**

- 팀 조직 생성·목록·상세·이름, 구성원 초대/인증된 수신자 수락/재발행/회수/역할/퇴장/소유권 이전.
- 기존 ProductionProject 연결·해제. 작품 ACL은 별도로 재검증하며 조직 가입이 원고 접근권한을 주지 않는다.
- 조직 생성 수·프로젝트 연결 수·회원+대기 초대 용량에 현재 모드의 정책을 트랜잭션 내에서 적용.
- 정책 변경과 quota 명령의 경합을 row share/update lock으로 제어. 낮은 빈도의 조직 변경은 별도 admission fence로 직렬화.
- DB 데이터·UI·재접속 유지, 감사, 동시 변경 충돌, 멱등성, 관리자 화면과 사용자 안내.
- core modelVersion2와 DB modelVersion1 불일치의 증분 compatibility migration.

**아직 전역 연결 완료가 아닌 부분:**

- 기존 Studio의 모든 브러시·WASM·폰트·3D 자산·AI 경로를 이 정책으로 통제하는 작업.
- 원고 업로드/파생물/내보내기/공유의 모든 자원 계량과 사용량 예약. 저장량은 미측정을 0으로 표시하지 않는다.
- Creco 설계의 모든 원고 버전·공동 텍스트 편집·주석·보호 공유·출력 변환을 신규 정책에 연결하는 작업.
- 요금제 판매·청구·정기결제·환불·유료 회원별 entitlements.
- 권리 BOM fingerprint 자동 배포, 법적 승인 문서의 외부 검증, 라이선스 제한 자산의 배포 산출물 자동 격리.

따라서 이 변경은 **운영 모드/정책 기반과 팀 조직 기능 구현**이며, 전체 서비스의 모든 라이선스 문제가 해결됐거나 모든 Creco 기능이 완성됐다는 보고가 아니다. `licensed-assets`와 `ai-shading`은 검토를 승인해도 provider/권한 경로의 연동이 완료되지 않아 비활성 상태를 반환한다. 기존 다른 기능의 활성 상태까지 바꿨다고 주장하지 않는다.

## 7. DB·배포 이행

0084: production modelVersion 1/2 호환. 0053을 수정하지 않는다.

0085: 팀 조직 6테이블, 마지막 소유자 보호 deferred trigger.

0086: 운영 정책 singleton, 변경 감사, 멱등 receipt. 초기 무료·미검토·과금 비활성.

새 migration은 rerunnable이며 정책 seed는 `ON CONFLICT DO NOTHING`으로 이미 저장된 설정을 덮어쓰지 않는다. 소스 manifest와 Drizzle schema를 함께 등록한다. 운영에는 별도 승인된 DB migration/배포가 필요하며, Git main 병합은 운영 설정 적용이나 라이선스 승인으로 간주하지 않는다.

관리자 배포 전 API와 동일 출처 경로, 관리자 인증·CSRF, rollback, 권리 BOM/정적 assets 경로를 확인해야 한다. 모드를 무료로 돌리는 것은 이미 발생한 외부 비용이나 발송된 파일을 취소하는 동작이 아니다.

## 8. 검증

관련 단위/DB/UI 테스트는 `apps/api/src/modules/operation-policy`, `team-workspace.repository.integration.test.ts`, `apps/admin/src/domains/operation-policy`에 있다. DB fixture는 기존 운영 DB를 상속하지 않는 로컬 전용 데이터베이스와 무작위 schema를 사용한다. migration·동시 생성/마감이 아닌 조직변경·승인 만료/배포물 불일치·재전송·자료 보존을 확인한다.

원격 main 병합 전 검증 결과와 미완료 목록은 별도 implementation report에 기록한다. mock UI 성공을 운영 DB나 전체 서비스 기능 완료로 바꾸어 보고하지 않는다.
