# ToonStudio 올인원 제작 UX 기반 — 2026-09-17

## 결정

ToonStudio의 사용자-facing 정체성은 **기획부터 연재까지 웹툰 제작의 모든 단계를 하나의 작품 프로젝트에서 연결하는 올인원 웹툰 제작 스튜디오**다.

이 결정은 다음 표현을 대체한다.

- 외부 드로잉 도구를 전제로 한 제작 관리 서비스
- 웹툰·웹소설 통합 인덱스를 제품 전체의 대표 정체성으로 사용하는 표현
- 사용자가 내부 엔진·도메인 구조를 먼저 이해해야 하는 기능 중심 탐색

ToonSpectrum의 작품 탐색·랭킹·인사이트는 폐기하지 않고 ToonStudio의 기획 참고와 작품 발견을 돕는 확장 영역으로 유지한다.

## 이 변경에서 구현한 기반

### 1. 제품 정체성 단일 원천

`apps/web/src/shared/lib/product-identity.ts`가 다음 정보를 관리한다.

- 제품 카테고리
- 대표 제목과 설명
- 검색·공유용 제목과 설명
- 기획·2D·3D·소재·협업·연재로 이어지는 과업 중심 시작점

홈, PWA, SEO, `llms.txt`, 푸터와 법적 서비스 유형은 같은 방향을 말해야 한다.

### 2. 과업 중심 진입

사용자는 전문 기능명을 외우는 대신 다음 행동에서 시작한다.

```text
기획 시작
2D 작업
3D 작업
소재
제작·협업
검토·연재
```

최근 작업이 있으면 신규 기능보다 `이어서 작업`을 먼저 제공한다.

#### 선택 게이트 최소화 원칙

작업을 계속할지 묻는 모달을 기본 진입 동선으로 사용하지 않는다. 애플리케이션이 현재 문맥과 안전 조건으로 답을 결정할 수 있으면 먼저 진행하고, 결과를 되돌릴 수 있거나 다른 명령으로 쉽게 바꿀 수 있게 한다.

- 같은 작품·같은 revision의 안전한 기기 복구본이고 현재 탭이 저장 리더라면 묻지 않고 자동으로 이어 연다.
- `새 그림`, `다른 작품 열기`, `가져오기`처럼 사용자의 창작 의도가 실제로 달라지는 행동은 명시적인 메뉴·버튼으로 시작한다.
- 최근 도구, 패널 상태, 보기 배율, 정렬·필터처럼 저위험 선호는 마지막 사용값 또는 합리적인 기본값을 적용하고 별도 확인을 요구하지 않는다.
- 삭제, 미저장 내용 폐기, 다른 revision 덮어쓰기, 권한 변경, 비용·게시·외부 전송처럼 비가역적이거나 영향 범위가 큰 행동만 확인을 요구한다.
- 작품·revision 불일치, 다른 탭이 저장 리더인 상태, 복구 권위를 확인하지 못한 상태에서는 자동으로 문서를 교체하지 않는다. 안전한 백업·복구 경로를 먼저 제공한다.
- 자동 진행에 실패했을 때만 수동 선택을 노출한다. 정상 경로의 사용자가 예외 처리 UI를 먼저 보게 하지 않는다.

즉 기본 규칙은 **`판단 가능 + 되돌릴 수 있음 = 앱이 진행`, `모호함 또는 비가역 = 사용자 결정`**이다.

### 3. Route UX Contract

`apps/web/src/shared/lib/site-route-ux.ts`는 주요 라우트의 다음 계약을 선언한다.

- 이 화면의 목적
- 하나의 대표 행동
- 필요한 프로젝트 문맥 수준
- 모바일 지원 정책
- 도움말 위치
- 복구 정책
- 기본 대상 사용자

라우트가 많아져도 새 화면은 빈 상태·오류·도움말·복구와 기기 정책 없이 공개하지 않는다.

### 4. 화면 잘림 방지와 입력 접근성

홈 전용 UX CSS는 다음을 강제한다.

- 그리드·플렉스 자식의 `min-inline-size: 0`
- 이미지의 `max-inline-size: 100%`
- 긴 한국어 제목과 링크의 안전한 줄바꿈
- 320px 화면의 단일 열 CTA와 카드
- 최소 44px 터치 목표
- 키보드 포커스 표시
- 고대비·강제 색상 대응
- 모션 감소 대응
- 섹션 이동 시 고정 헤더 아래 제목이 가려지지 않는 `scroll-margin`

### 5. 회귀 방지

Creator flagship 품질 워크플로가 다음을 함께 검증한다.

- 제품 정체성·시작점·라우트 UX 단위 테스트
- 전체 TypeScript 검사
- 프로덕션 번들·CSP
- 320·390·820·1440px 브라우저 렌더
- 가로 넘침
- 키보드 포커스
- 44px 모바일 CTA
- 명령 팔레트 검색
- 홈 섹션 이동

### 6. 서버·기기 작업 동기화 UX

저장과 동기화는 하나의 모호한 `저장됨` 표시로 합치지 않는다. 사용자가 실제로 판단해야 하는 보호 단계는 다음 세 가지다.

1. **이 기기 복구 저장**: 연결이 끊겨도 현재 탭의 변경을 먼저 보존한다.
2. **변경 단위 서버 승인**: 공동 작업 변경을 순서대로 보내고 승인 대기 개수를 보여준다.
3. **서버 원고 버전**: 다른 기기에서 다시 열 수 있는 명시적 초안 버전을 관리한다.

Studio는 평상시 불필요한 패널을 늘리지 않고, 다음 상황에서만 `기기·서버 동기화` 도우미를 표시한다.

- 서버 반영을 기다리는 변경이 있음
- 오프라인 보관 또는 재연결 중임
- 다른 탭이 저장 담당임
- 변경 보호 경로가 불안정함
- 권한 회수·작업실 참여 거부가 발생함
- 서버 원고와 분리된 로컬 변경의 복구가 필요함

도우미는 기존 저장·CRDT·복구 권위를 재구현하지 않는다. 현재 권위가 제공하는 상태와 행동만 한곳에 연결한다.

- 서버 연결 다시 확인
- 로컬 변경 복구 파일 내보내기
- 버전·복구 비교
- 프로젝트 백업
- 기기 복구 지점 수, 서버 반영 대기 수, 마지막 서버 승인, 서버 원고 버전 확인

동기화 편의성의 필수 원칙은 다음과 같다.

- 오프라인 변경은 기기에 먼저 내구적으로 보관하고 재연결 시 순서대로 재전송한다.
- 재시도는 중복 저장을 만들지 않으며 기존 서버 revision·승인 장벽을 통과해야 완료로 표시한다.
- 충돌·권한 오류·거부된 변경은 자동 덮어쓰기하지 않는다.
- 로컬 변경 복구 파일을 보존하기 전 서버 원고 강제 재로딩을 제안하지 않는다.
- 같은 기기 탭 동기화와 다른 기기에서 이어서 작업 가능한 서버 저장을 구분한다.
- 대용량 이미지·PSD·3D 자산은 이후 콘텐츠 해시 중복 제거, 중단 재개 업로드, 선택적 오프라인 고정을 같은 상태 모델에 연결한다.

## 사용자 언어

기본 UI에서는 다음 내부 용어를 사용하지 않는다.

```text
ProjectGraph
ScopeRef
Artifact
Workcell
Preflight
Provenance
Capability Gate
```

대신 다음처럼 실제 행동을 설명한다.

```text
작품 프로젝트
작업 범위
작업물
역할별 작업
게시 준비 검사
생성·수정 이력
사용 가능 여부 확인
```

## 화면별 기본 목적

| 화면 | 5초 안에 이해해야 하는 목적 | 대표 행동 |
| --- | --- | --- |
| 홈 | 제작 전체 흐름을 이해하고 최근 작업 또는 새 작품으로 이동 | 새 작품 시작 / 이어서 작업 |
| 기획실 | 작품 설정·회차·대본을 제작 기준으로 정리 | 첫 회차 구성 |
| 2D | 현재 컷 또는 원고를 직접 편집 | 캔버스 직접 작업 |
| 3D | 배경·소품·포즈·카메라를 만들어 컷에 연결 | 현재 컷에 넣기 |
| 소재 | 쓸 수 있는 소재와 권리를 확인 | 프로젝트에 추가 |
| 제작·협업 | 담당자·마감·선행 작업과 산출물을 연결 | 다음 작업 시작 |
| 검토 | 고정 검수본의 의견을 해결하고 승인 | 검토 요청 / 승인 |
| 연재 | 승인본의 규격·권리를 확인하고 게시본 생성 | 게시 준비 검사 |

## 이후 기능 구현 규칙

이 PR은 올인원 제품의 정체성·진입 구조·라우트 UX·반응형 품질을 고정하는 기반이다. 각 전문 기능은 다음 조건을 만족할 때 완료로 본다.

1. 실제 편집 또는 실행이 가능하다.
2. 실행 취소·다시 실행이 가능하다.
3. 자동 저장과 복구가 가능하다.
4. 다시 열었을 때 동일 상태가 재현된다.
5. 프로젝트·회차·컷 문맥을 잃지 않는다.
6. 권한과 협업 충돌을 설명한다.
7. 내보내기와 파일 왕복 손실을 숨기지 않는다.
8. 오류 뒤 작업을 보존한다.
9. 모바일·태블릿·데스크톱 지원 범위를 정직하게 표시한다.
10. 버튼 존재가 아니라 대표 사용자 과업 완주로 검증한다.
11. 기기 저장, 변경 승인, 서버 원고 버전을 한 상태로 거짓 축약하지 않는다.
12. 오프라인·재연결·충돌·복구 행동을 현재 작업 화면에서 바로 실행할 수 있다.
13. 다른 기기에서 이어가기 전에 서버 반영 완료 여부를 사용자가 확인할 수 있다.

## 비목표

- 이 변경 하나로 Clip Studio Paint·Photoshop·SketchUp의 모든 전문 기능과 완전한 파일 왕복 호환을 달성했다고 주장하지 않는다.
- 기존 저장·렌더·협업 엔진을 한 번에 교체하지 않는다.
- 운영 배포·도메인·데이터베이스·환경변수는 변경하지 않는다.
- 자동 배포를 재활성화하지 않는다.

올인원 목표는 유지하되, 기존에 검증된 2D·3D·저장·복구·제작·검수 기반을 단계적으로 같은 작품 데이터와 UX 계약 아래 통합한다.
