## 공개 제품 검토와 적용 범위

Creco의 공개 소개는 공정별 원고 비교, 뷰어 피드백, 에피소드 공정, 세부 권한과 반응형 보기를 설명한다. Jira의 공식 문서는 팀별 워크플로 관리와 동시 진행 작업 제한을 설명한다. 이번 증분은 화면이나 브랜드를 복제하지 않고 다음 작업 흐름을 보강한다.

| 검토한 사용자 문제 | 이번 구현 | 기존 권위와의 관계 |
| --- | --- | --- |
| 팀마다 다른 제작 공정 | 개인 4단계·협업 6단계·스튜디오 8단계 프리셋과 최대 32개 공정 편집 | 기존 프로젝트에 선택적으로 저장 |
| 여러 회차의 반복 작업 구성 | 회차별 누락 공정만 미리 보고 생성 | 기존 업무를 덮거나 중복 생성하지 않음 |
| 작업 상태와 병목 파악 | 칸반·목록, 필터, 우선순위, 공정별 동시 진행 수 | 기존 작업 상태·산출물 계약 유지 |
| 시각적인 작업 지시 | 본문·제목·체크 항목·참고 메모 블록 | HTML 대신 평문 구조를 저장 |
| 팀마다 반복하는 검색 | 프로젝트에 저장하는 팀 보기 | 새 접근 권한을 부여하지 않음 |
| 원고와 업무의 연결 | 입력 버전 고정, 선행 업무, 기존 원고·검수 링크 | 별도 원고 저장소나 승인 체계를 만들지 않음 |

Creco의 비공개 계정 영역이나 Jira 전체 기능과의 동등성을 주장하지 않는다. 보드에서 편집하는 공정은 제작 단계이며, 법적 승인이나 게시 권한을 새로 정의하는 범용 상태 머신이 아니다.

## 상태·권한·동시 수정

- 공정 설정은 `manage`, 업무 편집·상태 이동은 기존 `edit` 권한을 요구한다.
- 팀 보기의 신규 저장과 기존 팀 보기 수정은 관리 권한을 검사한다. 요청에서 공유 표시를 제거해도 기존 저장 상태를 기준으로 검사한다.
- 공정은 프로젝트 revision 외에 독립 `workflowProfile.revision`을 비교한다. 오래된 설정은 409로 거절한다.
- 기존 작업 편집은 `expectedTasks`, 새 작업 생성은 `expectedAbsentTaskIds`로 덮어쓰기를 방지한다.
- 상태 일괄 이동은 1~200개, 중복 없는 작업 ID, 정확한 이전 상태를 요구한다. 일부 성공으로 처리하지 않는다.
- 고정 입력·선행 작업·산출물 조건과 설정된 동시 진행 제한을 서버에서도 확인한다.
- 보드 상태 이동으로 `approved` 또는 `conditionally-approved`를 만들지 않는다. 완료 처리에도 승인된 제출본이 연결되어야 한다.
- 설명 블록과 체크리스트는 작업 메모다. 체크 표시가 공식 검수·승인·게시를 대신하지 않는다.
- 기존 공정을 사용하는 열린 작업이 있으면 해당 공정 삭제를 막는다. 기존 설정에 없던 레거시 작업은 표시·보존한다.
- 새 회차 작업은 초안으로 생성한다. 담당 역할·범위·활성 기간에 맞는 후보가 한 명일 때만 자동 배정한다.
- 기존 선행 공정에 작업이 여러 개이면 모두 의존성으로 연결한다. 다른 회차에 같은 생성 ID를 재사용하면 거절한다.

저장은 기존 aggregate JSON과 revision/idempotency/audit transaction을 재사용한다. 이 증분을 위해 별도 테이블·DDL·운영 migration을 실행하지 않는다. 구형 aggregate에는 선택적 필드가 없으며, 공정 운영 제한도 명시적으로 설정한 프로젝트에 적용한다.

## UI와 디자인

- 작업 보드가 첫 작업 화면이며 기존 역할별 작업실은 별도 보기로 유지한다. 기존 `task` deep link도 보존한다.
- 검색·우선 필터를 먼저 표시하고 회차·공정·담당자·정렬·팀 보기 설정은 접을 수 있는 영역에 둔다.
- 필터·정렬·보기는 URL로 복원한다. 선택은 필터 변경 시 해제하여 보이지 않는 작업을 잘못 변경하지 않게 한다.
- 드래그 외에 상태 선택 메뉴와 위·아래 버튼을 제공한다. 보드 가로 이동에도 명시적인 버튼이 있다.
- 편집 중 닫기, 새로고침, 저장 실패·동시 수정 시 초안 보존과 명시적 폐기를 구분한다.
- 한국어 IME 조합 중 저장을 방지하고, 대화상자·입력 요소 내부에서는 보드 단축키를 가로채지 않는다.
- 공통 디자인 토큰, 의미 있는 상태 텍스트와 아이콘, 최소 44px 주요 버튼, reduced motion, 고대비 표시를 사용한다.
- UI 정적 문구는 기존 i18n 등록·갱신 경로를 사용하며 핵심 문구에 영어를 제공한다. 번역이 없는 설명은 작성된 한국어를 유지하고 사용자 작성 원고·업무명은 자동 번역하지 않는다.

## 시각 자산 출처

`apps/web/public/assets/production-workspace/creator-workspace.webp`는 기존 저장소의 `assets/create/creator-board-hero.png`를 1280px WebP로 최적화한 파생 자산이다. 원본과 파생본의 SHA-256, 크기, 변환 조건은 같은 디렉터리의 `manifest.json`에 기록한다. 자산은 헤더 장식이며 업무 데이터나 수치를 이미지에 넣지 않는다.

요청된 새 이미지 생성 호출은 도구 오류로 시작되지 않았다. 이 파생본을 새로 생성한 ImageGen 2.5 결과로 표시하지 않는다. 기존 이미지의 생성 모델도 이번 작업에서 검증하지 않았다.

## 검증 명령과 증거 범위

저장소 루트에서 실행한다.

```sh
pnpm harness:verify
pnpm exec vitest run packages/core/src/production apps/web/src/domains/creator/production-hub --maxWorkers=1
pnpm exec vitest run apps/api/src/modules/production-collaboration/production-collaboration.service.test.ts apps/api/src/modules/production-collaboration/production-workflow-command.test.ts --maxWorkers=1
pnpm exec playwright test --config playwright.production-workflows.config.ts
```

브라우저 검증은 실제 Production React 화면과 샘플 reducer를 사용한다. 작업 생성·블록 재배치·저장·상태 변경·잘못된 시작 차단·편집 폐기 확인, 공정 프리셋과 드래그, 회차 생성 미리보기를 확인한다. light/dark/contrast 각각 1440/820/390/320px에서 문서 가로 넘침과 주요 버튼 터치 영역을 측정하고 axe 접근성 검사를 실행한다.

스크린샷·trace·JSON 보고서는 `.qa/production-workflows/` 아래에 생성된다. 실행 결과만 테스트 성공의 근거이며, 테스트 코드가 존재한다는 이유만으로 성공을 주장하지 않는다. 샘플 화면 검증은 운영 계정·운영 DB·실기기·통신사망 검증을 대신하지 않는다.

2026-09-27 최초 전체 typecheck는 기존 main의 공통 계약 이전 경로 오류로 실패했다. 제작 모듈의 집중 단위·브라우저 테스트와 전체 저장소 검증을 분리해 기록하며, 미통과 게이트를 우회하지 않는다. 공통 경계 복구 변경과 통합한 최종 SHA에 대한 게이트가 별도로 필요하다.

## 배포와 되돌리기

이번 작업은 운영 배포·DB 변경·외부 AI 과금 설정을 수행하지 않는다. 병합과 배포 승인은 별개다. 문제 발견 시 배포 없이 기존 정상 운영 버전을 유지한다. 소스 복구는 검증된 변경 커밋의 revert를 사용하며 기존 작업·원고·검수 기록을 삭제하지 않는다.

## 회차 운영과 기존 공정 호환

- 기존 `story`/`thumbnail`과 새 `story-lock`/`storyboard`는 동일한 논리 공정으로 해석한다. 저장된 작업 키를 강제로 바꾸지 않으며 필터·동시 진행 수·누락 공정 생성에 동일한 해석을 사용한다.
- 회차 생성과 일정 재배치도 저장된 팀 공정을 사용한다. 설정된 프로젝트에 기본 아홉 공정을 다시 추가하지 않는다.
- 회차 작업의 설명 블록·우선순위·고정 입력·완료 기록을 보존한다. 완료·취소 작업과 설정 밖의 레거시 작업을 임의로 재배치하지 않는다.
- 공정 표시 순서와 의존 관계는 독립적이다. 초기 마감 간격은 후속 의존 경로의 공수를 하루 8시간으로 환산한 달력일 기준 초안이며, 실제 개인 가용량·휴일·근무 캘린더를 대신하지 않는다.
- 공정이 활성화된 회차 변경은 `expectedWorkflowRevision`을 요구한다. 작성 중 팀 설정이 달라지면 최신 기준에서 다시 계획하도록 거절한다.
- 개인 공정에 게시 작업이 없어도 `EpisodeCollaboration.plannedReleaseAt`으로 제작 목표 마감을 표시한다. 이 필드는 실제 플랫폼 게시 일정·승인·발행 기록이 아니다.
- 회차 진행률도 설정된 공정의 승인·완료 상태를 기준으로 계산한다. 취소·범위 제외를 제작 완료로 간주하지 않는다.
