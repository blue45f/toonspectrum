# ToonStudio 캐릭터 워크숍 품질 감사 — 2026-09-03

## 1. 범위와 원칙

이 문서는 SHAPER의 공개 홈페이지·공개 사용 가이드에서 확인 가능한 제작 흐름을 기준으로
ToonStudio의 3D 데생 인형과 VRM 캐릭터 편집기를 점검한 결과다. 외부 제품의 소스코드,
비공개 API, 전용 에셋, 디자인 파일을 사용하지 않는다. 공개적으로 관찰 가능한 작업 개념만
참고하고, 구현은 ToonStudio의 문서·히스토리·렌더링 계약 위에서 독립적으로 수행한다.

공개 가이드에서 확인되는 핵심 흐름은 다음과 같다.

- 얼굴형, 눈, 눈동자, 코, 입, 귀, 헤어, 체형, 상의, 하의, 신발, 액세서리, 전신 포즈,
  손 포즈의 14개 조합 슬롯
- 캐릭터 표면 직접 그리기
- 참고 이미지 기반 프리셋 추천
- 사진·카메라 기반 포즈 인식
- 투명 배경 이미지 출력
- 요소별 분리 PSD 출력

## 2. 기존 구현의 실제 상태

### 2.1 기능 수와 체감 품질이 불일치한 이유

기존 화면은 14개 카테고리를 모두 노출했지만, 실제 3D 장면을 변경하는 경로는 체형·얼굴형·
전신 포즈·손 포즈 일부에 집중되어 있었다. 눈동자·입·귀·헤어·상의·하의·신발·액세서리는
선택 문자열만 바뀌었고 장면 메시·재질·리그는 변하지 않았다. 사용자는 카드가 눌렸기 때문에
변경되었다고 기대하지만 결과는 같았다. 이는 기능 부족보다 더 큰 신뢰 문제다.

### 2.2 카드가 결과를 예측하지 못함

프리셋 카드가 이모지와 텍스트로만 구성되어 있었다. 체형 비율, 얼굴 폭, 눈 크기, 코 높이,
포즈 실루엣을 선택 전에 비교할 수 없었다. 결과를 보려면 카드를 누르고 3D 뷰포트를 확인한 뒤
다시 돌아와야 했다. 반복 비교 비용이 높고, 비슷한 카드 간 차이를 기억하기 어려웠다.

### 2.3 커스터마이징의 양극화

한쪽에는 큰 방향을 정하는 프리셋, 다른 쪽에는 긴 슬라이더 목록이 있었지만 두 수준을 잇는
설명이 부족했다. 프리셋을 적용하면 어떤 수치가 바뀌는지 알기 어려웠고, 숫자로 미세 조정한 뒤
다른 카드를 선택하면 무엇이 유지되는지도 명확하지 않았다.

### 2.4 가짜 직접 그리기

데생 인형 패널의 직접 그리기는 로컬 토글과 브러시 상태만 변경했고 UV, 재질 아틀라스,
포인터 트랜잭션, Undo 소유권과 연결되지 않았다. 화면상 활성화 상태는 존재하지만 실제 모델에는
획이 남지 않았다. 반면 VRM 편집기에는 seam-safe UV surface brush 런타임이 이미 존재했다.

### 2.5 PSD가 이름만 분리된 합성 이미지

기존 PSD 경로는 한 장의 합성 캡처를 컬러 레이어로 넣고 알파 경계 일부를 선화로 추출했다.
머리·몸통·팔·다리·의상·액세서리를 실제로 분리하지 않았다. 레이어 이름이 많더라도 픽셀 의미가
같으면 후편집 효율은 올라가지 않는다.

### 2.6 기술 정보가 창작 판단보다 앞섬

참고 이미지 추천 화면은 raw cosine 유사도와 모델 해시를 전면에 노출했다. 이 정보는 회귀 검증과
감사에 필요하지만 창작자가 가장 먼저 판단해야 하는 것은 얼굴형·헤어·체형의 시각 결과다.

### 2.7 사진 포즈 검수의 맥락 손실

검출된 스켈레톤이 원본 사진과 분리된 어두운 배경에 표시되어, 관절이 실제 팔·다리 위에 놓였는지
확인하기 어려웠다. 전신만 적용할 수 있어 현재 하체를 유지하고 팔·손만 가져오는 등의 제작 흐름도
막혀 있었다.

### 2.8 밀도와 폭

320–360px 우측 패널 안에 카드, 설명, 슬라이더, 출력, 경고가 함께 들어갔다. 텍스트는 작아지고
카드는 결과를 보여줄 공간이 없었다. 기능이 많을수록 한 화면에 전부 펼치는 방식은 직관성을
오히려 떨어뜨렸다.

## 3. 이번 고도화의 설계 결정

### 3.1 14개 슬롯을 숨기지 않고 능력을 정직하게 표시

각 슬롯은 다음 세 상태 중 하나를 가진다.

- `live`: 현재 런타임에서 실제 장면에 적용 가능
- `routed`: 다른 ToonStudio 편집기에서 실제 지원
- `planned`: 저작 에셋·리그·라이선스 계약이 없어 선택 불가

현재 데생 인형의 `live` 슬롯은 얼굴형, 눈 크기, 코 높이, 체형, 전신 포즈, 손 포즈다.
헤어는 VRM 캐릭터 워크숍으로 연결되는 `routed` 슬롯이다. 나머지는 비활성 상태와 정확한 이유를
표시한다. 미지원 슬롯을 비슷한 수치나 장식으로 자동 대체하지 않는다.

### 3.2 프리뷰와 실제 적용이 같은 순수 플래너 사용

`applyShaperSelectionToBodyParams`가 카드 프리뷰와 실제 마네킹 커밋 모두의 입력을 만든다.
카드가 보여 준 체형·얼굴 비율과 장면에서 생성되는 메시가 다른 답을 낼 수 없다.

### 3.3 시각 우선 카드

새 프리뷰는 실제 지원 파라미터만 사용해 다음을 시각화한다.

- 신장, 두신, 어깨, 골반, 팔다리 비율, 체형 블렌드
- 얼굴 폭, 턱 길이, 눈 크기, 코 높이
- 기립, 짝다리, 달리기, 앉기, 전투 자세
- 손 포즈 선택에 따른 팔·손 연출

프리뷰는 장식 이미지가 아니라 동일 플래너의 결정적 SVG 예측이다. 자동 테스트는 선택 ID와
프리뷰 메타데이터를 함께 고정한다.

### 3.4 빠른 레시피와 정밀 조절의 분리

첫 화면은 큰 방향을 고르는 시각 레시피와 슬롯 카드만 보여 준다. 정밀 조절은 명시적으로 펼칠 때
나타난다. 정밀 조절은 슬라이더, 정확한 숫자 입력, 단위 표시를 함께 제공한다. 이를 통해 초보자는
카드만으로 시작하고 숙련자는 동일 화면에서 수치를 마무리할 수 있다.

### 3.5 결정적 레시피를 AI로 오인시키지 않음

네 가지 고정 조합은 `AI 추천`이 아니라 `빠른 스타일 레시피`로 표시한다. 외부 모델 추론이나
참고 이미지 분석이 실행되지 않는 상태에서 AI라는 라벨을 사용하지 않는다. 실제 참고 이미지
추천은 VRM 워크숍의 별도 로컬 분석 경로에서 시각 프리뷰와 함께 제공한다.

### 3.6 직접 그리기는 실제 런타임으로만 제공

데생 인형에는 UV 재질 슬롯이 없으므로 가짜 토글을 제거한다. 직접 그리기는 VRM 표면 편집기의
검증된 경로로 한정한다.

- 실제 Three ray hit와 face index
- UV chart/seam 경계 분리
- 압력·기울기 입력 보존
- 제스처당 하나의 canonical atlas commit
- sample/operation/memory 예산
- pointer cancel, capture loss, window blur, device loss 취소
- 포인터 hot path GPU readback 없음

### 3.7 의미 레이어 PSD

데생 인형 PSD는 같은 카메라와 깊이 테스트를 사용하는 ID 패스를 추가한다. 각 관절 메시를
머리·목, 몸통, 왼팔, 오른팔, 왼다리, 오른다리 ID로 렌더링하고, 실제 컬러 합성 결과를 ID 패스로
분배한다. 가려진 뒤쪽 면은 해당 레이어에 새로 나타나지 않는다.

출력 레이어:

1. 머리·목
2. 몸통
3. 왼팔
4. 오른팔
5. 왼다리
6. 오른다리
7. 선화

선화는 투명 실루엣뿐 아니라 합성 이미지의 luminance edge를 함께 검사한다. 의미 레이어 캡처는
별도 픽셀 예산을 가지며, 초과 시 비율을 유지한 채 안전하게 축소한다.

### 3.8 참고 이미지·사진 포즈 검수

VRM 워크숍의 참고 이미지 추천은 이모지 대신 실제 레시피 프리뷰를 보여 준다. raw model hash와
카탈로그 리비전은 접힌 기술 정보로 이동한다. 사진 포즈는 원본 이미지 위에 관절을 오버레이하고
전신·상체·팔·손 범위를 선택해 적용한다.

### 3.9 패널 폭과 단계 구조

데스크톱 데생 인형 워크숍은 400–440px, VRM 워크숍은 420–460px의 작업 폭을 사용한다. 전체
다이얼로그는 최대 1480px까지 확장하고 모바일에서는 기존처럼 세로 적층한다. 기능을 한 화면에
모두 펼치지 않고 `구성 → 포즈 → 출력`의 창작 단계로 나눈다.

## 5. 성능·안전 계약

- 3D 뷰포트는 기존 invalidate 기반 on-demand 렌더링을 유지한다.
- 프리셋 카드 SVG는 WebGL 컨텍스트를 추가로 만들지 않는다.
- 프리뷰와 실제 장면의 계산은 순수 데이터 플래너에서 수행한다.
- 의미 PSD 캡처는 포인터 hot path가 아니라 명시적 출력 명령에서만 GPU readback을 수행한다.
- ID material은 캡처 동안만 적용하고 `finally`에서 원래 재질을 복원한다.
- semantic ID materials와 render targets는 dispose된다.
- PSD·캡처는 픽셀 및 출력 바이트 예산을 가진다.
- 미지원 슬롯, provider 실패, 모델 불일치, 메모리 초과 시 자동 대체하지 않는다.

## 6. 이번 변경 후에도 남는 품질 차이

다음 항목은 UI 카드 추가만으로 해결할 수 없다. 실제 저작 에셋 파이프라인이 필요하다.

- 독립 눈·홍채·코 형태·입·귀 메시 및 텍스처 슬롯
- 프로덕션 헤어 메시, LOD, 썸네일, 충돌·리그 호환성
- 상의·하의·신발·액세서리 카탈로그와 장착 본
- 의상 관통 검사, 사이즈 변형, 소재 채널
- 얼굴 표정·입 모양 blendshape
- 헤어 앞/뒤, 피부, 의상, 신발, 액세서리까지 포함한 VRM 의미 PSD
- 대표 체형·극단 비율·모든 헤어/앞머리 조합의 브라우저 시각 회귀
- 실제 모바일 WebView와 물리 펜 입력 검증

provider가 없는 항목은 카탈로그에 게시할 수 없다.

## 8. 수용 기준

- 카드 선택 전 결과 실루엣을 비교할 수 있다.
- 카드 프리뷰와 실제 커밋이 같은 플래너를 사용한다.
- 비활성 슬롯은 이유를 읽을 수 있고 클릭해도 상태가 변하지 않는다.
- 숫자 입력과 슬라이더가 동일한 정규화·클램프 규칙을 사용한다.
- 포즈는 전신·손·사진 검수 동선이 한 단계 안에 있다.
- 직접 그리기는 실제 모델 표면에 남고 한 번의 Undo 단계가 된다.
- PSD의 각 부위 레이어 픽셀은 서로 중복되지 않고 가려진 면을 드러내지 않는다.
- 저장 후 다시 열었을 때 파라미터, 포즈, 표면 아틀라스, 의미 레이어 매핑이 동일하다.
- 모든 실패는 원본 상태를 보존하고 다음 작업 전에 명시적인 선택을 요구한다.
