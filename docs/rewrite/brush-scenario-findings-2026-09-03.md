# 다중 획 시나리오 검증 — 2026-09-03

오너 지시: "시작점 끝점 교차 다른 브러시하고 혼합 선 등등 최대한 다양하게 테스트하면서 품질,
질감, 성능, 깜빡임, 드로잉 중과 완료선과의 괴리 모두 고도화", "큰 원을 그려서 장획 시 이슈 확인,
꺾임도 자연스러운지 확인".

장획 매트릭스(`verify-studio-brushes.mts`)는 브러시마다 **직선 한 획**만 긋는다. 이 회차에서
붙인 `verify-studio-brush-scenarios.mts` 는 그 한 획이 절대 밟지 못하는 제스처를 돌린다.

| 시나리오 | 무엇을 재는가 |
| --- | --- |
| `curve` | S 커브에서 라이브↔커밋 실루엣, 양 끝 캡 |
| `circle` | 360 표본 닫힌 원 — 이 매트릭스에서 가장 긴 연속 경로, 시작·끝이 만나는 이음매 |
| `corners` | 90°·예각·반사각 지그재그 — 꺾임이 라이브에선 둥글고 커밋에선 각지면 결함 |
| `cross` | 같은 브러시 두 획의 교차부 — 깜빡임·톤 이동 |
| `mixed-over/under` | 젖은 매체 위 마른 매체, 그 반대 |
| `endpoints` | 탭·짧은 플릭·중간 획의 pointer-down/up 캡 |
| `eraser-cross` | 획 위를 지우개로 교차 — 지워진 틈이 남는지 |

매 획마다 baseline / 라이브(중간) / 라이브(마지막 표본) / 손 뗀 직후 / 릴리스 후 8프레임 /
정착 프레임을 찍고, 제스처 동안 메인 스레드 롱태스크와 애니메이션 프레임 정체를 표집한다.
스크린샷 자체가 만드는 롱태스크는 캡처 구간과 겹치는지로 분리해 앱 몫만 보고한다.

**실행 환경이 결정적이다.** 기존 게이트는 헤드리스 셸(SwiftShader)에서 돈다. 거기서는 WebGPU
라이브 잉크 레인이 애초에 선택되지 않아, 아래 두 결함이 190 브러시 전수 게이트를 통과했다.
시나리오 검증기는 기본값이 `channel: chromium`(실제 GPU) 이다.

## 고친 것

- **반투명 직접잉크 브러시가 아무것도 그리지 않음**(마커 0px). GPU 레인이 준비 증명 없이는
  렌더할 수 없는 스타일인데도 레인을 선택해 두고, 결정이 not-ready 를 돌려주자 획 자체를
  거절했다("선택 거부 사유: opacity"). 레인에 들어가기 전에 스타일을 판정해 Canvas2D 로 간다.
- **지우개가 GPU 브라우저에서 아예 동작하지 않음**("선택 거부 사유: eraser"). 같은 원인이다 —
  이 레인의 준비는 항상 `transparent-overlay` 라 destination-out 이 아래 커밋 캔버스를 지울 수
  없고, 결정은 절대 ready 가 되지 않는다. 채우기·대칭도 같은 이유로 스타일 게이트에 넣었다.
- **직전 획의 2초 지연 커밋 창 안에 그은 두 번째 획이 거절됨**. 대기 큐를 붙들고 있던 것은
  영수증이 아니라 유휴 타이머였다. 새 획이 시작되면 그 커밋을 flushSync 로 끝내고 가드를 읽는다.
  실측: 해칭 간격 0.6초에서 100% 거절 → 0%.
- 두 거절 모두 배너를 띄우며 캔버스를 38px 밀어, 그리는 도중 화면이 튀었다.

## 원·꺾임 육안 확인 (반지름 150px, 360 표본)

pen · gpen · maru-pen · pencil · brush · watercolor · oil · airbrush · charcoal 전부 라이브
마지막 프레임과 정착 프레임이 일치했고, 이음매·꺾임 모두 판정 오류 0.

- 원의 이음매: pen 은 매끄럽게 닫히고, maru-pen 은 양 끝이 테이퍼로 가늘어져 머리카락만 한 틈이
  남는다 — 라이브와 커밋이 같은 모양이므로 세필 nib 의 정직한 거동이다.
- 꺾임: 지그재그의 90°·예각·반사각 모두 라이브에서 각지고 커밋에서도 각졌다. 둥글게 뭉개지거나
  스파이크가 튀는 브러시는 없었다.

## 남은 관찰 (다음 회차)

- `pencil` 위를 지우개로 교차하면 손 뗀 직후 프레임에서 변화가 **0px**, 정착 후에야 226px 가
  지워진다 — 펜·마커·수채는 손 뗀 즉시 틈이 보인다. 연필 위 지우기의 라이브 피드백이 없다.
- `pencil` 탭의 시작 캡이 라이브와 커밋에서 53.8% 어긋난다(경고). 연필은 지터 다중 패스라 어느
  정도 차이는 설계지만, 탭 한 점에서 절반이 어긋나는 것은 확인이 필요하다.

## 미결: 글로우 계열 장획 성능 (수정 보류)

반지름 150px 원 한 획(360 표본):

| 브러시 | 제스처 시간 | 롱태스크 | 최악 태스크 | 최악 프레임 간격 |
| --- | --- | --- | --- | --- |
| neon | 9.0s | 0 | 0ms | 42ms |
| glow | 336.1s | 613 | 1283ms | 2625ms |
| soft-glow | (glow 와 동급) | | | |

CPU 프로파일(`studio-fx-brush.ts`): `closePath` 1.4s · `fxLuminousRunPolygons` 0.92s ·
`restore` 0.54s. 원인은 O(n²) 다 — 라이브 드래프트가 **포인터 이동마다 리본 전체를 다시 계획하고
다시 추적**한다. 구간마다 몸통 사다리꼴 하나와 24각형 라운드 조인 하나가 붙어, 360 구간이면 패스
하나가 1만 점을 넘고 그것을 360번 반복한다.

**시도했다가 되돌린 것**: 부드러운 구간(회전 쐐기 깊이 ≤0.05px, 국소 등폭)의 라운드 조인을
건너뛰면 336s → 54.7s, 최악 롱태스크 1283ms → 174ms 로 6~7배 빨라졌다. 그러나 정착 프레임을
눈으로 대조하니 **넓고 옅은 외곽 글로우 패스의 헤일로가 방사형으로 너덜해졌다**(스크린샷 대조).
쐐기 깊이 근사가 큰 반지름·저알파 패스의 누적 스캘럽을 대표하지 못한다. 품질 우선 원칙에 따라
되돌렸다.

**다음 회차의 올바른 해법**: 픽셀을 바꾸지 않는 증분화. 압력 경로에는 이미 접두부 재사용
빌더(`createStudioIncrementalFxPressurePathBuilder`)가 있는데 리본 패스 계획에는 없다. 안정
접두부의 폴리곤을 유지하고 새 구간만 추가하면 계획은 O(n) 이 된다. 추적·채움까지 줄이려면
라이브 프레임을 누적 오버레이로 옮겨야 한다(다른 매체가 쓰는 구조).
