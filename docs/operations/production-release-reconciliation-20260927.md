## 마이그레이션 이력

`0001`부터 `0091`까지는 적용 당시 SQL의 바이트를 유지한다. 경로 이동은 가능하지만 주석과
브랜드 이름도 이미 원장에 기록된 체크섬의 일부이므로 수정하지 않는다.
`scripts/production-migration-history-baseline.json`과 회귀 테스트가 이 계약을 검증한다.

`0092`는 협업 지원자의 `selected` 상태를 추가한다. Supabase 제공자 원장과 저장소 전용
`toonspectrum_ops.deployment_migration`은 다른 원장이므로 양쪽을 대조해야 한다.
`0093`은 구형·신형 브랜드 식별자를 함께 허용하고 누락된 음성 리뷰 제약과 불변성 트리거를
복구한다. 기존 라이선스, 객체 참조, 설명자와 그 해시는 다시 쓰지 않는다.
물리 객체의 v1 메타데이터 식별자는 기존 값을 유지하며 제품 이름과 독립적으로 취급한다.

## 검증과 적용

먼저 백업 또는 영향 범위의 스키마 복구 정보를 보관한다. 운영 연결 대상, 기존 91개 원장의
체크섬, 런타임 역할의 제한 권한, 활성 마이그레이션 잠금을 검증한다. 로컬 임시 PostgreSQL의
통합 테스트는 기존 행 보존, 구형·신형 쓰기, 재적용, 잘못된 기존 행이 있을 때의 롤백을 검증한다.

승인된 main SHA만 배포한다. DB 변경은 단일 작성자 잠금 안에서 트랜잭션으로 실행하고,
성공한 파일의 체크섬과 릴리스 SHA를 저장소 전용 원장에 함께 기록한다. 기존 원장 체크섬을
수정하거나 실패한 마이그레이션을 성공으로 표시해서는 안 된다.

## 실패와 복구

`0093`의 잠금 제한은 5초, 문장 제한은 90초다. 잘못된 기존 행을 발견하면 데이터를 변경해
맞추지 않고 전체 트랜잭션을 롤백한다. 새 제약은 구형 API와 호환되므로 API 문제가 발생하면
직전 검증된 이미지와 Worker 버전으로 복구한다. 기존 객체와 사용자 데이터는 삭제하지 않는다.
GitHub 환경의 DB 자격 증명이 다른 공급자를 가리키면 그 작업을 재실행하지 말고 실제 운영
연결 대상과 일치하도록 별도의 자격 증명 관리 절차를 따른다.
