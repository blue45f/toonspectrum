# `/research` 근거 종합·판단 노트

## 목표

`/research`의 기존 흐름은 질문 설정, 제공처별 검색, 저장 보드, 근거 공백, Story Lab·Studio 전환까지 연결한다. 이번 단계는 자료를 저장한 뒤에도 창작자가 다시 같은 자료를 훑어야 했던 공백을 보완한다.

새 판단 노트는 다음 세 종류의 사용자 작성 기록을 분리한다.

- **관찰**: 자료에서 직접 확인한 형태·맥락·조건
- **질문**: 추가 출처나 원문 확인이 필요한 불확실성
- **결정**: 근거를 바탕으로 실제 장면에 반영할 창작 선택

자동 요약이나 사실 판정을 만들지 않는다. 모든 노트는 창작자가 직접 작성하며, 연결 자료는 출처 추적만 돕는다.

## 벤치마크에서 가져온 원칙

### Notion 데이터베이스

- 같은 항목을 속성으로 분류하고 보드처럼 그룹화한다.
- 필터·검색·정렬보다 먼저 현재 작업 목적에 맞는 기본 뷰를 제공한다.
- 출처: <https://www.notion.com/help/views-filters-and-sorts>

### Are.na 채널

- 수집한 블록을 단순 북마크가 아니라 진행 중인 리서치 맥락으로 묶는다.
- 사용자가 직접 연결하고 재배열하는 느슨한 구조를 유지한다.
- 출처: <https://help.are.na/docs/getting-started/channels>

### Raindrop.io

- 저장 항목, 태그, 하이라이트, 노트를 한 검색 경계에서 찾을 수 있게 한다.
- 백업에 컬렉션·태그·노트 구조를 함께 보존하는 휴대성을 중시한다.
- 출처: <https://help.raindrop.io/using-search>, <https://help.raindrop.io/transfer>

ToonStudio에는 범용 지식관리 UI를 그대로 복제하지 않고, 웹툰 제작의 `근거 → 질문 → 장면 결정` 흐름만 좁혀 적용한다.

## 사용자 흐름

1. 시각 레퍼런스·판본·기회센터에서 자료를 저장한다.
2. `/research`에서 관찰·질문·결정 중 하나를 선택한다.
3. 한 문장 노트를 쓰고 현재 저장 보드에서 최대 5개 근거를 연결한다.
4. 질문 노트는 현재 조사 모드의 검색어로 다시 실행한다.
5. 결정 노트는 Story Lab으로 이동해 이야기 구조에 반영한다.
6. 리서치 브리프를 내보내면 판단 노트와 연결 출처가 함께 포함된다.
7. 판단 노트 JSON은 기존 자료·기획서 JSON과 별도 스키마로 합치기 또는 완전 대체 복구한다.

## Authority와 스키마 경계

- 저장 키: `toonstudio:research-notebook:v1`
- 정본: 현재 브라우저의 `localStorage`
- 계정 동기화·서버 저장·공동 편집은 제공하지 않는다.
- `CreatorWorkspace` v1과 `ResearchDeskSession` v1은 변경하지 않는다.
- 판단 노트는 별도 버전형 스키마로 유지해 기존 자료·기획서 복구 경계를 보존한다.

```ts
interface ResearchNotebook {
  version: 1;
  entries: ResearchNotebookEntry[];
}

interface ResearchNotebookEntry {
  id: string;
  kind: "observation" | "question" | "decision";
  text: string;
  sourceIds: string[];
  createdAt: string;
  updatedAt: string;
}
```

## 입력·용량 제한

- 노트: 최대 36개
- 노트 본문: NFKC 정규화 후 2~320자
- 연결 자료: 노트당 최대 5개
- 저장 JSON: 최대 64 KiB
- 가져오기 파일: UI에서 최대 1 MiB, 파서는 실제 스키마 크기 제한을 다시 적용
- ID·타임스탬프·열거형·출처 ID를 파싱할 때 재검증
- 중복 노트 ID는 첫 항목만 보존

## 상호작용·접근성

- 유형 버튼은 `aria-pressed`를 사용한다.
- 보드는 세 개의 의미 있는 섹션으로 구성하고 각 섹션에 제목과 개수를 제공한다.
- 저장 상태와 오류는 `role=status`, `aria-live=polite`로 알린다.
- `Cmd/Ctrl + Enter`로 노트를 저장할 수 있다.
- 모든 편집·검색·삭제·가져오기 기능은 키보드로 접근할 수 있다.
- 완전 대체·초기화·삭제는 명시적인 확인을 거친다.
- 모바일에서는 단일 열, 넓은 화면에서는 세 열 보드로 전환한다.

## 실패와 복구

- 브라우저 저장이 실패해도 현재 탭의 메모리 상태는 유지하고 오류를 표시한다.
- 다른 탭의 `storage` 이벤트를 수신해 동일 키의 최신 유효 스냅샷을 반영한다.
- 손상된 JSON·지원하지 않는 버전·초과 크기는 기존 노트를 덮어쓰지 않고 거부한다.
- 합치기 복구는 현재 노트를 우선하며 같은 ID의 백업 항목으로 덮어쓰지 않는다.
- 저장 자료가 삭제되면 노트는 유지하고 `보드에서 제거된 자료` 상태를 표시한다.

## 권리·사실성 한계

- 연결 자료 수는 신뢰도 점수가 아니다.
- 사용자 관찰·질문·결정은 사실 검증 결과로 표시하지 않는다.
- 연결된 URL·CC0·메타데이터 표시는 실제 사용 범위와 권리 허가를 자동 보증하지 않는다.
- 브리프에 위 한계를 명시한다.

## 검증 범위

- 모델: 파싱, 용량·개수 제한, 중복 제거, 추가·재분류·삭제, 합치기, 마크다운 출처 연결
- 훅: 초기 로드와 저장 실패 시 메모리 상태 보존
- 페이지: 저장 자료 연결, 로컬 지속성, 유형 재분류, 질문 재검색과 검색 이력 기록
- 기존 `/research` 검색·백업·SavedBoard 회귀 테스트와 함께 실행
